# 模範解答

ブランチ戦略とは、チーム開発におけるブランチの使い方のルールで、いわばチームの「交通ルール」のようなものです。個人開発なら`main`に直接コミットしても問題ありませんが、複数人で開発すると作業の競合や未完成の機能の混入が起こるため、ルールが必要になります。代表的なものに、Git FlowとGitHub Flowがあります。Git Flowは`main`・`develop`・`feature`・`release`・`hotfix`の5種類のブランチを使い分け、複数バージョンの並行管理やリリースサイクルが明確な反面、複雑で学習コストが高く、モバイルアプリなど大規模なプロジェクトに向いています。一方GitHub Flowは`main`と`feature`の2種類だけのシンプルな戦略で、すべての変更をプルリクエスト経由で`main`にマージし、継続的デプロイに適していて、WebアプリケーションなどではこちらやSaaSに向いています。初心者にはシンプルなGitHub Flowから始めるのがおすすめです。
