イシュー駆動開発（Issue-Driven Development）とは、新機能やバグ修正などのすべての作業を「イシュー（課題）」として登録し、そのイシューごとにブランチを作成して開発を進める手法です。基本的な流れは、まずイシューを作成し、イシュー番号を含むブランチ（例：`feature/1-add-login`）を切って開発を行い、完了したらプルリクエストを作成してコードレビューを受け、`main`にマージし、最後にイシューをクローズする、という順序です。プルリクエストの説明に`Closes #1`のように書いておくと、マージ時に対応するイシューが自動的にクローズされます。この手法を使うと、誰が何を作っているのかが一目でわかる作業の可視化、担当者を割り当てる作業の分担、状態を管理する進捗管理、そしてなぜその変更をしたのかを後から追える履歴の記録といったメリットが得られます。
