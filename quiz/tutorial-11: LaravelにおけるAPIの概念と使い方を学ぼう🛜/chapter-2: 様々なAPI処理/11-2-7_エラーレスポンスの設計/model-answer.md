APIがエラーを返すときに、すべて同じ形式で返すように設計しておくと、それを受け取るクライアント（フロントエンド）側の処理がシンプルになり、何が問題なのかを正しく判断できるようになります。具体的には、人間が読めるエラーメッセージ（例：「タスクが見つかりません」）と、プログラムで判定しやすいエラーコード（例：`TASK_NOT_FOUND`）の両方を含めます。メッセージは表示文言の変更や多言語対応で変わる可能性があるため、変わりにくいエラーコードがあるとプログラムで安定して条件分岐できます。また、404や422などの適切なHTTPステータスコードを返すことで、そもそもエラーが起きたのかどうかをクライアントが確実に判断できます。これにより、形式がバラバラで処理が複雑になることを防げます。
