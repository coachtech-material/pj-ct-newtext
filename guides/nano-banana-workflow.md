# ナノバナナ画像生成ワークフロー

## 概要

ナノバナナとは、教材の通常Section（非ハンズオン）に挿入する**概念図解画像**のことです。
Gemini Pro の Gem 機能（カスタム指示）を使い、コミックエッセイ風の手描きタッチで生成します。

**目的**: 文章だけでは捉えにくい概念の構造を、比喩とイラストで一目で理解できるようにする

**対象**: 55件の概念図（Issue #153 で管理）

---

## ディレクトリ構成

```
image/nano-banana/
├── README.md              ← バージョン管理ルールの説明
├── v1/                    ← 初回量産
│   ├── gem-settings.md    ← Gem設定（その時点の設定を記録）
```

### バージョン管理

- 各 `vN/` にその時点の `gem-settings.md` と `prompts/` を含める
- 過去バージョンは削除しない（再現性のため）
- 詳細は `image/nano-banana/README.md` を参照

## Gem設定

Gemini Web UI でGemを作成し、`gem-settings.md` の内容を設定します。

### 設定手順

1. [Gemini](https://gemini.google.com/) にアクセス
2. 左メニュー「Gem マネージャー」→「新しいGemを作成」
3. `gem-settings.md` の内容をコピーして設定:
   - **名前**: `教材イラスト`
   - **説明**: gem-settings.md の「説明」欄を貼り付け
   - **カスタム指示**: gem-settings.md の「カスタム指示」欄を貼り付け
4. 「保存」をクリック

> 設定変更時は `gem-settings.md` も更新し、新バージョン（v2/）を作成してください。

## ワークフロー全体像

```
1. 挿入ポイント特定
   ↓
2. プロンプトドラフト作成（ASCIIアートで構図表現）
   ↓
3. ユーザーFBで練り直し
   ↓
4. プロンプト確定 → prompts/ に保存
   ↓
5. Gemini Web UIで画像生成
   ↓
6. 品質チェック → 不合格ならリテイク（5に戻る）
   ↓
7. 教材にimgタグ挿入
```

## プロンプト作成プロセス

### 1. 教材Sectionを読む

対象Sectionの教材ファイルを読み、以下を把握します:

- **比喩**: 教材で使われている比喩（レストラン、たい焼き、玉ねぎ等）
- **キーワード**: 核となる技術用語（MVC、Controller、Middleware等）
- **既存テキスト図**: ASCII図やテキストベースの図解がある場合、それを画像化する
- **前後のSection**: 文脈や前提知識の確認

### 2. プロンプトドラフト作成

以下の3つを作成します:

#### a. プロンプト本文

5要素を必ず含める:

| # | 要素 | 内容 | 例 |
|:--|:--|:--|:--|
| 1 | 対象概念 | 何を図解するか | 「LaravelのMVCアーキテクチャ」 |
| 2 | 要素リスト | キャラクター/オブジェクト/ボックスとラベル | 「Controller（厨房リーダー）」 |
| 3 | フロー指定 | 番号付き手順 | 「① お客さん → ホールスタッフ」 |
| 4 | テキスト指定 | ラベル文言（日本語15文字以内） | 「ラベル「Model（シェフ）」」 |
| 5 | 構図指示 | 要素の配置 | 「左→右」「上→下」「左右分割」 |

#### b. ASCIIアートで構図表現

画像の構図（要素の配置・矢印の方向・ラベル位置）をASCIIアートで可視化します。
これにより、Gemini生成前の段階で構図の問題を発見でき、後戻りを防げます。

```
例: MVCの構図イメージ

    ┌─────────────────────────────────────────────────────┐
    │           「Laravel MVCアーキテクチャ」                │
    │                                                      │
    │  [Browser]  ──①──▶  [Routing]  ──②──▶  [Controller] │
    │  (お客さん)        (ホールスタッフ)     (厨房リーダー)  │
    │                                         │    ▲      │
    │                                    ③──▼    │⑥      │
    │                                     [Model]          │
    │                                     (シェフ)          │
    │                                    ④──▼  ▲⑤       │
    │                                    [Database]        │
    │                                    (冷蔵庫)           │
    │                                                      │
    │            [View]  ◀──⑦──  [Controller]              │
    │          (盛り付け担当)                                │
    │  [Browser]  ◀──⑧──  [Routing]                       │
    └─────────────────────────────────────────────────────┘
```

#### c. 挿入情報 + 確認項目

プロンプトファイルの末尾に記載します（後述のファイル形式を参照）。

### 3. ユーザーFBで練り直し

- ドラフト（本文 + ASCIIアート）をユーザーに提示
- FBを受けて修正 → 確定

### 4. 確定版を保存

`image/nano-banana/v1/prompts/` に保存します。

## プロンプトファイル形式

```markdown
# {Section番号}: {概念名}（{テンプレート名}）

**Gem**: v4.1 | **テンプレート**: A1 / A2 / A3 / B1 / B2 | **ステータス**: ✅完成 / テスト中 / 未着手

## プロンプト本文

｀｀｀
[Geminiに渡すプロンプト本文]
｀｀｀

## 構図イメージ（ASCIIアート）

｀｀｀
[画像の配置・要素の位置関係をASCIIアートで表現]
｀｀｀

## 挿入情報

- ファイル: `curriculums/tutorial-X/.../X-X-X_xxx.md`
- 挿入位置: {セクション名}の{説明}の直後（L{行番号}付近）
- 画像ファイル名: `X-X-X_c1.png`

## 確認項目

- [ ] 技術用語のラベルが正確か（スペルミス、用語の間違い）
- [ ] フローの番号（①②③...）が正しい順序で全て見えるか
- [ ] 教材内の比喩・表現と一致しているか
- [ ] {概念固有のチェック項目}
```

### ファイル命名規則

`{N}-{M}-{S}_{概念名の英語}.md`

例: `9-1-3_mvc.md`, `6-2-3_docker.md`, `11-1-1_auth.md`

## テンプレート一覧

| テンプレート | 用途 | 例 |
|:-------------|:-----|:---|
| **A1**: 比喩フロー型 | 比喩ベースの処理フロー | MVC、認証フロー、ミドルウェア |
| **A2**: 比較型 | 2つの概念の左右対比 | Web認証 vs API認証、Docker有無 |
| **A3**: 比喩シーン型 | 単一比喩の概念図解 | Docker/たい焼き、DBMS/執事 |
| **B1**: 技術フロー/シーケンス図 | 状態遷移、シーケンス図 | ファイル4状態、Git Flow |
| **B2**: ER図 | テーブル構造・リレーション | PK/FK、多対多 |

各テンプレートの詳細は `image/nano-banana/v1/gem-settings.md` と `local/image-generation/guide.md` を参照。

## 画像生成手順（Gemini Web UI）

### 準備

1. Gemini Web UI で「教材イラスト」Gemを開く
2. 新しいチャットを開始

### 生成

1. プロンプトファイルの**プロンプト本文**をコピー
2. **構図イメージ（ASCIIアート）** もコピー
3. 両方をGeminiのチャットに貼り付けて送信
   - ASCIIアートは構図の指示としてGeminiが参考にできるため、プロンプトと一緒に渡す
4. 生成された画像をダウンロード

### コツ

- セッション開始時に、過去の合格画像を2-3枚アップロードすると品質が安定する
- Style A → Style B の順で生成するとGem切り替えが減る
- 1日8-10枚が目安（集中力の維持）

## 品質チェックリスト

### 必須基準（全て通過が必要）

- [ ] 全てのラベルが白カード上にあり、背景に埋もれていない
- [ ] 日本語テキストが読める（50%縮小でも判読可能）
- [ ] 要素数が8以下
- [ ] フローの番号が正しい順序で、見つけやすい
- [ ] 矢印が単色・太い（グラデーション/虹色なし）
- [ ] 16:9横長
- [ ] 概念が正確に表現されている
- [ ] 大人向けの品位がある（子供っぽくない）

### 不合格基準（1つでもあれば却下）

- テキストが文字化け/判読不能
- 概念が事実として間違っている
- 要素が8個を超えている（ごちゃごちゃ）
- 情報階層がない（全て同じ目立ち方）

## 教材挿入手順

### imgタグの形式

```html
**概念図の説明文**

<img alt="{N}-{M}-{S}_c{連番}.png" src="">
```

- `alt`属性にファイル名を記載
- `src`属性は空（GitHub Actions で S3 URL に自動置換される）
- 画像ファイルは `image/` ディレクトリに配置

### ファイル命名

- 概念図: `{N}-{M}-{S}_c{連番}.png`（`_c` = concept）
- 例: `9-1-3_c1.png`、`12-1-1_c1.png`（Git Flow）、`12-1-1_c2.png`（GitHub Flow）

### 完成イメージの表示ルール

- **画像1枚**: トグル不要、直接表示
- **画像2枚以上**: `<details><summary>📸 完成画面を確認する（クリックで展開）</summary>` で折りたたみ

### 画像一覧への登録

`image/section-image-list.md` のナノバナナ概念図セクションにエントリを追加してください。

## リテイクフロー

画像が品質チェックを通過しなかった場合:

1. 不合格理由を特定（チェックリスト参照）
2. プロンプトの修正が必要か判断:
   - ラベル位置・色 → Geminiに「〇〇を修正して」とリテイク指示
   - 構図の根本変更 → プロンプト本文を修正して再生成
3. 修正後、再度品質チェック
4. 3回リテイクしても不合格の場合 → プロンプト自体を見直す

---

## 新バージョンの作り方

スタイル変更や一括修正が必要な場合:

1. `image/nano-banana/vN/` ディレクトリを新規作成
2. その時点の `gem-settings.md` を配置
3. 対象プロンプトを `prompts/` に配置（変更分のみでもOK）
4. 変更理由をコミットメッセージに記載
5. `image/nano-banana/README.md` に必要に応じてバージョン説明を追記
