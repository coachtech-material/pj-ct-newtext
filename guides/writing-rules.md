# 執筆ルール

> **目的**: 教材の文体・スタイル・構成を統一し、チーム全員が同じ品質で執筆できるようにする

---

## 対象読者

- **プログラミング未経験者**
- **ITリテラシーが高くない学習者**

この前提を常に意識し、説明の丁寧さ・分かりやすさを最優先にする。

---

## 文体ルール

### 基本方針

- **丁寧語**で統一（「〜です」「〜ます」）
- **読点を多めに**使用（「、」で適切に区切る）
- 1文を短くし、理解しやすい文章にする

### 専門用語の扱い

- 専門用語は初出時に必ず**日常の言葉で言い換え**を併記する
- 例: 「リポジトリ（プロジェクトの保管庫）」「コミット（変更の記録）」
- その後は専門用語をそのまま使ってよい

### 比喩の使い方

- 身近で実用的な比喩を使う（「書類」「ノート」「コピー機」など）
- 過度に凝った比喩は避ける（「魔法の杖」「秘密の呪文」等はNG）
- 「比喩で理解する:」のような直接的な事前通告を避け、自然な形で導入する

### 初学者への配慮

- **「これが無いと何が困るか」を導入で示す**。ただし導入で語り切らない（下記「導入の書き方」）
- **「つまずきポイント」を先回り**して説明する（「ここでエラーが出たら、こうしてください」）
- **「今は理解しなくてOK」を適宜明記**する（心理的負担を減らす）
- **前提知識は、必要な箇所で1文だけ参照**する（「9-5-5で書いたリレーションを使います」）。節の冒頭に前節の要約を置かない

---

## 分量

**数値の下限・上限を置かない**。必要な情報を省略しない前提で、**最短の表現を選ぶ**。同じ内容を短く言えるなら短くする。

- 言い換えの重ね・同一論点の再説明・過剰な前置きとまとめで字数を伸ばさない
- **1 Section = 1つの成果物、または1つの問い**。2つ入っているなら、削るのではなく Section を分ける
- 削ってよいのは**重複と儀式**であって、情報ではない。専門用語の言い換え併記・なぜそうするかの理由・具体例そのものは削らない

> ⚠️ **旧ルールの廃止**: 「1セクションあたり最低4,000文字」は廃止した。この下限が、器を増やす・同じ話を書き足すという形で冗長さを生んでいたため（実測: 下限のすぐ上に複数Sectionが揃う現象が確認された）。

## 通常Sectionの構成

構成は**必ず埋める枠ではなく、必要なものだけ使う部品**として扱う。中身の無い部品は置かない。

```
タイトル（H1）
├── 🎯 このセクションで学ぶこと（2〜3項目）
├── 導入（これが無いと何が困るか）
├── 概念の説明
├── 詳細解説（コマンド/コードの使い方、オプション、注意点）
├── 🏃 実践
└── ✨ まとめ
```

任意の部品: `> 💡 TIP` ／ `> ⚠️ 注意` ／ コードリーディング ／ よくある間違い。

> ⚠️ **置かない部品**: 節末の「次のセクションでは〜」という移行アナウンス（次節のタイトルが同じ情報を持つ）。ただし**積み残した論点を渡す**場合だけは、1文で書いてよい（例: 「誰がどの機能を使ってよいかは 13-4-2 で表にします」）。

詳細は `guides/section-structure.md` を参照。

## 導入の書き方

導入に置くのは「**これが無いと何が困るか**」だけにする。次のものを導入に積まない。

| 積まない | 代わりに |
|:---------|:---------|
| 前節の要約（「前のセクションで〜できるようになりました」） | 必要なら本文中で1文だけ参照する |
| 工程上の位置づけの再説明 | 初出の節に1箇所だけ置く |
| この節で作る成果物の定義 | 「読み方」「書き方」の見出しの中で扱う |
| 用語の言い換えの列挙 | 初出の箇所でその都度併記する |

---

## 地の文の書き方

文そのものの書きぶりを次のとおり決める。実測で頻出した順に並べている。

| やらない | 代わりに |
|:---------|:---------|
| 「〜ではなく、〜です」の二項対比 | 「〜です」と直接書く。**1 Section に2回まで** |
| 「理由は2つあります」「手順は5つです」の個数予告 | 予告せずリストを出す。数はリストを見れば分かる |
| 「では、〜のでしょうか。」の反語 | 答えから書く |
| 「〜と思うかもしれません」「気になるかもしれません」 | 読者が思っていない疑問を代弁しない |
| 比喩を節の全域で引きずる | 比喩は導入の1文だけ。以降は専門用語で進める |
| 「まだ〜ない」型の断定文の見出し | 見出しは名詞句にする |
| 「〜することができます」「〜を行います」「〜という形になります」 | 「〜できます」「〜します」「〜になります」 |
| 全段落が同じ長さ・同じ型で着地する | 長さとトーンにムラを作る |
| 動作主が消えた受動態（「設定されます」） | 「あなたが〜します」「〇〇が自動で〜します」 |

同一論点の**本説明は Section 内に1箇所**だけ置き、他からは1文の参照に留める。本文 → `💡 TIP` → `✨ まとめ` で同じ主張を3回書かない。

詳細な点検基準は `.claude/skills/section-write/references/ai-slop-curriculum.md`。機械判定できるものは `.claude/scripts/lint_curriculum.py` が検出する。

## コードブロック

- 必ず**言語指定**をする（```php, ```bash, ```blade 等）
- **ファイルパス**をコメントで明記する
- 省略する場合は `// ...` で示す
- **JSON（`.json` ファイル）のコードブロックにはコメントを書かない**。JSONはコメントを許さない仕様で、`//` を1行入れただけで設定ファイルとして読めなくなる（`.claude/settings.json` では、フックも権限も無言で全滅し、警告もログも出ないことを実測済み）。ファイル名は**コードブロックの直前の地の文に太字で書く**
- すべてのコード例には**処理の流れを1行ずつ解説**する
- **実行結果を明示**し、何が起きているかを説明する
- エラーが出る場合は、その原因と対処法も記載する

## 外部リンクの扱い

**教材の外にあるものを、受講生が辿る必要があるかたちで挙げたら、URLを添える。**

判断は「受講生がその名前で何をするか」で分ける。**名前を出すことをためらってURLの無い遠回しな言い方にするのは、いちばん避ける**（「デザインツール」より「Figma」のほうが像が立つ）。

| 挙げ方 | URL | 理由 |
|:--|:--|:--|
| **例えとして名前を出すだけ**（誰でも知っている製品。「Slackのようなもの」「Figmaで届く」） | 不要 | 名前だけで像が立つ。辿る先は要らない |
| **名前だけ知っておくもの**で、受講生が調べに行く前提のもの（OSSリポジトリ・学習サービス・関連する考え方の道具） | **必須** | 辿る先が無いと行き止まりになる。検索で別物に当たるものもある |
| 受講生が**使う**もの（導入するツール・開く画面） | 手順の中に既にあればそれで足りる | 導入コマンドや開く先が本文にあるため |
| コマンド・フラグ・設定キー | 不要 | 手元で `/help` と公式ドキュメントから引ける |

書き方:

- URLはインラインコードで書く（`` `https://example.com/` ``）。リンク記法にしない（LMS側の表示に依存しないため）
- 公式ドキュメントの**個別ページ**は変わりやすい。入口のURLを1つ挙げ、あとはページ名で指す
- 変わりうるもの（製品ページ・料金・提供状況）には「2026年◯月時点」を添える
- 同じ節で同じURLを繰り返さない。1節1回

> ⚠️ 執筆時に**必ず実在を確かめる**。URLは記憶で書かない。取得した一次資料のパスと突き合わせる。

## 画像の扱い

### ファイル命名規則

```
{Tutorial}-{Chapter}-{Section}_{連番}.png
```

例: `9-1-8_1.png`, `9-1-8_2.png`

### imgタグの形式

```html
**画像の説明**

<img alt="9-1-8_1.png" src="">
```

- `alt`属性にファイル名を記載
- `src`属性は**リリース時は空**（GitHub Actionsで S3 URLに自動置換される）
- 画像の前に説明テキストを記載

### 執筆・レビュー中のsrc（相対パス運用）

執筆中のマイルストーンブランチでは、プレビューで画像を確認できるよう `src` に**リポジトリ内の相対パス**を入れてよい（altと同名のファイルを指すこと）。

```html
<img alt="13-2-2_1.png" src="../../../image/13-2-2_1.png">
```

- ローカルエディタのプレビューとGitHub上の表示で画像が見える
- **リリース（LMS反映）前に一括で空へ戻す**。復元漏れは `python3 .claude/scripts/lint_curriculum.py --release curriculums/` が 🔴（img-src-not-restored）で検出する
- 復元コマンド（対象Tutorialを指定して実行）:

```bash
find "curriculums/tutorial-13: システム設計を学ぼう📐" -name '*.md' \
  -exec perl -i -pe 's#src="(?:\.\./)+image/[^"]*"#src=""#g' {} +
```

### 配置ルール

- 画像は `image/` ディレクトリに配置する
- 画像が1枚の場合: トグル不要、直接表示
- 画像が2枚以上の場合: `<details><summary>📸 完成画面を確認する（クリックで展開）</summary>` で折りたたみ

## 重複の削減

- 同じ概念を別章で繰り返さない
- 前のセクションで説明した内容は、簡潔に参照する
- できる限り演習は統合し、一気通貫で学べるようにする
- **`✨ まとめ` は本文の文をコピーしない**。本文の該当文をそのまま貼り直したまとめは、読まなくてよい場所として学習される

---

## コードリーディングの徹底

すべてのコード例には以下を含める:

1. **処理の流れを1行ずつ解説**する
2. **実行結果を明示**し、何が起きているかを説明する
3. エラーが出る場合は、その**原因と対処法**も記載する
