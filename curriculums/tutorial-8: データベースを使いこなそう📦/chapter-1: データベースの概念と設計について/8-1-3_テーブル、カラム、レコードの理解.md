# 8-1-3: テーブル、カラム、レコードの理解

## 🎯 このセクションで学ぶこと

*   データベースの基本的な構成要素である「テーブル」「カラム」「レコード」の3つの用語を正確に使い分けられるようになる。
*   Excelの「シート」「列」「行」との対応関係を理解する。
*   カラムに「データ型」を設定する重要性を説明できるようになる。

---

## 導入

前のセクションで、リレーショナルデータベースはデータを「テーブル」という表形式で管理することを学びました。この「テーブル」は、データベースの世界における最も基本的な構成単位です。

このセクションでは、テーブルをさらに分解し、その構成要素である **「カラム」** と **「レコード」** について、詳しく見ていきます。これらの用語は、SQLを書いたり、データベースについて誰かと話をしたりする上で、避けては通れない基本中の基本です。Excelとの対応関係を意識しながら、正確に理解していきましょう。

---

## 詳細解説

### 📊 テーブル、カラム、レコードの三位一体

顧客情報を管理する`customers`テーブルを例に見てみましょう。

**`customers` テーブル**

| `id` (顧客ID) | `name` (氏名) | `email` (メールアドレス) | `registered_at` (登録日) |
| :--- | :--- | :--- | :--- |
| 1 | 山田 太郎 | taro@example.com | 2023-01-15 |
| 2 | 鈴木 花子 | hanako@example.com | 2023-02-20 |
| 3 | 佐藤 次郎 | jiro@example.com | 2023-03-10 |

この表全体が一つのテーブル（Table）です。テーブルは、特定のテーマに関するデータの集まりです。（例: 顧客テーブル、商品テーブル、注文テーブル）

#### カラム（Column）

表の**縦の列**、つまり「`id`」「`name`」「`email`」「`registered_at`」といった各項目がカラム（Column）です。カラムは、そのテーブルがどのようなデータを持っているかを定義します。カラムには、必ず名前（カラム名）が付けられます。

*   **カラム名**: `id`, `name`, `email`, `registered_at`

#### レコード（Record）

表の**横の行**、つまり一人一人の顧客データが**レコード（Record）** です。レコードは、テーブルに格納されている具体的なデータの一件一件を指します。例えば、`id`が`1`の「山田 太郎」さんのデータが一つのレコードです。

*   **レコード1**: `(1, "山田 太郎", "taro@example.com", "2023-01-15")`
*   **レコード2**: `(2, "鈴木 花子", "hanako@example.com", "2023-02-20")`

### 🆚 Excelとの対応関係

これらの用語は、Excelの用語と非常によく似ています。対応関係を整理しておきましょう。

| データベース用語 | Excel用語 | 説明 |
| :--- | :--- | :--- |
| **テーブル (Table)** | **シート (Sheet)** | データの集まり全体。 |
| **カラム (Column)** | **列 (Column)** | データの項目・属性。 (例: 氏名、メールアドレス) |
| **レコード (Record)** | **行 (Row)** | 一件分の具体的なデータ。 (例: 山田さんのデータ) |

> **補足**: データベースの世界では、カラムのことを**フィールド（Field）**、レコードのことを**タプル（Tuple）** と呼ぶこともありますが、意味は同じです。本書では、主に「カラム」と「レコード」という用語で統一します。

### 🔢 データ型（Data Type）の重要性

データベースのテーブルを作成する際には、各カラムに **「どのような種類のデータを格納するか」** をあらかじめ定義しておく必要があります。これを**データ型（Data Type）** と呼びます。

Excelでは、一つの列に文字列も数値も日付も自由に入力できてしまいますが、データベースではこれを厳密に区別します。

なぜなら、データ型を正しく設定することには多くのメリットがあるからです。

1.  **データの整合性の保証**: 例えば、「年齢」カラムに`INTEGER`（整数）型を設定しておけば、「二十歳」のような文字列が誤って入力されるのを防ぐことができます。システム的にデータの品質を保つことができるのです。
2.  **記憶領域の効率化**: 例えば、「性別」のように「男性」「女性」「その他」の数種類しか値が入らないカラムには、`VARCHAR`（可変長文字列）よりも`ENUM`や`TINYINT`（小さな整数）といった、よりメモリ消費の少ないデータ型を使うことで、ディスクスペースを節約できます。
3.  **計算や比較の正確性**: 「登録日」カラムが`DATETIME`（日付時刻）型であれば、「2023年1月以降に登録したユーザー」といった日付に基づいた検索や計算が正確かつ高速に行えます。もしこれが単なる文字列だと、このような処理は非常に困難になります。

代表的なデータ型には、以下のようなものがあります。

| データ型 | 説明 | 例 |
| :--- | :--- | :--- |
| **`INTEGER`** (または `INT`) | 整数 | `1`, `100`, `-50` |
| **`VARCHAR(n)`** | 可変長の文字列（最大n文字） | `VARCHAR(255)` は、最大255文字の文字列を格納 |
| **`TEXT`** | 長い文字列 | 記事の本文など |
| **`DATETIME`** | 日付と時刻 | `2023-10-26 10:30:00` |
| **`DATE`** | 日付のみ | `2023-10-26` |
| **`BOOLEAN`** (または `BOOL`) | 真偽値（True / False） | `true`, `false` (内部的には 1 / 0) |

テーブルを設計する際には、「このカラムにはどんなデータが入るだろうか？」と考え、最適なデータ型を選択することが非常に重要です。

## ✨ まとめ

このセクションでは、データベースを構成する3つの基本要素について学びました。

*   **テーブル**: データの集まり全体。（Excelの**シート**に相当）
*   **カラム**: データの項目・属性。（Excelの**列**に相当）
*   **レコード**: 一件分の具体的なデータ。（Excelの**行**に相当）

そして、カラムを定義する際には**データ型**を指定することが重要であることも学びました。データ型は、データの整合性を保ち、記憶領域を効率化し、正確な計算を可能にするための重要な仕組みです。

これらの用語は、今後の学習で何度も登場します。それぞれの意味と役割をしっかりと区別して覚えておきましょう。
