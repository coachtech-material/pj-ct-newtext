## 🎯 このセクションで学ぶこと

*   `WHERE`句で、より複雑な条件を指定してデータを絞り込めるようになる。
*   `AND`, `OR`, `NOT`を使って、複数の条件を組み合わせる方法を理解する。
*   `LIKE`を使った、あいまい検索（部分一致）の方法をマスターする。
*   `IN`や`BETWEEN`を使って、より簡潔に条件を記述する方法を知る。
*   `ORDER BY`句を使って、取得した結果を特定の順序で並び替えられるようになる。
*   `LIMIT`と`OFFSET`句を使い、ページネーションの基本的な仕組みをSQLで実現できるようになる。

## 導入：大量のデータから、欲しい情報だけを取り出す技術

これまでの学習で、`SELECT`文でデータを取得し、`JOIN`で複数のテーブルを結合できるようになりました。しかし、実際のアプリケーションでは、何百万、何千万というレコードの中から、ユーザーが必要とする特定の情報だけを、見やすい順序で、少しずつ表示する必要があります。

例えば、ECサイトで「価格が1万円以下で、評価が4以上の、人気順のテレビ」を探すような場面を想像してください。これは、データベースに「価格」「評価」「人気度」といった条件で問い合わせ（クエリ）を投げ、結果を並び替えているのです。

また、検索結果が1000件あったとして、それを一度に表示するとブラウザが固まってしまいます。通常は「1ページあたり20件ずつ」のように区切って表示します。これが**ページネーション**です。

このセクションでは、`SELECT`文の能力を最大限に引き出すための重要な句、`WHERE`（絞り込み）、`ORDER BY`（並び替え）、`LIMIT`/`OFFSET`（件数制限）を学びます。これらを使いこなすことで、単にデータを取得するだけでなく、「意味のある情報」を効率的に引き出すことができるようになります。

## 詳細解説

### 🔍 `WHERE`句による高度な絞り込み

`WHERE`句はすでにおなじみですが、ここではさらに強力な使い方を見ていきましょう。

#### 複数の条件を組み合わせる (`AND`, `OR`, `NOT`)

*   `AND`: **すべての条件**を満たす場合に真となります。（「AかつB」）
*   `OR`: **いずれかの条件**を満たす場合に真となります。（「AまたはB」）
*   `NOT`: 条件を**否定**します。（「Aではない」）

**例：`id`が1で、かつ`title`が'初めての投稿'である投稿を取得**
```sql
SELECT * FROM posts WHERE user_id = 1 AND title = '初めての投稿';
```

**例：`user_id`が1または2である投稿を取得**
```sql
SELECT * FROM posts WHERE user_id = 1 OR user_id = 2;
```

`AND`と`OR`を混在させる場合は、意図しない結果を避けるために`()`でグループ化することが推奨されます。

**例：`user_id`が1で、かつ（タイトルが'A' または コンテンツに'B'が含まれる）投稿**
```sql
SELECT * FROM posts WHERE user_id = 1 AND (title = 'A' OR content LIKE '%B%');
```

#### あいまい検索 (`LIKE`)

完全一致ではなく、特定に文字列を含むレコードを探したい場合に`LIKE`を使います。`%`（0文字以上の任意の文字列）や`_`（任意の1文字）といったワイルドカードと組み合わせます。

*   `'A%'` : Aから始まる
*   `'%A'` : Aで終わる
*   `'%A%'` : Aを含む
*   `'A_B'` : Aで始まり、Bで終わり、間に1文字だけある（例: `AAB`, `AXB`）

**例：タイトルに「入門」という単語を含む投稿を検索**
```sql
SELECT * FROM posts WHERE title LIKE '%入門%';
```

#### 範囲指定 (`BETWEEN`) とリスト指定 (`IN`)

条件式をより簡潔に書くための便利な演算子です。

*   `BETWEEN A AND B`: AからBまでの範囲（AとBを含む）
*   `IN (A, B, C)`: A, B, Cのいずれかに一致

**例：`id`が1から3までのユーザーを取得**
```sql
-- 通常の書き方
SELECT * FROM users WHERE id >= 1 AND id <= 3;

-- BETWEENを使った書き方
SELECT * FROM users WHERE id BETWEEN 1 AND 3;
```

**例：`user_id`が1または3である投稿を取得**
```sql
-- ORを使った書き方
SELECT * FROM posts WHERE user_id = 1 OR user_id = 3;

-- INを使った書き方
SELECT * FROM posts WHERE user_id IN (1, 3);
```
`IN`は、サブクエリと組み合わせることでさらに強力になりますが、それはまた別の機会に学びます。

### 📊 `ORDER BY`句による並び替え

取得した結果セットを、指定したカラムの値に基づいて並び替えます。

*   `ASC`: **昇順** (Ascending) - 小さいものから大きいものへ（デフォルト）
*   `DESC`: **降順** (Descending) - 大きいものから小さいものへ

**例：投稿を作成日時の新しい順（降順）に並び替える**
```sql
SELECT * FROM posts ORDER BY created_at DESC;
```

複数のカラムを組み合わせて並び替えることも可能です。その場合、先に指定したカラムが優先されます。

**例：ユーザーIDの昇順で並び替え、同じユーザーIDの中では作成日時の新しい順に並び替える**
```sql
SELECT * FROM posts ORDER BY user_id ASC, created_at DESC;
```

### 📖 `LIMIT`と`OFFSET`によるページネーション

大量のデータを分割して取得するために使います。Webアプリケーションのページネーション機能は、まさにこの仕組みで実現されています。

*   `LIMIT [件数]`: 取得するレコードの最大件数を指定します。
*   `OFFSET [開始位置]`: 何件目から取得を開始するかを指定します（0から始まる）。

**例：最新の投稿を5件だけ取得する**
```sql
SELECT * FROM posts ORDER BY created_at DESC LIMIT 5;
```

**例：1ページあたり10件表示する場合の、3ページ目のデータを取得する**

*   表示件数: 10件 (`LIMIT 10`)
*   開始位置: (3ページ目 - 1) * 10件 = 20件目から (`OFFSET 20`)

```sql
SELECT * FROM posts ORDER BY created_at DESC LIMIT 10 OFFSET 20;
```

この`LIMIT`と`OFFSET`の組み合わせは、Web APIを設計する際にも頻繁に登場する非常に重要な概念です。

## ✨ まとめ

このセクションでは、`SELECT`文をより実践的に使うための絞り込み、並び替え、件数制限のテクニックを学びました。

*   `WHERE`句では、`AND`, `OR`, `NOT`を使って複雑な条件を組み立てることができる。
*   `LIKE`とワイルドカード`%`を使えば、文字列の部分一致によるあいまい検索が可能になる。
*   `BETWEEN`や`IN`を使うと、範囲指定やリスト指定の条件を簡潔に記述できる。
*   `ORDER BY`句で、結果の並び順を`ASC`（昇順）または`DESC`（降順）で自由に制御できる。
*   `LIMIT`（件数）と`OFFSET`（開始位置）を組み合わせることで、ページネーションのロジックをSQLで実現できる。

これらの句は、`SELECT`文の基本的な構造の一部です。実行される順序は `FROM` → `WHERE` → `SELECT` → `ORDER BY` → `LIMIT` となっており、この流れを意識すると、クエリの動作が理解しやすくなります。
