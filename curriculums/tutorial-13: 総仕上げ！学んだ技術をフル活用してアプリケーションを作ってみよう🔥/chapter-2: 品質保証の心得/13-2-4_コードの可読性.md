# 13-2-4: コードの可読性

## 🎯 このセクションで学ぶこと

> ⚠️ **注意**: このChapterでは**実際のコードは書きません**。品質の高いコードを書くための「心得」を学びます。

## 🧠 先輩エンジニアの思考プロセス

### 「なぜコレクションの次に可読性なのか？」

コレクションメソッドを学んだら、最後に**コードの可読性**を高めます。

### 理由1: リファクタリングの仕上げ

```
DRY原則 → 重複を排除
命名規則 → 意図を明確に
コレクション → 簡潔に
可読性 → 読みやすくする  ← 仕上げ
```

### 理由2: 「読みやすさ」は主観的

可読性は主観的な概念ですが、**定石のテクニック**があります。これらを知っておくことで、誰が読んでも理解しやすいコードが書けます。

### 理由3: 未来の自分への投資

今書いているコードは、1週間後、1ヶ月後、1年後の自分が読むことになります。読みやすいコードは、**未来の自分への投資**です。

## 早期リターン（Early Return）

### ネストが深いコード（悪い例）

```php
public function update(Request $request, Task $task)
{
    if (auth()->check()) {
        if ($task->user_id === auth()->id()) {
            $validated = $request->validate([...]);
            $task->update($validated);
            return redirect()->route('tasks.show', $task);
        } else {
            abort(403);
        }
    } else {
        return redirect()->route('login');
    }
}
```

**問題点**:
- ネストが深く、読みにくい
- メインロジックがどこにあるかわかりにくい
- `else`が多く、条件の把握が難しい

### 早期リターンで改善（良い例）

```php
public function update(Request $request, Task $task)
{
    // 異常系を先に処理
    if (!auth()->check()) {
        return redirect()->route('login');
    }

    if ($task->user_id !== auth()->id()) {
        abort(403);
    }

    // メインロジック（ネストなし）
    $validated = $request->validate([...]);
    $task->update($validated);
    
    return redirect()->route('tasks.show', $task);
}
```

**改善点**:
- ネストが浅く、読みやすい
- 異常系が先に処理され、メインロジックが明確
- `else`がなくなり、条件の把握が容易

### コードリーディング

| 部分 | 説明 |
|:---|:---|
| `if (!auth()->check())` | 未ログインなら即座にリダイレクト |
| `if ($task->user_id !== auth()->id())` | 所有者でなければ403エラー |
| 残りのコード | メインロジック（ネストなし） |

> 💡 **ポイント**: 「異常系を先に処理して、正常系を後に書く」のが早期リターンのコツです。

### さらにPolicyで改善

```php
public function update(StoreTaskRequest $request, Task $task)
{
    $this->authorize('update', $task);
    
    $task->update($request->validated());
    
    return redirect()->route('tasks.show', $task)->with('success', 'タスクを更新しました。');
}
```

**さらなる改善点**:
- 認可チェックが`authorize`メソッドに集約
- バリデーションがFormRequestに集約
- コントローラーは「何をするか」だけに集中

## 三項演算子の適切な使用

### シンプルな条件分岐

```php
// ✅ 適切な使用
$priorityLabel = match($task->priority) {
    1 => '低',
    2 => '中',
    3 => '高',
    default => '不明',
};

// ✅ Bladeでの使用
<span class="{{ $task->priority === 3 ? 'text-red-500' : 'text-gray-500' }}">
    {{ $priorityLabel }}
</span>
```

### 複雑な条件は避ける

```php
// ❌ 複雑すぎる（三項演算子のネスト）
$message = $task->priority === 3 ? '至急対応！' : ($task->priority === 2 ? '早めに対応' : '余裕あり');

// ✅ matchを使う
$message = match($task->priority) {
    3 => '至急対応！',
    2 => '早めに対応',
    1 => '余裕あり',
    default => '不明',
};
```

### null合体演算子

```php
// ❌ 冗長
$categoryName = $task->category ? $task->category->name : '未分類';

// ✅ null合体演算子
$categoryName = $task->category?->name ?? '未分類';
```

## コメントの書き方

### 悪いコメント

```php
// ❌ コードを説明しているだけ
// タスクを取得
$task = Task::find($id);

// ❌ 古い情報
// タスクを削除（2023年に追加）
$task->delete();

// ❌ 当たり前のこと
// IDが一致するかチェック
if ($task->user_id === auth()->id()) {
```

### 良いコメント

```php
// ✅ なぜそうするのかを説明
// 論理削除ではなく物理削除を使用（GDPR対応のため）
$task->forceDelete();

// ✅ 複雑なロジックの意図を説明
// 優先度「高」かつ期限が3日以内のタスクを「緊急」として表示
$urgentTasks = $tasks->filter(fn($task) => 
    $task->priority === 3 && $task->due_date?->diffInDays(now()) <= 3
);

// ✅ ビジネスルールを説明
// カテゴリーは全ユーザーで共有されるため、削除時は関連タスクの確認が必要
if ($category->tasks()->exists()) {
    return back()->with('error', 'このカテゴリーにはタスクが存在します。');
}
```

### PHPDocコメント

```php
/**
 * タスクを登録する
 *
 * @param StoreTaskRequest $request バリデーション済みのリクエスト
 * @return \Illuminate\Http\RedirectResponse
 */
public function store(StoreTaskRequest $request)
{
    auth()->user()->tasks()->create($request->validated());
    
    return redirect()->route('tasks.index')->with('success', 'タスクを登録しました。');
}
```

## 一貫性を保つ

### 命名の一貫性

```php
// ❌ 一貫性がない
$task = Task::find($id);
$taskData = Task::find($id);
$taskInfo = Task::find($id);

// ✅ 一貫性がある
$task = Task::find($id);
```

### フォーマットの一貫性

```php
// ❌ 一貫性がない
if($condition){
    // ...
}

if ($condition)
{
    // ...
}

// ✅ 一貫性がある（PSR-12準拠）
if ($condition) {
    // ...
}
```

### 処理順序の一貫性

```php
// ✅ コントローラーのメソッド順序を統一
class TaskController extends Controller
{
    public function index() { }    // 一覧
    public function create() { }   // 作成画面
    public function store() { }    // 作成処理
    public function show() { }     // 詳細
    public function edit() { }     // 編集画面
    public function update() { }   // 更新処理
    public function destroy() { }  // 削除処理
}
```

## 実践例

### Before（可読性が低い）

```php
public function index()
{
    $tasks = auth()->user()->tasks()->with('category')->get();
    $data = [];
    foreach ($tasks as $task) {
        if ($task->priority === 3) {
            $data[] = ['title' => $task->title, 'category' => $task->category ? $task->category->name : '未分類', 'priority' => '高'];
        } else if ($task->priority === 2) {
            $data[] = ['title' => $task->title, 'category' => $task->category ? $task->category->name : '未分類', 'priority' => '中'];
        } else {
            $data[] = ['title' => $task->title, 'category' => $task->category ? $task->category->name : '未分類', 'priority' => '低'];
        }
    }
    return view('tasks.index', ['data' => $data]);
}
```

### After（可読性が高い）

```php
public function index()
{
    $tasks = auth()->user()
        ->tasks()
        ->with('category')
        ->latest()
        ->get();
    
    return view('tasks.index', compact('tasks'));
}
```

```php
// app/Models/Task.php
class Task extends Model
{
    /**
     * 優先度のラベルを取得
     */
    public function getPriorityLabelAttribute(): string
    {
        return match($this->priority) {
            1 => '低',
            2 => '中',
            3 => '高',
            default => '不明',
        };
    }

    /**
     * カテゴリー名を取得（未分類の場合はデフォルト値）
     */
    public function getCategoryNameAttribute(): string
    {
        return $this->category?->name ?? '未分類';
    }
}
```

```blade
{{-- ビュー --}}
@foreach ($tasks as $task)
    <tr>
        <td>{{ $task->title }}</td>
        <td>{{ $task->category_name }}</td>
        <td>{{ $task->priority_label }}</td>
    </tr>
@endforeach
```

**改善点**:
- コントローラーはデータ取得のみに集中
- 優先度ラベルの変換はモデルのアクセサに移動
- カテゴリー名の取得もモデルのアクセサに移動
- ビューはシンプルに表示するだけ

## 可読性向上のチェックリスト

| チェック項目 | 説明 |
|:---|:---|
| ネストは3段階以内か | 早期リターンで減らす |
| 1つのメソッドは30行以内か | 長い場合は分割を検討 |
| 変数名は意図が伝わるか | 省略しすぎていないか |
| コメントは「なぜ」を説明しているか | 「何を」ではなく「なぜ」 |
| 一貫性があるか | 命名、フォーマット、順序 |

## 🚨 よくある間違い

### 間違い1: 過度なコメント

```php
// ❌ 過度なコメント
// タスクを取得する
$task = Task::find($id);  // IDでタスクを検索
// タスクが見つかったかチェック
if ($task) {  // タスクが存在する場合
    // タスクを削除する
    $task->delete();  // 削除処理を実行
}

// ✅ コードで意図を表現
$task = Task::findOrFail($id);
$task->delete();
```

### 間違い2: 早期リターンを使わない

```php
// ❌ ネストが深い
if ($user) {
    if ($user->isAdmin()) {
        if ($task->exists()) {
            // 処理
        }
    }
}

// ✅ 早期リターン
if (!$user) {
    return;
}
if (!$user->isAdmin()) {
    abort(403);
}
if (!$task->exists()) {
    abort(404);
}
// 処理
```

### 間違い3: 一貫性がない

```php
// ❌ 一貫性がない
$task = Task::find($id);
$categoryData = Category::find($categoryId);
$usr = User::find($userId);

// ✅ 一貫性がある
$task = Task::find($id);
$category = Category::find($categoryId);
$user = User::find($userId);
```
