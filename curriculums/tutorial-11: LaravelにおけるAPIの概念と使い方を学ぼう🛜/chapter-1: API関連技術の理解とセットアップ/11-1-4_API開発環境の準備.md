## 🧠 先輩エンジニアの思考プロセス

### 「なぜJSONの後に『開発ツール』を学ぶのか？」

#### 理由1: ブラウザだけでは不十分

WebアプリケーションはブラウザでテストできますがAPIは**専用のツール**が必要です。

POST、PUT、DELETEリクエストは、ブラウザのアドレスバーからは送れません。

---

#### 理由2: 効率的な開発

**Postman**などのツールを使うと、APIの開発・テストが効率的になります。

| 機能 | 説明 |
|------|------|
| リクエストの保存 | 繰り返し使える |
| レスポンスの確認 | 見やすく整形される |
| 認証ヘッダーの設定 | 簡単に設定できる |

---

#### 理由3: チームでの共有

APIの仕様を**ツールで共有**できます。

Postmanのコレクションを共有すれば、チーム全員が同じAPIをテストできます。

## Step 1: Postmanのインストール

### 1-1. Postmanとは

**Postman**は、**業界標準のAPIテストツール**です。APIにリクエストを送信し、レスポンスを確認できる専用アプリケーションです。

| メリット | デメリット |
|----------|------------|
| 業界標準で実務でも使われる | アプリを別途インストールする必要がある |
| 機能が豊富（コレクション、環境変数など） | |
| 無料プランで十分使える | |

---

### 1-2. インストール手順

1. [Postman公式サイト](https://www.postman.com/)にアクセス
2. 「Download」をクリック
3. インストーラーをダウンロード
4. インストーラーを実行
5. アカウントを作成してログイン（Googleアカウントでも可）

---

### 1-3. 基本的な使い方

1. Postmanを起動
2. 「New」→「HTTP」をクリック（または `+` タブをクリック）
3. リクエストを設定して送信

## Step 2: リクエストの送信

### 2-1. GETリクエストを送信する

**例**: タスク一覧を取得する

1. メソッドが「GET」になっていることを確認
2. URLを入力: `http://localhost/api/tasks`
3. 「Send」をクリック

**レスポンス例**:

```json
{
  "data": [
    { "id": 1, "title": "タスク1" },
    { "id": 2, "title": "タスク2" }
  ]
}
```

**GETリクエスト送信後のレスポンス表示画面**

<img alt="11-1-4_2.png" src="">

---

### 2-2. POSTリクエストを送信する

**例**: タスクを作成する

1. メソッドを「POST」に変更
2. URLを入力: `http://localhost/api/tasks`
3. 「Body」タブをクリック
4. 「raw」を選択し、右側のドロップダウンで「JSON」を選択
5. 以下のJSONを入力:

```json
{
  "title": "新しいタスク"
}
```

6. 「Send」をクリック

**POSTリクエストのBody設定画面**

<img alt="11-1-4_3.png" src="">

---

### 2-3. ヘッダーを設定する

APIによっては、ヘッダーを設定する必要があります。

1. 「Headers」タブをクリック
2. 「Key」と「Value」の入力欄に直接入力

**例**:

| Key | Value |
|------|-----|
| Authorization | Bearer トークン |
| Content-Type | application/json |

> 💡 **ポイント**: Postmanでは、「Body」→「raw」→「JSON」を選択すると、`Content-Type: application/json`は自動的に設定されます。

**Headersタブでの設定画面**

## Step 3: 便利な機能

### 3-1. リクエストを保存する（コレクション）

リクエストを保存すると、後で再利用できます。Postmanでは、リクエストを**コレクション**（フォルダのようなもの）にまとめて管理します。

**コレクションの作成とリクエストの保存手順**:

1. 左サイドバーの「Collections」の横にある「+」をクリック
2. 「Blank Collection」を選択
3. コレクション名を入力（例: 「タスクAPI」）
4. コレクション名の横にある「+」をクリックして、新しいリクエストを追加
5. リクエスト名の横にある「…」をクリックし、「Rename」を選択して、リクエスト名を入力（例: 「タスク一覧取得」）
6. リクエストのメソッド・URLなどを設定し、「Save」（`Ctrl + S` / `Cmd + S`）をクリック

保存したリクエストは、左側のコレクション内に表示されます。

**コレクション作成・リクエスト保存の画面**

<img alt="11-1-4_5.png" src="">

> 💡 **ポイント**: コレクションを作成しておくと、「タスクAPI」「ユーザーAPI」などカテゴリごとにリクエストを整理できます。

---

### 3-2. 環境変数を使う

Postmanでは、環境変数を使って、URLの一部を変数に置き換えることができます。

**設定手順**:

1. 右上の「No environment」をクリック
2. 「Create Environment」を選択
3. 環境名を入力（例: 「ローカル環境」）
4. 変数を追加:

| Variable | Value |
|----------|-------|
| BASE_URL | http://localhost |

5. 「Save」をクリック
6. 右上のドロップダウンで作成した環境を選択

URLを`{{BASE_URL}}/api/tasks`と書くと、`http://localhost/api/tasks`に置き換えられます。

## 🚨 よくある間違い

### 間違い1: Content-Typeを設定し忘れる

**問題**: POSTリクエストでJSONを送信する場合、`Content-Type: application/json`が必要

**対処法**: Postmanでは、「Body」→「raw」→「JSON」を選択すると、自動的に設定されます。

---

### 間違い2: URLを間違える

**問題**: URLを間違えると、404エラーが返される

**対処法**: URLを確認します。

---

### 間違い3: サーバーが起動していない

**問題**: サーバーが起動していないと、接続エラーが返される

**対処法**: `./vendor/bin/sail up -d`でDockerコンテナを起動します。

```bash
# プロジェクトディレクトリで実行
cd ~/laravel-practice/your-project-name
./vendor/bin/sail up -d
```

## 💡 TIP: curlコマンドを使う

ターミナルから、curlコマンドでAPIをテストすることもできます。

```bash
# GETリクエスト
curl http://localhost/api/tasks

# POSTリクエスト
curl -X POST http://localhost/api/tasks \
  -H "Content-Type: application/json" \
  -d '{"title":"新しいタスク","status":"pending"}'
```
