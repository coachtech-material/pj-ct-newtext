# 13-1-3: UMLと作図の約束事

## 🎯 このセクションで学ぶこと

- UML（ソフトウェアの設計図の、世界共通の描き方）とは何かを知り、この教材で描く図と表の全体像をつかむ。
- draw.ioで図形を置き、文字を入れ、線でつなぎ、保存と画像の書き出しまでできるようになる。
- 設計の成果物を残すためのdesign-practiceリポジトリを用意し、最初の1図を保存できるようになる。

---

## 導入：同じことを伝える図でも、描く人によって変わる

13-1-1と13-1-2では、設計とはどういう作業で、この教材ではどこまでを学ぶのかを見てきました。Chapter 2から設計書を作り始めるので、その前に道具と約束事をそろえます。

設計書には図がたくさん出てきます。ところが、「誰がこのシステムで何をできるか」を1枚にまとめるだけでも、ある人は使う人を丸で描き、別の人は名前を四角で囲みます。線の矢印が「その人が使う機能」を指すのか「データが流れる向き」なのかも、描いた人にしか分かりません。読む側は、中身に入る前に描き方の意図を推測することになります。

記号の形と意味をあらかじめ決めておけば、この推測が要りません。そのために作られた共通の描き方がUMLです。

## UMLと、この教材で描く図

UMLは、プログラムの設計図の統一表記法です。図の種類ごとに、どんな形の記号をどんな意味で使うのかが決まっています。皆さんが描く図も、自分だけが分かる図ではなく、他の人が読める図を目指します。

### この教材で描く9つの図と表

設計書に使う図は、UMLの図だけではありません。この教材で作るのは、次の9つです。

| 成果物 | 何を決めるためのものか | 学ぶ章 |
|:-------|:---------------------|:---------------|
| ユースケース図 | 誰が、このシステムで何をできるか | Chapter 2 |
| シーケンス図 | 1つの処理が、どこからどこへ、どの順で流れるか | Chapter 6 |
| 状態遷移図 | 1件のデータの状態が、何をきっかけに移り変わるか | Chapter 6 |
| クラス図 | プログラムをどんなまとまりに分け、互いにどうつなぐか | Chapter 7 |
| 画面遷移図 | どの画面から、どの操作で、どの画面へ移るか | Chapter 3 |
| ワイヤーフレーム | 1つの画面に、どの項目をどう並べるか | Chapter 3 |
| ER図 | どんなデータを、どんな関係で持つか | Chapter 5 |
| 権限マトリクス | どの役割の人が、どの機能を使えるか | Chapter 4 |
| CRUD表 | どの機能が、どのデータを作り・読み・書き換え・消すか | Chapter 5 |

上の4つがUMLの図、続く3つはUMLに含まれない図で、最後の2つは図ではなく表として作ります。どれもWeb開発の現場で定番の設計書です。ER図だけは、8-1-5「データベース設計の基礎」で読み方を学びました。Tutorial 13では、そのER図も含めて7つの図をすべてdraw.ioで自分の手で描きます。

<details>
<summary>💡 名前だけ知っておく図（今は覚えなくてOK）</summary>

現場の設計書や技術記事では、この教材で描かない図に出会うこともあります。名前と用途だけ挙げておきます。

- **オブジェクト図**: ある瞬間のデータの中身。クラス図の補助です。
- **パッケージ図**: まとまりどうしの依存関係。規模が大きくなると出番が来ます。
- **コミュニケーション図**: シーケンス図と同じやり取りを、誰と誰がつながっているかの側から表します。
- **配置図**: プログラムがどのハードウェアの上で動き、どう通信するか。
- **アクティビティ図**: 作業の流れを、分岐や並行処理も含めて表します。

</details>

## 作図の3つの約束事

描く図の種類は章ごとに違いますが、次の3つはどの章でも共通です。

### 約束事1: 図は自分の手で描く

13-1-1で確認したとおり、Tutorial 13の間は、図をAIに描かせません。記法や考え方をAIに質問するのは構いませんが、図そのものを作らせるのはTutorial 14からです。

### 約束事2: 道具はdraw.ioに揃える

作図にはdraw.ioを使います。2026年8月時点で、アカウント登録なしにブラウザだけで無料で使えます。図形を選んで置くだけで描けて、この教材で作る図はすべてこの1つでまかなえます。

### 約束事3: 描いたものはdesign-practiceに残す

設計練習用のリポジトリ（プロジェクトの保管庫）を1つ作り、`design-practice` という名前を付けます。この中に章ごとのフォルダを作り、Chapter 1で作ったものは `13-1/`、Chapter 2で作ったものは `13-2/` に入れていきます。入るのは主に図のファイルで、章によってはMarkdownで作った表も一緒に入ります。

1か所へ集めるのは、前の章で決めたことを次の章で使う場面が何度も出てくるからです。Tutorial 14でも、貯めた設計書を素材に使います。

## ⚙️ draw.ioを使ってみる

ブラウザで `https://app.diagrams.net/` を開くと、ログインを求められずに編集画面が出ます（2026年8月時点）。

**draw.ioを開いた直後の画面**

<img alt="13-1-3_1.png" src="../../../image/13-1-3_1.png">

覚えるのは、どこに何があるかだけです。

| 場所 | 何があるか |
|:-----|:-----------|
| 上部 | メニューバー（ファイル／編集／表示／配置／その他／ヘルプ）。保存と書き出しは「ファイル」の中 |
| 左 | 図形パネル。最上部が図形の検索ボックスで、その下に「一般」などの図形の一覧 |
| 中央 | 方眼のキャンバス。ここに図を描く |
| 右 | 書式パネル。図形を選ぶと「スタイル」「テキスト」「配置」の3つのタブが出る |

> 💡 **TIP**: 表示が英語で開いた場合は、メニューバーの「その他」→「言語」で日本語に変えられます。draw.ioは表示テーマによってボタンの位置が変わるので、教材の画像と細部が違っても、メニューの名前をたどれば同じ操作にたどり着けます（2026年8月時点）。

### 図形を出す

キャンバスに置く図形を、この教材ではシェイプと呼びます（日本語の画面では「図形」と表示されます）。最初に使うのは、Actor（棒人間）、Ellipse（楕円）、四角形、直線の4つです。

**Actor（棒人間）**: 左上の検索ボックスに `actor` と入力してEnterを押し、検索結果の先頭に出てくる棒人間を使います。

**検索ボックスに actor と入力したところ**

<img alt="13-1-3_2.png" src="../../../image/13-1-3_2.png">

出てきたシェイプは、クリックするか、キャンバスへドラッグすると置けます。

**Ellipse（楕円）**: 検索ボックスに `ellipse` と入力します。「一般」パレットの中にもあります。

**四角形**: 「一般」パレットの先頭にあります（検索するなら `rectangle` です）。

**直線**: 「一般」パレットの一番下に、いろいろな線が並んでいます。ここから選ぶのは、図の区切り線のように、シェイプとつながっていない線を引くときです。シェイプどうしをつなぐ線は、次の「線でつなぐ」のやり方で引きます。

### 文字を入れる

置いたシェイプをダブルクリックすると、文字を入力できます。

入れた文字は、既定でシェイプの中央に出ます。四角の中に別のシェイプを並べる図では重なるので、次の手順で枠の上部へ寄せます（2026年8月時点）。

1. 位置を変えたいシェイプを、1回クリックして選びます。右の書式パネルのタブが3つに変わります。
2. 「テキスト」タブを開きます。フォントの指定欄の下に、文字の位置を決めるボタンが6つ並びます。左の3つが横方向、右の3つが縦方向（上・中央・下）です。
3. 縦方向の「上」を押します。文字が枠の上部へ移動します。

**四角の文字を枠の上部へ移動したところ**

<img alt="13-1-3_3.png" src="../../../image/13-1-3_3.png">

### 線でつなぐ

つなぎたいシェイプの縁にカーソルを合わせると、青い矢印と×印が出ます。そこからドラッグして、相手のシェイプの上で離すと、2つが線で結ばれます。

> ⚠️ **注意**: 引いた線の端に矢印が付くことがありますが、付いたままで構いません。線の向きに意味があるかどうかは、それぞれの図を学ぶ章で説明します。

### .drawioファイルとして保存する

メニューバーの「ファイル」から「保存」を選びます（⌘+S、Windowsでは Ctrl+S）。開いたダイアログ（設定画面）で、3つの欄を確認します。

**「ファイル」から「保存」を選んだところ**

<img alt="13-1-3_4.png" src="../../../image/13-1-3_4.png">

| 欄 | 決めること |
|:-----|:-----------|
| 名前を付けて保存 | ファイル名。あとで中身が分かる英数字の名前にします（例: `usecase.drawio`） |
| タイプ | ファイルの形式。既定の `XMLファイル (.drawio)` のままにします |
| 場所 | 保存先。この教材では **デバイス**（自分のPC）を選びます。手元にあれば、Tutorial 4で学んだGitの操作で記録できます |

「保存」を押すと、そのままダウンロードフォルダへ保存されるか、保存先のフォルダを選ぶ画面が開くかのどちらかです（2026年8月時点）。選ぶ画面が開いた場合もダウンロードフォルダを選び、あとでdesign-practiceへ自分で移します。

できる `.drawio` ファイルが図の本体で、開き直せば続きから編集できます。

### PNG画像に書き出す

`.drawio` ファイルは、draw.ioで開かないと中身を見られません。GitHub上でそのまま図を確認できるように、画像も書き出します。

メニューバーの「ファイル」から「形式を指定してエクスポート」→「PNG...」と選びます。

**ファイルメニューからPNGの書き出しを選んだところ**

<img alt="13-1-3_5.png" src="../../../image/13-1-3_5.png">

## ⚙️ design-practiceリポジトリを用意する

図を描き始める前に、置き場所を作ります。

**手順1: GitHubでリポジトリを作る**

作り方は、4-4-1「リモートリポジトリの作成」で学んだとおりです。GitHubの右上の「＋」から「New repository」を開き、次のように設定します。

- Repository name: `design-practice`
- Public / Private: `Public`
- Initialize this repository with: `Add a README file` にチェックを入れる

> ⚠️ **注意**: 4-4-1では「初期化オプションのチェックは全て空のままにする」と学びました。あれは、手元のリポジトリをGitHubへアップロードする場合の話です。今回は逆に、GitHub側で作ったものを手元へ持ってくるので、READMEを入れます。

**手順2: 手元にcloneする**

`design-practice` のページを開いて緑色の「Code」ボタンを押し、4-4-2「ローカルとリモートの接続」で学んだとおり、**SSHのタブに切り替えてから**URLをコピーします。`git@github.com:あなたのユーザー名/design-practice.git` という形式です。

> ⚠️ **注意**: 「Code」ボタンを押した直後はHTTPSのタブが選ばれています。そのURLでcloneすると、pushのたびにユーザー名やパスワードを聞かれます。Tutorial 10やTutorial 11のハンズオンで使った `https://` のURLは、他の人が用意したスターターキットを取ってくるだけで、pushしない場面のものでした。今回は自分のリポジトリへpushするので、SSHを使います。

このフォルダは先の章でも使い続けるので、置き場所はホームディレクトリ（`~`）に固定します。

```bash
# ホームディレクトリへ移動する
cd ~

# URLの部分は、自分がコピーしたものに置き換える
git clone git@github.com:あなたのユーザー名/design-practice.git
cd design-practice
```

> ⚠️ **注意**: Windowsの方は、ここまでの操作をWSL（Ubuntu）のターミナルで行ってください。6-2-1で学んだとおり、作業フォルダはWSL側のホームに置きます。`~/design-practice` は、WSLの中に作られます。

**手順3: このセクション用のフォルダを作る**

Chapter 1の成果物を入れる `13-1/` を作ります。

```bash
# design-practice フォルダの中で実行する
mkdir 13-1
```

> 💡 **TIP**: Gitは、中にファイルが1つも無いフォルダを記録できません。`13-1/` は、このあとの実践で図のファイルを入れてから記録します。

**手順4: VS Codeで開く**

6-2-6で学んだ `code .` で、`design-practice` をVS Codeで開いておきます。

```bash
# design-practice フォルダの中で実行する
code .
```

左側のエクスプローラーに `13-1` フォルダとREADMEファイルが並びます。Windowsの方は、左下に「WSL: Ubuntu」と出ていることを確認してください。

### 書き出したファイルをdesign-practiceへ移す

ダウンロードフォルダに入った `.drawio` とPNGを、`13-1/` へ移します。

**Macの方**は、ダウンロードフォルダも `design-practice` も同じMacの中にあるので、Finderでドラッグするか、`mv` で移せます。

```bash
# 例: ダウンロードした self-checkout.drawio を 13-1/ へ移す
mv ~/Downloads/self-checkout.drawio ~/design-practice/13-1/
```

**Windowsの方**は、ファイルが2つの場所にまたがります。draw.ioはWindows側のブラウザで動くので保存先はWindows側のダウンロードフォルダで、`design-practice` はWSLの中にあります。WSL側へ渡す操作が1回だけ必要で、おすすめはVS Codeへのドラッグ＆ドロップです。

1. 手順4で開いたVS Code（左下が「WSL: Ubuntu」のもの）を表示します。
2. Windowsのエクスプローラーで、ダウンロードフォルダを開きます。
3. `.drawio` とPNGを、VS Codeの左側のエクスプローラーにある `13-1` フォルダの上へドラッグ＆ドロップします。

VS Codeのエクスプローラーにファイル名が並べば、WSL側の `~/design-practice/13-1/` にコピーされています。

WSLのターミナルからは、Windows側のダウンロードフォルダが `/mnt/c/Users/（Windowsのユーザー名）/Downloads` として見えるので、`cp` でコピーしても構いません。

```bash
# （Windowsのユーザー名）は、自分のWindowsのユーザー名に置き換える
cp /mnt/c/Users/（Windowsのユーザー名）/Downloads/self-checkout.drawio ~/design-practice/13-1/
```

> 💡 **TIP**: 6-2-1で「作業フォルダは `/mnt/c` の下に置かない」と学びました。あれは置き場所の話で、Windows側にあるファイルを読み取ってコピーするのは問題ありません。

## 🏃 最初の1図を描いてみよう

> 🔥 この演習では、図をAIに描かせずに、自分の手で描きましょう。記法や考え方についてAIに質問するのは構いませんが、成果物を生成させるのはTutorial 14までお預けです。まず自分の手と頭で描けるようになった人だけが、AIの描いた設計を正しく評価できるようになります。

道具に慣れるために、簡単な図を1枚描きます。題材はスーパーやコンビニのセルフレジで、使う部品は次のとおりです。

- 棒人間が1つ: 「お客さん」
- 四角が1つ: 「セルフレジ」（この中に楕円を並べます）
- 楕円が2つ: 「商品を読み取る」「支払う」
- 線が2本: 棒人間と、2つの楕円をそれぞれつなぐ

> ⚠️ **注意**: この棒人間・四角・楕円・線が設計の上で持つ意味は、次のChapter 2で学びます。ここでの目的は、シェイプを思ったとおりに置き、線でつなぎ、保存と書き出しができることです。

### Step 1: 棒人間と四角を置く

`https://app.diagrams.net/` を開き、検索ボックスに `actor` と入力して、棒人間をキャンバスの左側に置きます。次に「一般」パレットの四角形を、その右側に置きます。あとで中に楕円を2つ入れるので、大きめにします。

### Step 2: 文字を入れて、四角の名前を上へ寄せる

棒人間をダブルクリックして「お客さん」、四角に「セルフレジ」と入力します。

このままだと「セルフレジ」の文字は四角の中央にあり、次のStepで置く楕円と重なります。四角を選び、「テキスト」タブで縦方向の「上」を押しておきます。

### Step 3: 楕円を2つ置く

検索ボックスに `ellipse` と入力して楕円を出し、四角の中に上下に並べて2つ置きます。上の楕円に「商品を読み取る」、下の楕円に「支払う」と入力します。

### Step 4: 線でつなぐ

棒人間の縁に出てきた青い矢印からドラッグして、「商品を読み取る」の楕円の上で離します。同じ手順で、棒人間と「支払う」もつなぎます。

### Step 5: 保存して、書き出して、記録する

1. 「ファイル」から「保存」を選びます。名前は `self-checkout.drawio`、「タイプ」は既定のまま、「場所」は「デバイス」を選び、ダウンロードフォルダに保存します。
2. 「ファイル」から「形式を指定してエクスポート」→「PNG...」を選び、既定のまま「エクスポート」を押します。ダウンロードされたファイルの名前が `self-checkout.png` になっていなければ、その名前に変えます。
3. 2つのファイルを `design-practice/13-1/` へ移します（移し方は「書き出したファイルをdesign-practiceへ移す」のとおりです）。
4. Tutorial 4とTutorial 12で学んだ流れで、コミットとpushまで済ませます。

```bash
# design-practice フォルダの中で実行する
git add 13-1
git commit -m "13-1: draw.ioの練習図を追加"
git push origin main
```

> 💡 **TIP**: Tutorial 12では、イシューを立ててブランチを切り、プルリクエストを出す流れを学びました。design-practiceは一人で使う練習用のリポジトリなので、ブランチを切らずに `main` へ直接コミットして構いません。

pushしたら、GitHubのdesign-practiceを開きます。`13-1/` に2つのファイルが並び、`self-checkout.png` をクリックして図が表示されれば完了です。

## 💡 よくある間違い・つまずきポイント

**保存した `.drawio` ファイルが見つからない**

保存のダイアログの「場所」で「デバイス」以外を選ぶと、自分のPCにファイルは作られません。「ファイル」から「名前を付けて保存...」を選び、「場所」を「デバイス」にして保存し直すと、ダウンロードフォルダに現れます。Windowsの方が探すのは、Windows側のダウンロードフォルダです（WSLの中には作られません）。

**シェイプに文字が入らない**

1回クリックしただけでは、シェイプが選ばれるだけです。ダブルクリックしてください。

**四角の名前と、中に置いた楕円が重なる**

四角を選び、「テキスト」タブで縦方向の「上」を押します。

## ✨ まとめ

- UMLは、プログラムの設計図の統一表記法です。記号の形と意味が決まっているので、読む人は図の読み方から考えずに済みます。
- この教材で作るのは、UMLの図4つ（ユースケース図・シーケンス図・状態遷移図・クラス図）、UMLに含まれない図3つ（画面遷移図・ワイヤーフレーム・ER図）、表2つ（権限マトリクス・CRUD表）です。
- 作図の約束事は3つです。Tutorial 13の間は図を自分の手で描くこと、道具はdraw.ioに揃えること、成果物はdesign-practiceの章ごとのフォルダに残すことです。
- draw.ioでは、検索ボックスからシェイプを出し、ダブルクリックで文字を入れ、シェイプの縁から線を引きます。書き出した `.drawio` とPNGは、ダウンロードフォルダから `13-1/` へ移して記録します。

これで、設計の全体像は終わりです。次のChapter 2「機能設計」からは、設計書を作り始めます。最初に扱うのは、与えられた仕様から機能一覧を作る作業と、このセクションで置いた棒人間・四角・楕円・線に意味を与えた図、ユースケース図です。
