# 13-3-2: 画面仕様 - ワイヤーフレームと画面項目定義

## 🎯 このセクションで学ぶこと

- 1枚の画面に何をどの順で並べるのかを、線と枠だけの下書きに起こせるようになる。
- その画面に置く項目を、名前・種類・必須かどうかまで表に書き出せるようになる。
- 画面設計で決めることと、決めないことを区別できるようになる。

---

## 導入：画面の名前だけでは、まだ作れない

13-3-1で作った画面一覧に、こんな行がありました。

| ID | 画面名 | 役割 | 主な利用者 |
|:---|:-------|:-----|:-----------|
| SC-03 | 連絡先入力画面 | お名前と連絡先を入力する | 患者 |

この1行を渡されて、画面を作り始められるでしょうか。「連絡先」が電話番号なのか、メールアドレスなのか、その両方なのかが決まっていません。両方だとして、どちらも必ず入れてもらうのかも決まっていません。前の画面で選んだ診療と日時を、この画面にもう一度映すのかどうかも書かれていません。

四角の中身が空っぽのままだと、ここで手が止まります。埋めるために作るのが、次の2つです。

- **ワイヤーフレーム**（画面のどこに何を置くかを、線と枠だけで表した下書き）: 1枚の画面の並びを目で見て確かめるもの。
- **画面項目定義**（その画面に置く項目を、名前・種類・必須かどうかまで書き出した表）: 図では表せない決めごとを言葉で固定するもの。

2つで1組です。ワイヤーフレームだけでは「この欄は空のままでもよいのか」が分からず、表だけでは「どれが上でどれが下か」が分かりません。

## ワイヤーフレームの読み方

13-3-1で読んだ歯科医院の予約アプリから、SC-03「連絡先入力画面」のワイヤーフレームを見てください。

**歯科医院の予約アプリ 連絡先入力画面のワイヤーフレーム**

<img alt="13-3-2_1.png" src="../../../image/13-3-2_1.png">

線と四角と文字しかありませんが、この画面で何が起きるのかは読み取れます。

いちばん上に画面の見出しがあり、その下に前の画面で選んだ診療と日時が映ります。その下からは、「お名前」のような項目名の四角と、患者に入れてもらう空の四角が、横に2つで1組になって並びます。上から下へ読んでいけば、患者が何をすればよいのかが順にたどれます。

「電話」「メール」と書かれた2つの四角は、押して次へ進むところではありません。ご希望の連絡方法を、どちらか1つ選んでもらうための候補です。ワイヤーフレームでは、選ぶ候補もボタンも同じ四角で表すので、図の上では見分けが付きません。どちらなのかは、このあと作る画面項目定義で書き分けます。

つまり、この画面で押して次へ進むところは、いちばん下の1つだけです。この画面から出ていく矢印も、13-3-1の画面遷移図では1本だけでした。図と下書きが食い違っていれば、どちらかが間違っています。

この下書きが🔑 **決めていないこと**も読み取れます。文字の大きさ、色、枠の丸み、余白の広さ、ボタンの見た目。どれも決まっていません。13-1-1で確認したとおり、デザインは与えられるものとして進めるので、皆さんが決めるのは、🔑 **何を、どの順で、いくつ置くか**だけです。

## ワイヤーフレームの描き方

使う記号は4つです。

| 記号 | 表すもの |
|:-----|:---------|
| 外枠の大きな四角 | 画面1枚ぶんの範囲 |
| 中の四角 | 項目の置き場所（見出し・表示する値・項目名・入力欄・選ぶ候補・押すところ・一覧の1行） |
| 横線 | まとまりの区切り |
| 文字 | 項目名・ボタンの文字・仮の値 |

四角1つが項目1つとは限りません。項目名の四角と、その値が入る四角は、🔑 **2つで1組**です。選んでもらう項目なら、項目名の四角と、候補を並べた四角がまとめて1組になります。

**描く手順**

1. 画面一覧の「役割」の欄を読み直し、その画面に映るものと、入力してもらうものを書き出します。
2. 外枠を1つ置き、書き出したものを上から順に四角で並べます。並べる順は、利用者が読んでいく順です。
3. 押せるところ（ボタン・リンク）を置きます。押した先は、13-3-1で描いた画面遷移図の矢印と合っているかを確かめます。
4. 項目名やボタンの文字を、四角の中に書きます。値が入る欄は空のままにします。

一覧のように同じ形の行が並ぶところは、🔑 **2〜3行だけ描いて「以下同じ」と書きます**。実際に並ぶのが20行でも、20個の四角を描く意味はありません。決めたいのは1行の中に何が入るかであって、行の数ではないからです。

> ⚠️ **注意**: 実物そっくりに描こうとすると、時間ばかりかかって決めごとは1つも増えません。四角の大きさがそろっていなくても、並びが少しずれていても、そのままにしてください。

**draw.ioでの操作**

この図で新しく覚える操作はありません。13-1-3で学んだ四角・直線と、ダブルクリックでの文字入力だけで描けます。商品の一覧のように、1つの四角の中に文字と別の四角の両方を入れるときは、文字が枠の中央に来て中の四角と重なります。そのときは13-1-3で使った「テキスト」タブで、文字の位置を枠の上に寄せてください。

## 画面項目定義の読み方

同じ連絡先入力画面の画面項目定義が、次の表です。

| 項目名 | 種類 | 必須 | 内容 |
|:-------|:-----|:-----|:-----|
| 画面見出し | 表示 | - | 「連絡先の入力」 |
| 選んだ診療と日時 | 表示 | - | 前の2画面で選んだ診療名と日時 |
| お名前 | 入力（1行） | 必須 | 予約する方のお名前 |
| 電話番号 | 入力（1行） | 必須 | 当日つながる電話番号 |
| メールアドレス | 入力（1行） | 任意 | 予約内容をお送りする先 |
| ご希望の連絡方法 | 選択 | 必須 | 「電話」「メール」のどちらか1つ |
| 入力内容を確認するボタン | ボタン | - | 押すと予約内容確認画面へ移る |

ワイヤーフレームでは似たような枠が並んでいるだけでしたが、この表では1つずつ違うものになっています。必須（空のままでは先に進めない項目）の欄を見ると、お名前と電話番号は必ず入れてもらい、メールアドレスは空でもよいと決まっています。ご希望の連絡方法は、自由に書いてもらうのではなく、2つから選んでもらいます。ここまで決まって、はじめて実装する人は迷わずに画面を作れます。

いちばん下の行には、押した先が書かれています。13-3-1で描いた矢印と同じ内容です。図と表のどちらにも書いておくと、片方だけを見た人でも行き先が分かります。

## 画面項目定義の書き方

列は `項目名`・`種類`・`必須`・`内容` の4つで固定します。ワイヤーフレームに置いた四角を、上から順にたどって書き出すと漏れません。このとき、項目名の四角とその値が入る四角は、描いたときと同じく1組で1行にまとめます。連絡先入力画面の表が7行で足りているのは、そうやってまとめているからです。逆に、一覧の1行のように、1つの四角の中に複数のものを並べたところは、中に入っているものを1つずつ行にします。どちらの場合も、四角の数と表の行数は一致しません。

**「種類」に書く言葉は6つだけ**

| 種類 | どんな項目か |
|:-----|:-------------|
| 表示 | 見せるだけで、利用者が変えられないもの |
| 入力（1行） | 1行ぶんの文字を入れてもらうもの |
| 入力（複数行） | 何行にもわたる文章を入れてもらうもの |
| 選択 | 決まった候補から選んでもらうもの |
| ボタン | 押すと何かが起きるもの |
| リンク | 押すと別の画面へ移るもの |

5-1-6「フォームの基礎」で学んだ `<input>` や `<textarea>` を思い出した方もいるはずです。設計書には、そうしたタグの名前は書きません。画面項目定義は依頼者にも読んでもらう書類なので、作り方の言葉は持ち込まず、上の6つの言葉で表します。

**「必須」の欄の書き方**

必須かどうかを書くのは、入力と選択の行だけです。「必須」か「任意」のどちらかを書きます。表示・ボタン・リンクの行には `-` を書きます。空欄にしないのは、13-2-2で無い項目を空欄にせず「なし」と書いたのと同じ理由で、決めた結果と書き忘れを区別するためです。

必須かどうかは、思いつきでは決められません。「お名前が無いと、当日どなたの予約か分からない」「メールアドレスは、電話がつながれば無くても困らない」というように、その項目が無いと誰が何に困るのかで決めます。決められないときは、13-2-1で学んだとおり、想定を添えて確認事項リストへ回します。

**「内容」の欄の書き方**

表示の行には何を映すのか、入力の行には何を入れてもらうのか、ボタンとリンクの行には押した先を書きます。「どこまでの値なら受け付けるか」は、まだ書きません。それは次の13-3-3で入力チェック表として作ります。

## 🏃 描いてみよう

> 🔥 この演習では、設計書をAIに作らせずに、自分の手で書きましょう。記法や考え方についてAIに質問するのは構いませんが、成果物を生成させるのはTutorial 14までお預けです。まず自分の手と頭で書けるようになった人だけが、AIの作った設計を正しく評価できるようになります。

13-3-1で画面一覧と画面遷移図を作った、9-4-9「Eloquent ORM - ハンズオン演習」のブログシステム（`eloquent-app-practice`）を続けて使います。今回は3枚のうち **SC-02 投稿作成画面** の1枚だけを取り出して、ワイヤーフレームと画面項目定義を作ります。

9-4-9で配置したBladeの中身が、そのまま答え合わせの材料になります。

```blade
<!-- resources/views/posts/create.blade.php（9-4-9 の body 部分。CSS は省略） -->
<body>
    <h1>投稿作成</h1>
    <form action="/posts" method="POST">
        @csrf
        <div class="form-group">
            <label>タイトル</label>
            <input type="text" name="title" required>
        </div>
        <div class="form-group">
            <label>内容</label>
            <textarea name="content" rows="5"></textarea>
        </div>
        <button type="submit">作成</button>
    </form>
    <p><a href="/posts">← 一覧に戻る</a></p>
</body>
```

### Step 1: ワイヤーフレームを描く

draw.ioで、外枠の四角を1つ置き、上のBladeのうち**画面に文字や欄として映るものだけ**を、上から順に並べます。`@csrf` や `<div class="form-group">` のように目に見えないものは置きません。文字は、実物に書かれているものをそのまま使ってください。

### Step 2: 画面項目定義を作る

列は `項目名`・`種類`・`必須`・`内容` の4つです。ワイヤーフレームに置いた四角を、書き方のとおりに上からたどって書き出します。

「必須」の欄を埋めるとき、次の2行を見比べてください。

```blade
<input type="text" name="title" required>
<textarea name="content" rows="5"></textarea>
```

片方には `required` が付いていて、もう片方には付いていません。9-4-9では、この差はコードの中にしか書かれていませんでした。本来は逆で、🔑 **どちらを必須にするかを先に決めて、この表に書いてから**コードを書きます。表に書いてあれば、実装する人が迷いませんし、あとから「内容は空でもよかったんでしたっけ」と聞かれても、表を指させます。

### Step 3: design-practiceに保存する

`13-3/` フォルダに、ワイヤーフレームを `blog-wireframe.drawio` と `blog-wireframe.png`、画面項目定義を `blog-screen-items.md` として保存します。保存した `.drawio` と書き出したPNGはダウンロードフォルダに入るので、13-1-3の「書き出したファイルをdesign-practiceへ移す」のとおりに `13-3/` へ移してから、コミットしてください。

```bash
# design-practice フォルダの中で実行する
git add 13-3
git commit -m "13-3: ブログシステムの投稿作成画面の画面仕様を追加"
git push origin main
```

設計に唯一の正解はありません。四角の大きさや位置が解答例と違っていても、上の観点を満たしていれば合格です。そのうえで、判断が分かれやすい2点を補足します。

- **内容を「任意」とした理由**: 実物の `<textarea>` に `required` が付いていないからです。ただし、本文の無い投稿を許すかどうかは決めごとであって、コードから読み取った結果が正解とは限りません。自分で設計するときにここで迷ったら、「本文が空の投稿は保存できない想定ですが、問題ないですか」と確認事項リストへ回します。

## 💡 よくある間違いと現場での使われ方

**よくある間違い: 見た目を作り込んでしまう**

色を塗り、角を丸くし、実物の写真をはめ込んでしまう間違いです。時間がかかるだけではありません。見せられた依頼者も見た目のほうに気を取られて、いちばん見てほしい項目の抜けを指摘してくれなくなります。ワイヤーフレームがわざと線と枠だけなのは、話題を中身に集中させるためです。

現場では、ワイヤーフレームと画面項目定義で、渡す相手が違います。ワイヤーフレームは依頼者に見せて、「この画面でこれだけのことができれば足りますか」を合意するために使います。画面項目定義は実装する人と、あとで画面の見た目を作るデザイナーに渡します。デザイナーがいる現場では、ワイヤーフレームを渡してそこから仕上げてもらうので、この下書きが仕上げの出発点になります。

## ✨ まとめ

- ワイヤーフレームは、外枠の四角・中の四角・横線・文字の4つだけで描く画面の下書きです。決めるのは、何を、どの順で、いくつ置くかだけで、色や書体は決めません。
- 一覧のように同じ形の行が並ぶところは、2〜3行だけ描いて「以下同じ」と書きます。
- 画面項目定義は、`項目名`・`種類`・`必須`・`内容` の4列の表です。ワイヤーフレームの四角を上からたどって書き出すと漏れません。項目名と入力欄の四角は1組で1行なので、四角の数と行数は一致しません。
- 種類に書く言葉は、表示・入力（1行）・入力（複数行）・選択・ボタン・リンクの6つだけです。タグの名前のような作り方の言葉は書きません。
- 必須かどうかは入力と選択の行だけに書き、それ以外は `-` を書きます。決められないときは、想定を添えて確認事項リストへ回します。

次のセクション（13-3-3）では、この表で「必須」と書いた入力欄について、どこまでの値を受け付けるのかと、受け付けられなかったときに画面へ何と出すのかを決めます。
