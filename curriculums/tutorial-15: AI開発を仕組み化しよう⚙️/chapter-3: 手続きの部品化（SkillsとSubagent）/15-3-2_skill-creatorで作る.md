# 15-3-2: skill-creatorで作る

## 🎯 このセクションで学ぶこと

- skill-creatorを入れて、いまの会話でやった作業をSkillに起こさせられるようになる。
- 生成された `SKILL.md` を全文読み、頼んでいない手順が混ざっていないかを確かめられるようになる。
- 生成物に自分で1行足して、自分の道具に直せるようになる。

---

## 導入

3つの問いを通った1本目、差分の受け取り手順を部品にします。作り方は、`SKILL.md` を思い出しながら手で書く形ではありません。実際に1回やってから、いまやった手順を書き起こさせます。思い出して書いた手順は、たいてい実際にやっている手順より短くなります。抜けたところは、部品を呼ぶたびに抜けたままになります。

---

## 部品にするもの

14-4-2で、届いた差分を3段の順に読みました。1段目で `docs/reply.md` と突き合わせ、2段目で触っていないはずの4か所を見て、3段目でこの機能に当たる観点だけを当てる。この順番は、リプライ機能でもポスト作成機能でも同じでした。変わったのは対象の差分だけです。

同じ差分には `/code-review` も送りました。汎用の間違い探しはそちらに任せ、部品にするのは `docs/reply.md` に書いたものと突き合わせるという、このプロジェクトの物差しのほうです（15-3-1）。

部品に任せるのは、順番の組み立てまでです。返ってくるのは下読みで、絞られた先を読むのは自分です。

---

## skill-creatorとは

skill-creatorは、Skillを作るためのSkillです。「いまやった手順をSkillにして」と頼むと、その会話を材料にして `SKILL.md` を書き起こします。置き場所や書き方の選択肢を聞き返してくることもあれば、材料がそろっていれば聞かずに書き上げることもあります。

Claude Codeに最初から入っているものではないので、公式が配っているものを入れます。次の2行を、Claude Codeの入力欄に打ちます（2026年8月時点）。

```text
/plugin marketplace add anthropics/skills
/plugin install example-skills@anthropic-agent-skills
```

1行目は、公式が置いている配布元を登録します。2行目で、その中の `example-skills` というまとまりを入れます。こういう「Skillやサブエージェントをまとめて配れる形」をプラグインと呼びます。標準の `.claude/` に置くものとの使い分けは、15-3-5にまとめてあります。

この2行で入るのは、リポジトリではなく手元のClaude Codeのほうです。Playwright MCPを入れたとき（14-4-4）と同じで、`git status` には何も出ません。

---

## 🏃 差分の受け取りをSkillにする

投稿アプリのフォルダでClaude Codeを起動します。この演習は、まっさらな状態から始めます。

```bash
# 投稿アプリのフォルダで実行する
claude
```

### Step 1: skill-creatorを入れる

上の2行を順に打ちます。

```text
/plugin marketplace add anthropics/skills
```

```text
/plugin install example-skills@anthropic-agent-skills
```

一度入れれば、次のセッションからも使えます。

### Step 2: 対象のプルリクエストの番号を調べる

材料にするのは、Tutorial 14でマージしたリプライ機能のプルリクエストです。番号は人によって違うので、一覧で確かめます。

```text
gh pr list --state merged で、マージ済みのプルリクエストの一覧を出して。
```

リプライ機能のプルリクエストの番号を控えておいてください。以下では `<番号>` と書きます。

### Step 3: 受け取りの手順を、手で1回やる

14-4-2の3段を、そのまま依頼文にします。1行目の `gh pr diff <番号>` は、マージ済みのプルリクエストの差分を出すコマンドです。

```text
gh pr diff <番号> でリプライ機能の差分を出して、次の順で読んで報告して。

1. docs/reply.md と突き合わせる。書いていないものが増えていないか（composer.json に注意）
2. 触っていないはずの場所を見る。routes/web.php・app/Http/Controllers/PostController.php・
   app/Policies/PostPolicy.php・resources/views/posts/index.blade.php の4つ。消えた行から先に
3. 中身を読む。N+1・認可の置き場所・マスアサインメント・XSS・CSRF・入力チェック・書き方の揃い

観点 / 判定（要確認・OK・対象外）/ ファイル名:行番号 / 気づいたこと の順で1行ずつ。
判定できないときは、何が足りなくて判定できないのかを書いて。
最後に、人が自分の目で読むべき場所を3つまで挙げて。コードは直さないで。
```

最後の2行が、この作業の範囲を決めています。「人が自分の目で読むべき場所を3つまで」で読む場所をこちらに戻し、「コードは直さないで」で手前に止めます。ここが無いと、AIが書いたコードをAIが直す形になります。

返ってきた報告は、このあと部品の結果と見比べる相手になります。目を通しておいてください。

### Step 4: いまの会話をSkillにさせる

次の1行だけを送ります。

```text
いまこの会話でやった手順をSkillにして
```

名前を打っていませんが、この頼み方でもClaude Codeのほうからskill-creatorを見つけて起動します。15-3-1で見た2つ目の呼ばれ方です。画面には `Skill(example-skills:skill-creator)` と出ます。出てこなければ `/skill-creator` と打ってください。どちらでも動くものは同じです。

続けて、置き場所や名前を選択式で聞かれます。答えるのはこちらです。ただし、材料がそろっていると判断されると、何も聞かずにそのまま `SKILL.md` を書き始めることもあります。次の画面は、聞かずに書き始めたときのものです。

**SKILL.mdができた画面（2026年8月時点）**

<img alt="15-3-2_1.png" src="https://s3.ap-northeast-1.amazonaws.com/coachtech-lms-bucket-dev/curriculums/images/15-3-2_1.png">

> 💡 **進行例について**: AIとの開発は毎回違う流れになります。ここに示すのは一つの進行例です。あなたの画面と違っていても、チェックリストを満たしていれば正解です。

```text
Claude Code: （Skill(example-skills:skill-creator) が起動し、置き場所・手順の持ち方・
              できたものを試すかどうかを、選択式で聞いてくる。あるいは何も聞かずに
              SKILL.md を書き、どこに何を書いたかが報告される）
```

置き場所を聞かれたら、**このリポジトリ内**を選びます。`.claude/skills/` の下に置かれるので、コミットすれば同じリポジトリで作業する人にも渡ります。聞かれなかったときも、`.claude/skills/` の下にできていれば同じです。名前は会話の中身から自動で付きます。ここでは `review-diff` を想定して書きますが、違う名前が付いたら、以下はその名前に読み替えてください。

聞かれる項目は、そのときによって変わります。意味が取れない選択肢が出たら、そのまま「どちらを選ぶと何が違うのか」と聞き返して構いません。逆に何も聞かれなかったときは、次のStepで中身を読むところで確かめます。

### Step 5: できた `SKILL.md` を全文読む

VS Codeで `.claude/skills/review-diff/SKILL.md` を開きます。読む前に流し見で済ませないでください。ここから先、この部品を呼ぶたびに実行されるのは、いま画面に出ている文章そのものです。

見るのは次のところです。

- 名札の部分が、15-3-1で見た形（`name` と `description`）になっているか
- `description` の後半に、自分が打ちそうな言い方が並んでいるか。無ければ足す
- Step 3で頼んでいない観点や手順が混ざっていないか
- 「人が自分の目で読むべき場所を3つまで」と「コードは直さない」が残っているか

### Step 6: 突き合わせ先が無いときの決めを、自分で足す

生成された時点では、1段目は「`docs/reply.md` と突き合わせる」になっているはずです。設計書を作らずに進めた機能では、突き合わせる相手がありません。計画をどう持つかは変更ごとに選ぶ、と14-3-1で決めたので、設計書の無い機能はこの先も出てきます。

`SKILL.md` の1段目に、自分の手で1行足します。

```markdown
設計書が無い機能のときは、そのイシューに書いた受け入れ条件を突き合わせ先にする。
```

生成させたものは、そのまま使わなければいけないものではありません。書いたのが誰であっても、この先これを呼ぶのはあなたです。

### Step 7: 起動し直して、同じ差分に当て直す

`.claude/skills/` は、いまのセッションを始めた時点ではありませんでした。作った直後のこのセッションからは、まだ呼べません（15-3-1）。いったん終了して、同じ会話の続きから開き直します。

```bash
# 投稿アプリのフォルダで実行する
claude -c
```

`-c` は最後の会話の続きから始める起動のしかたです（14-5-2）。起動し直したことに変わりはないので、いま作った部品が読み込まれ、Step 3の報告も画面をさかのぼれば残っています。

同じ差分に、今度は部品を当てます。

```text
/review-diff <番号> のプルリクエストの差分を見て
```

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
Claude Code: （書いた手順がそのまま読み込まれ、3段の順に読んだ結果が、
              観点 / 判定 / ファイル名:行番号 / 気づいたこと の形で1行ずつ並び、
              最後に人が自分の目で読むべき場所が3つまで挙がる）
```

何を見ればよいのかを聞き返されたら、そのまま答えて構いません。呼ぶときに後ろへ続けた文をどう扱うかは、`SKILL.md` の書き方で決まります（15-3-4）。

Step 3の報告と見比べてください。同じ順番・同じ形で返っていれば、手順が部品に移っています。判定の中身は一致しなくて構いません。見ているのは、当てる観点をその場で組み立てる作業が消えたかどうかです。

呼んでも見つからないと返ったときは、フォルダ名と打った名前を見比べ、合っていれば `/exit` してもう一度 `claude` で起動してください。

### Step 8: 記録する

```bash
# 投稿アプリのフォルダで実行する
git status
```

差分が出ているのは `.claude/` だけで、`app/` のファイルは変わっていないはずです。`SKILL.md` の最後の1行が効いています。確かめたら、コミットします。

```text
.claude/skills をコミットして、main に push してください。
そのあと、棚卸しのイシューの3つ目「差分と設計書を突き合わせる順番を組み立てた」にチェックを付けて。
```

これは機能を作る作業ではないので、作業1つにブランチ1本という区切り（14-3-2）には当てはまりません。ブランチを切らずに `main` へ送ります。

思いどおりに直らない・壊れたと感じたら、14-5-1（直らないときの型）へ進んでください。まだコミットしていない変更は `git restore .`（4-3-5）で元に戻せます。

このセクションが終わった時点で、次の5つを確かめてください。

- [ ] `.claude/skills/review-diff/SKILL.md` ができていて、全文を読んだ
- [ ] Step 3で頼んでいない観点や手順が混ざっていない
- [ ] 設計書が無いときの突き合わせ先を、自分の手で1行足した
- [ ] 起動し直したあと `/review-diff` が動き、Step 3と同じ形で返ってきた
- [ ] `git status` で `app/` に差分が無いことを見てから、`main` にpushした

---

## ✨ まとめ

- 手順を部品にするときは、先に1回やってから「いまこの会話でやった手順をSkillにして」と頼む。書き起こすのはskill-creatorで、公式の配布元から入れる。
- skill-creatorは環境側に入る。リポジトリには何も増えないので、cloneし直した人はもう一度入れる。
- 置き場所を聞かれたら、このリポジトリ内を選ぶ。コミットすれば同じリポジトリで作業する人に渡る。
- 生成された `SKILL.md` は全文読む。頼んでいない手順が混ざっていないか、範囲を止める行が残っているかを見る。
- 足りない決めは自分の手で書き足す。設計書が無い機能では、イシューの受け入れ条件が突き合わせ先になる。
- `.claude/skills/` を初めて作ったセッションからは呼べない。起動し直してから当て直す。
