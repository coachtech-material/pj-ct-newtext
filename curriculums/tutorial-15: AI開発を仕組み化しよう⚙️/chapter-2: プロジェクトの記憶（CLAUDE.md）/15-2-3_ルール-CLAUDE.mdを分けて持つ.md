# 15-2-3: ルール - CLAUDE.mdを分けて持つ

## 🎯 このセクションで学ぶこと

- 決まりを話題ごとのファイルに分けて置ける。
- `paths` を付けたルールが、いつ読み込まれるのかを説明できる。
- 事実・場所限定の決まり・手順の3つを、どこに置くか選び分けられる。

---

## 導入

15-2-1で `CLAUDE.md` に決まりを足しました。この調子で足していくと、コマンドの話・書き方の話・テストの話・触らないでほしいものが、1枚の中に混ざって並びます。テストの決まりを直したいときに、どこに書いたかを探すところから始めることになりますし、似た決まりが離れた場所に2つあっても気づけません。

---

## ルールとは

ルールは、`.claude/rules/` というフォルダに置く、話題ごとに分けた決まりのファイルです。1つのファイルに1つの話題を書き、中身が分かる名前を付けます。2026年8月時点の公式ドキュメントが例に挙げているのが、まさに `testing.md`（テストの決まり）や `api-design.md` です。`.md` のファイルは、下にフォルダを作って入れても見つけてもらえます。

```text
post-app-practice/
├── CLAUDE.md
└── .claude/
    ├── settings.json
    └── rules/
        └── testing.md
```

`paths` の指定が無いルールは、起動のときに `CLAUDE.md` と同じ扱いで読み込まれます（2026年8月時点の公式ドキュメント）。`/context` を打つと、`CLAUDE.md` と合わせて `Memory files` に数えられます。置き場所が分かれるだけで、毎回読まれることは変わりません。

### なぜ分けるか

1枚に混ざったままだと、15-2-2で見た太り方のうち③（他の場所にあることの写し）と⑥（前と後で食い違っている）が育ちます。どちらも、どこに何を書いたかが分からなくなることから生まれます。話題ごとにファイルが分かれていれば、テストの決まりを足したいときに開く先は1つに決まります。

正直に書いておくと、いまの `CLAUDE.md` は200行の目安に遠く届いていません。この大きさなら、1枚のままでも回ります。公式ドキュメントも、分ける話は「大きくなってきたら」の手当てとして書いています。ここで分けるのは、大きくなってから慌てないように、置き場所の決め方を先に持っておくためです。

---

## paths - 場所で読み込みを絞る

ルールのファイルの先頭に `paths` を書くと、そのパターンに当てはまるファイルをClaudeが読んだときだけ、その決まりが読み込まれます（2026年8月時点）。ツールを使うたびに毎回読まれるわけではありません。

書き方は、ファイルのいちばん上に `---` ではさんだ数行を置いて、その中に当てはめたい場所を並べる形です。

```markdown
---
paths:
  - "database/migrations/**"
---

# マイグレーションの決まり

- 実行済みのマイグレーションファイルは書き換えず、新しく1つ追加する。
```

こう書いたルールは、`database/migrations/` の中のファイルをClaudeが読んだときに効きます。それ以外の作業のあいだは読み込まれないので、そのぶんコンテキストの空きが残ります。

パターンの書き方は、次の形です。

| 書き方 | 当てはまるもの |
|:--|:--|
| `**/*.php` | どの階層にあっても、PHPのファイル全部 |
| `app/**/*` | `app/` の下のファイル全部 |
| `*.md` | プロジェクトのいちばん上にある、マークダウンのファイル |
| `tests/Feature/*.php` | `tests/Feature/` の直下にある、PHPのファイル |

`/compact` で会話を要約したあと、いちばん上の `CLAUDE.md` はディスクから読み直されますが、`paths` を付けたルールは読み直されません。当てはまるファイルを次に読んだときに、また読み込まれます（2026年8月時点の公式ドキュメント）。

> 💡 **TIP**: 自分のマシンのどのプロジェクトでも効かせたい決まりは、`~/.claude/rules/` に置けます。同じことがプロジェクト側にも書いてあれば、プロジェクト側が優先されます（2026年8月時点）。

## 🏃 テストの決まりを別のファイルへ移す

15-2-1で `CLAUDE.md` に足した決まりのうち、テストの行を `.claude/rules/testing.md` へ移します。`paths` は付けません。起動のたびに読まれるまま、話題だけを分けます。

思いどおりに直らない・壊れたと感じたら14-5-1（直らないときの型）へ。応急は `git restore .`

```bash
# アプリのフォルダへ移動して、記録していない変更が無いかを見る
cd ~/laravel-practice/post-app-practice
git status
```

自分が触ったファイルが出てきた場合は、先にコミットしておいてください。

```bash
# アプリのフォルダで実行する
claude
```

### Step 1: 移す先を作らせる

渡すのは、どこに何を分けたいかと、読ませる先だけです。何が決まりとして要るのかは、このアプリのテストを実際に読めるAIのほうが分かります（15-1-3）。

```text
テストの決まりを .claude/rules/testing.md に分けて持ちたい。
@CLAUDE.md のテストの行と、@tests/ の中身を見て、
このアプリのテストの決まりをルール化してほしい。
そのうえで、CLAUDE.md からテストの行を消して。
```

できあがったファイルを開いて読みます。見比べる相手は、14-4-1から自分が実際にやってきたテストの回し方です。自分がやっていることで書かれていない決まりがあれば、その場で足させます。行数も文言も毎回変わるので、下の例と同じである必要はありません。

<details>
<summary>📄 できあがりの一例（自分のファイルを読んでから開いてください）</summary>

```markdown
# テストの決まり

- 機能のテストは `tests/Feature/` に置く。
- 実装を変えたら、テストも書いて `./vendor/bin/sail test` で回し、通るまで直して、最後に結果を報告する。
- テストを1クラスだけ回すときは `./vendor/bin/sail test --filter ReplyTest` の形で回す。
- データベースを使うテストには `use RefreshDatabase;` を付ける。
```

2行目は、15-2-1で `CLAUDE.md` に足した行が移ってきたものです。残りは、14-4-1でテストを回したときの実際のやり方が決まりの形になったものです。

</details>

### Step 2: 移した行が両方に残っていないかを見る

`CLAUDE.md` を開いて、テストの行が消えていることを確かめます。15-2-1で決めた「古い行を消してから、新しい行を足す」を、移すときにも当てます。両方に残したままだと、片方を直した日にもう片方が古くなります。

`CLAUDE.md` にこの行が見当たらなければ、消す作業は要りません。`.claude/rules/testing.md` の側に入っていれば、それで同じ状態です。

### Step 3: 開き直して、読まれていることを見る

`paths` の無いルールが読み込まれるのは起動のときなので、いま開いているセッションでは間に合いません。`/exit` で閉じて、起動し直します。

```bash
# アプリのフォルダで実行する
claude
```

`/context` を打って、`Memory files` の行を見ます。`CLAUDE.md` だけだったときより、数えられているファイルが増えています（2026年8月時点）。


- [ ] `.claude/rules/testing.md` が、`.claude/rules/` の下にある

## 決まりの置き場

15-1-3で見た対応表を、ここでもう一度当てます。毎回のセッションで要る事実は `CLAUDE.md`。決まった場所だけで効く決まりは、`paths` を付けたルール。順番に踏む複数の手順は、Skill（Chapter 3で作ります）。2026年8月時点の公式ドキュメントも、この3つで使い分けを説明しています。

いま `.claude/rules/testing.md` に移したテストの決まりは、3つのうち1つ目です。話題を分けただけで、毎回読まれることは変えていません。`paths` を付けるかどうかは、その決まりが**どこでも効いてほしいか**、**決まった場所でだけ効けばよいか**で選びます。

---

## ✨ まとめ

- 話題ごとの決まりは `.claude/rules/` に、1ファイル1話題で置く。ファイル名は中身が分かるものにする。
- `paths` の無いルールは、起動のときに `CLAUDE.md` と同じ扱いで読まれる。読み込まれたかは `/context` の `Memory files` で見る。
- `paths` を付けたルールは、当てはまるファイルをClaudeが読んだときに読み込まれる。`/compact` のあとは読み直されない。
- 移すときも、元の行を消してから足す。両方に残すと、片方が古くなった日に食い違う。
- 毎回要る事実は `CLAUDE.md`、場所限定の決まりは `paths` 付きのルール、複数の手順はSkill。
