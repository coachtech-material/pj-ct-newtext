# 14-2-2: 整理はAIとやる

## 🎯 このセクションで学ぶこと

- 決めていないことを決めていないまま渡して、決めるべき分かれ道をAIに質問させられるようになる。
- 返ってきた問いに答えながら、受け入れ条件を「〜すると、〜になる」の形まで固められるようになる。
- 案出し・調べもの・コードの読み解きを、文の形を整えないまま投げられるようになる。

---

## 導入

14-2-1で、まだ固まっていないことの整理は、このセクションでAIと一緒にやると書きました。整理を任せる相手はAIで、決める人はあなたのままです。開発フロー（Issue化 → 計画 → 実装とテスト → レビュー → UAT → PR）の現在地は前のセクションと同じで、先頭の、意図と受け入れ条件を固めるところがまだ終わっていません。

---

## 決め落としの見つけ方

機能を1つ足すと決めた時点で、決めなければならない分かれ道が何本か生まれます。プロフィール画面なら、誰のプロフィールを見られるのか、といったところです。

やっかいなのは、分かれ道が何本あるのかが、作ったことのない機能では分からないことです。数えられないものは、決め落とします。

ここはAIに聞き出させます。要望の文だけを渡して、**足りない判断を質問させます**。自分から「何を決めればいいですか」と尋ねると一般論が返りますが、いまのアプリを読んだうえで質問させると、このアプリで実際に分かれるところが出てきます。

渡す文に足すのは、「決めないといけないことがあれば、先にこちらへ質問して」の1行です。あとは14-2-1と同じで、コードを書く手前で止めておきます。

聞き出すだけで、決めるのはあなたです。実際の利用を大規模に調べた[Anthropicの分析](https://www.anthropic.com/research/claude-code-expertise)でも、何をするかの判断はおよそ7割を人が、どうやるかの判断はおよそ8割をAIが担っていました。返ってきた問いを読み飛ばして進めれば、AIが決めた側で残りが組み上がります。

## 曖昧に投げてよいもの

依頼を組み立てるのは、作らせるときの話です。作らせない用事なら、思いついた文をそのまま投げて構いません。

機能の案を出させる。

```text
このアプリに機能を1つ足すなら何がある？ 3つくらい出して。
```

アプリの中がどう繋がっているかを調べさせる。

```text
タイムラインでポストを出しているところ、どこからどう繋がってるか教えて。
```

自分で `routes/web.php` から順にファイルを開いて追うより、速く済みます。読んで分からなかったところは、そのまま続けて聞けます。

目の前のコードが何をしているのかを聞く。

```text
app/Policies/PostPolicy.php って何してるファイル？
```

ただし、案出しの返答をそのまま「じゃあ作って」に繋げると、目的も受け入れ条件も渡っていない依頼になります。

## 🏃 プロフィール画面の受け入れ条件を、対話で決める

このアプリにプロフィール画面はありません。ユーザーごとのページも、そのためのルートも無いので、どんな画面になるのかは何も決まっていません。その状態のまま「プロフィール画面が欲しい」を渡して、受け入れ条件が書けるところまで持っていきます。

この機能はこのセクション限りの題材で、このあとのセクションでも作りません。送る依頼はコードを書く手前で止めてあるので、ファイルは書き換わりません。

ターミナルで投稿アプリのフォルダ（14-1-3でCLAUDE.mdを作ったフォルダ）へ移動して、Claude Codeを起動します。

```bash
# 投稿アプリのフォルダで実行する
claude
```

### Step 1: 要望をそのまま渡す

決まっているのは、最初の2行だけです。あとの3行は、質問を向こうにさせるためのものです。

```text
このアプリに、プロフィール画面が欲しい。
ポストを読んだ人が、書いた人のことを少し分かるようにしたい。

決めないといけないことがあれば、先にこちらへ質問して。
いまのアプリを読んだうえで、このアプリで実際に分かれるところだけ聞いて。
作り方はそちらで決めて、コードはまだ書かないで。
```

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
あなた: （上の依頼を送る）
Claude Code: （users テーブルやタイムラインの画面を読んだうえで、誰のプロフィールを
              見られるのか、名前とメールアドレスのほかに何を出すのか、自己紹介文を
              足すのか、本人が書き換えられるようにするのか、タイムラインのどこから
              開くのか、といった問いを並べてくる）
```

途中で実装まで進み始めたときは、`Esc` で止めて「まだ実装しないで。質問だけ先に出して」と伝えてください。止めるのが遅れてファイルが書き換わってしまっても、まだコミットしていない変更なので `git restore .`（4-3-5）で元に戻せます。

**見るのは、返ってきた問いのほうです。** 自分で書いた2行が、どれだけ決め落としていたか。

### Step 2: 問いに答える

問いには、1つずつ答えます。答えは短くて構いません。「他人のプロフィールも見られる」「自己紹介文は足す」「本人が書き換えるのは今回作らない」。この演習ではあなたが発注者なので、答えの中身は自分で選んで構いません。

決めきれない問いが出てきたら、そこだけ投げ返します。

```text
アイコンの件、判断がつかない。選べる案を出して、それぞれの手間も書いて。
```

### Step 3: 受け入れ条件の形にまとめさせる

答え終わったら、決まったことを1つの形にそろえさせます。

```text
ここまで決めたことを、受け入れ条件にまとめて。
「〜すると、〜になる」の形で、ブラウザの操作で確かめられる文にして。
```

返ってきた行を、自分が答えた内容と突き合わせます。答えたはずの決めごとが落ちていたら、その行を足させます。13-2-2で書いたときと同じで、操作して合否が決まらない行（「プロフィールが見やすい」など）が混じっていたら、書き直させます。

ここで決めた条件は、どのファイルにも書かれません。Issueと設計書という残る形に起こすのは、14-2-1で条件を固めたリプライ機能のほうで、14-3-3でやります。

閉じる前に、次を確かめてください。確かめ終えたら `/exit` で閉じます。

- [ ] 自分が書いた2行に入っていなかった判断について、AIから問いが返ってきた
- [ ] 返ってきた問いに、すべて自分で答えた（決めきれないものは案を出させて選んだ）
- [ ] 受け入れ条件が「〜すると、〜になる」の形で3行以上そろっている
- [ ] ファイルは1つも書き換わっていない（ファイル編集時に出る差分の表示が、応答の中に無い）

---

## ✨ まとめ

- 決めるのはあなたで、決めるべきことを並べる仕事はAIに渡す。要望の文に、先に質問させる1行を足すだけで足りる。
- 返ってきた問いは、自分の決め落としの一覧として読む。全部に答えてから先へ進む。
- 決めきれない問いは、案を出させて選ぶ。選ぶところまでが自分の仕事。
- 受け入れ条件は、操作して合否が決まる行になるまで書き直させる。
- 作らせない用事（案出し・調べもの・コードの読み解き）は、文の形を整えずに投げてよい。実装を頼む段になったら、依頼の形に戻す。
