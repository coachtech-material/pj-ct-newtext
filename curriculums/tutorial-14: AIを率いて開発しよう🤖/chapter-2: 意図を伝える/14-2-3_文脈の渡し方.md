# 14-2-3: 文脈の渡し方

## 🎯 このセクションで学ぶこと

- `@` でファイルを名指しして、場所を文章で説明する手間を省けるようになる。
- 画面を撮ってそのまま貼り、見た目を言葉で書き起こさずに渡せるようになる。
- 手本になるファイルやページのURLを、読んでほしい場所として渡せるようになる。

---

## 導入

14-2-2では、要望から受け入れ条件までを文章のやり取りで固めました。14-2-1で挙げた「参照」（読んでほしい場所）のほうは、文章で説明するより、ファイルや画面をそのまま渡したほうが速く正確に届きます。開発フローの現在地は変わらず、Issue化 → 計画 → 実装とテスト → レビュー → UAT → PR の先頭です。

## ファイルを名指しする `@`

`@` は、Claude Codeの入力欄でファイルを名指しするための記号です。`@` に続けてパスが入っていると、AIは答える前にそのファイルを読みます。

読んでほしい場所は、パスさえ書いてあれば届きます。14-2-1の依頼文にあった `app/Policies/PostPolicy.php` の1行も、文章の中に書いただけで、そこを読ませていました。「app フォルダの中の Http の中の Controllers にある PostController.php」と場所を書き下す必要はありません。`@` を使うのは、そのパスを打ち間違えずに入れられるからです。

入力欄で `@` を打つと、そのあとにファイルパスの候補が出ます。途中まで打つと候補が絞り込まれるので、目的のファイルを選べばパスが入ります（2026年8月時点）。表示が違うときは `/help` と公式ドキュメントで確かめてください。

**`@` を打つと、ファイルパスの候補が出ます**

<img alt="14-2-3_1.png" src="">

使うのは、**触る場所がもう決まっているとき**です。決まっていないときは名指ししません。探させたほうが、こちらの思い込みで外すことがない分だけ確実です。

前例のあるものは、やり方を説明せずにそのファイルを渡します。「ここと同じやり方で」と書いて場所を指せば、そのファイルが手本になります。

手元に無いものは、URLで渡します。入力欄にページのURLを貼ると、AIはそのページを読みに行けます（2026年8月時点）。

## 画面を撮った画像

Claude Codeの入力欄には、画像も貼れます。撮った画面をそのまま渡すと、AIはそこに何が写っているかを読みます。

ファイルを渡しても、その画面がどう見えているかは渡りません。ブラウザに出ているのは、テンプレートに、データと見た目の指定が合わさった結果だからです。何がどう並んでいるかを言葉で書き起こせば、書いた側が見落としたものはそこで落ちます。

渡したい範囲を撮って、クリップボードに入れます。画面を撮るのはOS側の機能です。Macは `Control+Shift+Command+4`、Windowsは `Windows+Shift+S` を押すと、選んだ範囲がクリップボードに入ります（2026年8月時点）。この割り当てはOSの設定で変えられるので、押しても撮れないときは、お使いのOSのヘルプで「スクリーンショット」を調べてください。

貼り付け先は、Claude Codeの入力欄です。割り当てられているキーは使っているターミナルで変わり、`Ctrl+V`、iTerm2では `Cmd+V`、Windows（WSL）では `Alt+V` です（2026年8月時点）。WSLでは `Ctrl+V` も割り当てられていますが、ターミナル側が先に受け取ってしまうことがあるので、そのときは `Alt+V` を押してください。押しても反応が無いときや表示が違うときは、`/help` と公式ドキュメントで確かめてください。うまく渡せると、入力欄に `[Image #1]` のような印が入ります。これが、画像を受け取った合図です。印が出たら、続けて依頼の文章を打ちます。

印が出ないときは、その画像をアプリのフォルダに保存してから `@` で指してください。確かめ終えたら、保存した画像は消しておきます。

> ⚠️ **注意**: 14-1-5で引いた線は、画像にも同じように当てはまります。画面を撮るときは、本物のメールアドレスやパスワードが写り込んでいないかを見てください。この演習で画面に出るのは、練習用に用意された `usera@example.com` のアカウントだけです。

## 🏃 ファイルと画面で、同じタイムラインを渡す

同じタイムラインを、ファイルと画像の2通りで渡します。どちらの依頼もコードを止めてあるので、ファイルは書き換わりません。もし実装まで進み始めたら、`Esc` で止めてください。止めるのが遅れて書き換わってしまっても、まだコミットしていない変更なので `git restore .`（4-3-5）で元に戻せます。

画面を撮るので、アプリを動かしておきます。止まっている場合は、Docker Desktop（またはDocker Engine）を起動してから、このあと起動するClaude Codeとは別のターミナルで次を実行してください。

```bash
# 投稿アプリのフォルダで実行する
./vendor/bin/sail up -d
```

ターミナルで投稿アプリのフォルダ（14-1-3でCLAUDE.mdを作ったフォルダ）へ移動して、Claude Codeを起動します。

```bash
# 投稿アプリのフォルダで実行する
claude
```

### Step 1: `@` でファイルを渡す

入力欄で `@resources/` まで打ち、候補から `resources/views/posts/index.blade.php` を選びます。パスが入ったら、改行して依頼を続けます。

```text
@resources/views/posts/index.blade.php
このファイル、画面に何を並べてる？ コードはまだ書かないで。
```

返ってきた説明が、このファイルの中身に沿っているかを見ます。ポスト1件ごとに名前・時刻・トピック名・タイトル・本文が並ぶこと、自分のポストにだけ編集と削除が出ること。このあたりに触れていれば、ファイルが読まれています。

### Step 2: 画面を撮って渡す

ブラウザで `http://localhost` を開き、`usera@example.com` / `password` でログインして、タイムライン（`http://localhost/posts`）を表示します。

**この画面を撮ってから、Claude Codeへ貼り付けます**

<img alt="14-2-3_2.png" src="">

撮った画像を入力欄に貼り付け、印が入ったのを見てから、続けて次を打ちます。

```text
いま貼ったのが、このアプリのタイムラインです。
この画面に並んでいるものを、上から順に説明して。
コードはまだ書かないで。
```

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
あなた: （画像を貼って、上の依頼を送る）
Claude Code: （左上のアプリ名、右上の名前とメールアドレスとログアウト、
              「ホーム」の見出し、その下に並ぶポストのアバター・名前・時刻・
              トピック名・タイトル・本文、自分のポストにだけ出る編集と削除、
              といったものを順に挙げてくる）
```

返ってきた説明に、画面へ実際に出ているものが入っていれば、画像が読まれています。

閉じる前に、次を確かめてください。確かめ終えたら `/exit` で閉じます。

- [ ] `@` で指したファイルの中身に沿った説明が返ってきた
- [ ] 入力欄に、画像を受け取った印が入った（何度試しても入らないときは、画像をアプリのフォルダに保存して `@` で指す）
- [ ] 画像を渡した依頼への返答に、画面に出ている文言か、編集・削除の操作が出てくる
- [ ] ファイルは1つも書き換わっていない（ファイル編集時に出る差分の表示が、応答の中に無い）

## ✨ まとめ

- 触る場所が決まっているときは `@` で名指しする。決まっていないときは名指しせず、探させる。
- `@` を打たない場面でも、依頼文にパスを書けば、そこは読まれる。
- 手本があるものは、やり方を書かずにファイルで渡す。手元に無いものはURLで渡す。
- 画面の見た目は、言葉で書き起こさずに撮って貼る。印が入らないときは、ファイルに保存して渡す。
- 撮る範囲に、本物の認証情報が入っていないかを先に見る。
