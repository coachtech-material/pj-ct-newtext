# 14-1-3: CLAUDE.mdを作る

## 🎯 このセクションで学ぶこと

- 毎回のセッションで読まれる1枚として、`CLAUDE.md` の役割を言えるようになる。
- `/init` で叩き台を作り、中身を読んで自分の手で削れるようになる。
- 削った1枚をコミットして、プロジェクトの一部として残せるようになる。

---

## 導入

Claude Codeのセッションは、起動するたびにまっさらなところから始まります（14-1-2）。このアプリがDockerの中で動いていることも、テストの回し方も、次に起動したときには残っていません。毎回打ち直すか、1枚のファイルに置いておくか。この節では後者を用意します。

---

## 毎回読まれる1枚

`CLAUDE.md`（このプロジェクトの前提を書いておく、AIが毎回読むファイル）を、アプリのフォルダに1枚置きます。公式ドキュメントの説明では、Claude Codeは各セッションの開始時にこのファイルを読みます。あなたが「読んでください」と頼まなくても読まれます。

新しく入った人に渡す、機械の取扱説明書のようなものだと考えてください。電源の入れ方、押してはいけないボタン、変な音がしたときに見るところ。毎回口で説明する代わりに、機械の横に1枚貼っておきます。

ここに書いたことは、判断の材料として渡されるだけで、強制的な設定ではありません。これも公式ドキュメントに明記されています。書けば必ずそのとおりになる保証はなく、上がるのは確率です。同じ公式ドキュメントには、具体的で短い指示ほど従われやすい、長さは1ファイル200行未満を目安に、とも書かれています。

何を書いて何を書かないか、どう育てていくかは、Tutorial 15で扱います。この節でやるのは、叩き台を作って、明らかに要らないものを落として、記録するところまでです。

---

## 置き場所は1つだけ

置くのはアプリのフォルダのいちばん上で、ファイル名は `CLAUDE.md` です。すべて大文字で、拡張子は `.md` にします。

```text
post-app-practice/
├── CLAUDE.md      ← ここに置く
├── app/
├── routes/
└── tests/
```

`app/` や `docs/` のような下のフォルダには入れないでください。下のフォルダに置いた `CLAUDE.md` は、セッションの開始時には読まれず、Claude Codeがそのフォルダのファイルを読みに行ったときに、はじめて読み込まれます。毎回読ませたいものは、いちばん上の1枚に書きます。

Claude Codeを起動するときも、必ずアプリのフォルダに `cd` してから `claude` を打ちます（14-1-2でやったのと同じです）。

---

## 🏃 /init で叩き台を作る

`CLAUDE.md` はただのテキストファイルなので、1から自分で書けます。ただ、白紙から書き始めると手が止まります。Claude Codeには、いまのコードを読んで叩き台を書く `/init` というコマンドがあるので、まずこれを使います。出てきたものは、そのままでは使いません。読んで、削って、コミットするところまでが、この実践です。

### Step 1: 打つ前に、手元をきれいにしておく

`/init` は新しいファイルを作ります。気に入らなければ捨てて戻せるように、先に記録していない変更を無くしておきます。

```bash
# アプリのフォルダへ移動して、記録していない変更が無いかを見る
cd ~/laravel-practice/post-app-practice
git status
```

14-1-2の最後に `README.md` の変更をコミットしているので、変更は残っていないはずです。自分が触ったファイルが出てきた場合は、先にコミットしておいてください。

このフォルダが、この先の章でClaude Codeを起動する場所になります。

### Step 2: `/init` と打つ

Claude Codeを起動して、入力欄に1行打ちます。

```bash
# 投稿アプリのフォルダで実行する
claude
```

```text
/init
```

`/init` は、いまのコードを読んで回ります。ルート、コントローラー、モデル、テスト、設定ファイルと開いていくので、少し時間がかかります。読み終えると、フォルダのいちばん上に `CLAUDE.md` ができます。

> 💡 **TIP**: すでに `CLAUDE.md` がある状態でもう一度 `/init` を打っても、上書きはされません。改善の案が出るだけです（2026年8月時点）。

### Step 3: 全文を読んで、削る

できあがった `CLAUDE.md` をVS Codeで開き、上から最後まで読みます。

物差しは1つです。**消してもミスが増えないなら、消します。** `/init` が書くのは、いまのコードを見た結果なので、次のようなものが混ざります。

| 見つけたら | どうするか |
|:--|:--|
| このアプリで自分が打ったことのないコマンド | その行を消します |
| 教材で使ってきた形と違うコマンド | `php artisan` を `./vendor/bin/sail artisan` に置き換えます |
| いまだけの話（「いまここが足りない」「これから直す」） | 消します |

3種類とも書かれていないことがあります。無ければ、そのまま次へ進んでください。

最初の2行（`# CLAUDE.md` と、その下の説明文）はそのままで構いません。見出しが英語のままなのが気になるなら、日本語に書き換えても構いません。

### Step 4: コミットする

削り終えたら記録します。これも頼みます。

```text
CLAUDE.md をコミットしてください。
```

この1枚は、コードと同じくプロジェクトの一部です。だから一緒に記録します。効く相手は、次に起動したときの自分と、来月このアプリに戻ってきた自分です。このコミットはどの機能イシューにも属していないので、ブランチを切らず `main` のまま進めます。

ここまでで、次を確かめてください。

- [ ] `CLAUDE.md` が投稿アプリのフォルダのいちばん上にある
- [ ] 中身を全部読んで、自分が打ったことのないコマンドや、いまだけの話が残っていない
- [ ] `git log` に `CLAUDE.md` を追加したコミットがある

この1枚が毎回どれくらい場所を取っているかは、`/context` で見えます（14-5-2）。

## ✨ まとめ

- セッションは毎回まっさらから始まる。前提を書いた1枚を置いておくと、Claude Codeがセッションの始めに読む。
- 置き場所はアプリのフォルダのいちばん上、ファイル名は `CLAUDE.md`。下のフォルダに置いたものは、セッションの開始時には読まれない。
- 書いたことは判断の材料として渡るだけで、強制ではない。具体的で短いほど従われやすい。
- `/init` の出力はそのまま使わない。消してもミスが増えない行を落としてから、`main` にコミットする。
