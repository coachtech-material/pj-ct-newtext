## ⚙️ Claude Codeを入れる

**先に済ませておくこと**

Claude Codeへのログインには、Anthropicのアカウントを使います。まだ持っていない方は、ブラウザで `https://claude.ai` を開いてアカウントを作り、Proプランに切り替えてから先へ進んでください。申し込みの画面はサービス側のものなので、表示される案内に従って進めます。

インストールのコマンドは、MacでもWindows（WSL）でも同じです。

> ⚠️ **注意**: Windowsの方は、必ずWSL（Ubuntu）のターミナルで実行してください。PowerShellやコマンドプロンプトからは入れられません。

**手順1: `curl` があるか確かめる**

この手順はWindowsの方だけです。Macの方は手順2へ進んでください。

```bash
curl --version
```

バージョンが表示されれば入っています。`command not found` と出たときだけ、次を実行してください。

```bash
sudo apt update && sudo apt install curl
```

`sudo` を付けたコマンドを実行すると、パスワードを聞かれます。6-2-1でUbuntuを初めて起動したときに決めたパスワードを入力してください。入力しても画面には何も表示されませんが、ちゃんと打てています。

**手順2: インストールする**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

インターネットから取ってきた導入用のスクリプトを、そのまま実行しています。

> ⚠️ **注意**: 先頭に `sudo` を付けないでください。このインストーラーは、`sudo` を付けて実行されると自分で止まります（2026年8月時点）。ファイルの置き場所が変わってしまい、`claude` コマンドが動かなくなるためです。

**手順3: 入ったか確かめる**

```bash
claude --version
```

バージョンが表示されれば成功です。`command not found` と出た場合は、下の折りたたみを開いてください。

<details>
<summary>⚙️ `claude: command not found` と出たときの手当て（クリックで展開）</summary>

コマンドは入っているのに、ターミナルがその置き場所を探しに行っていない状態です。まず、探しに行く場所の一覧に入っているかを確かめます。

```bash
echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin"
```

`$PATH` は、ターミナルがコマンドを探しに行くフォルダの一覧です。`:` で区切られて並んでいるものを1行ずつに分け、その中にClaude Codeが置かれた `.local/bin` があるかを探しています。

何も表示されなければ、一覧に入っていません。次の2行を実行して追加します。

```bash
# Macの方（zsh）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

```bash
# Windowsの方（WSLのbash）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

1行目は、ターミナルが起動時に読み込む設定ファイルの末尾に、「探しに行く場所へ `.local/bin` を足す」という1行を書き込んでいます。9-1-2で `sail` の短縮名を登録したときと同じやり方です。2行目の `source` は、その設定ファイルをいますぐ読み直させる命令です。ターミナルを一度閉じて開き直しても、同じことになります。

そのあと、もう一度 `claude --version` を実行してください。

一覧に `.local/bin` が表示されているのに `claude` が動かないときは、まずターミナルを一度閉じて開き直してください。それでも動かない場合は、手順2のコマンドをもう一度実行して、最後に `✅ Installation complete!` と表示されることを確かめてください。

</details>

## ⚙️ Node.jsを入れる

Node.js（JavaScriptをパソコンの上で動かすための実行環境）を入れておきます。Chapter 4で、ブラウザの操作をAIに任せて受け入れ確認を回すときに、その道具がこの上で動きます。

版は指定せずに入れます。新しい版が出続けるので、指定して書くとすぐ古くなるためです。

**Macの方**

4-2-1で入れたHomebrewを使います。

```bash
brew install node
```

**Windows（WSL）の方**

Node.jsの配布元が用意している置き場所をUbuntuに登録してから、インストールします（2026年8月時点）。

```bash
curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt install -y nodejs
```

1行目でLTS（長期サポート版。長い期間、修正が提供される版）の置き場所を登録し、2行目でその置き場所から入れています。

**入ったか確かめる**

```bash
node --version
npm --version
```

どちらもバージョンが表示されれば入っています。表示されない場合や、手順が変わっている場合は、Node.jsの公式サイトのインストール手順を確認してください。

## ⚙️ GitHubを操作する道具を入れる

Tutorial 12では、イシューもプルリクエストもGitHubの画面から作りました。Tutorial 14では、この操作もAIに渡します。そのために `gh`（GitHub CLI）を入れておきます。ターミナルからGitHubを操作するための公式のコマンドで、Claude Codeはこれを使ってイシューを立てたりプルリクエストを作ったりします。

**Macの方**

```bash
brew install gh
```

**Windows（WSL）の方**

GitHubが配っているパッケージの置き場所をUbuntuに教えてから、インストールします。長いですが、まとめて1回貼り付けて実行して構いません。

```bash
(type -p wget >/dev/null || (sudo apt update && sudo apt install wget -y)) \
	&& sudo mkdir -p -m 755 /etc/apt/keyrings \
	&& out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
	&& cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
	&& sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
	&& sudo mkdir -p -m 755 /etc/apt/sources.list.d \
	&& echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
	&& sudo apt update \
	&& sudo apt install gh -y
```

> ⚠️ **注意**: `sudo apt install gh` だけでも入りますが、そちらは使わないでください。Ubuntuに最初から登録されているものは古く、GitHub側が「一部の機能が動かない」と案内しています（2026年8月時点）。上のコマンドは、GitHub公式の置き場所を登録してから入れています。

**GitHubにログインする**

```bash
gh auth login
```

いくつか質問されるので、次のように答えます。

| 聞かれること | 選ぶもの |
|:--|:--|
| どのアカウントか | `GitHub.com` |
| 通信の方式 | `SSH`（4-2-3で鍵を作っているため） |
| どの鍵を使うか | 4-2-3で作った鍵 |
| ログインの方法 | `Login with a web browser` |

最後にターミナルへ8桁のコードが出るので、それをコピーして、開いたブラウザの画面に貼り付けます。

**入ったか確かめる**

```bash
gh auth status
```

`Logged in to github.com account` と自分のアカウント名が表示されれば成功です。

## セッションという単位

ブラウザでAIサービスを使うとき、画面の左側に会話が1本ずつ並んでいます。同じ会話の中なら「さっきの件だけど」で通じますが、新しい会話を始めると、相手は前の話を何も知りません。

Claude Codeも同じです。`claude` を実行してから `/exit` で終えるまでのひとつづきのやり取りを**セッション**と呼びます。セッションの中では、前に話したことが残っています。「さっきのファイル」と書けば通じますし、一度説明した決めごとを繰り返す必要もありません。終えると、そのやり取りは次の起動には引き継がれず、また何も知らないところから始まります。

残るのは、そのあいだに書き換えられたファイルのほうです。1回のやり取りをどこで区切るかは、14-5-2で扱います。

> 💡 **TIP**: Tutorial 10で学んだログインのセッションとは別のものです。同じ言葉ですが、指しているものが違います。

## 基本の操作

| やりたいこと | 操作 |
|:--|:--|
| 起動する | プロジェクトのフォルダで `claude` |
| 終える | `/exit` と打つか、`Ctrl+D` を押す |
| 動いている途中で止める | `Esc` を押す（そこまでの作業は残ります） |
| 使えるコマンドを見る | `/help`。`/` を打つと候補の一覧が出ます |
| 前に打ったものを呼び出す | `↑` |
| 長い指示を改行しながら書く | 行の終わりで `\` を打ってから `Enter` |

入力欄では `Enter` が送信になるので、複数行を**自分で打つ**ときは `\` を打ってから `Enter` で改行します。

書いてあるものを**貼り付ける**ときは、`\` は要りません。改行の入った文をそのまま貼り付ければ、改行もそのまま入ります（2026年8月時点）。送信は、最後に `Enter` を1回押すだけです。この先の演習では、何行かある依頼をそのまま貼り付けて送る場面が何度も出てきます。

コマンドとキー操作の一覧は、14-1-7の早見表にまとめてあります。

## 詰まったら、Claude Codeに聞く

道具の導入や設定でうまくいかないときは、出ているものをそのままClaude Codeに渡して直させてください。

```text
このコマンドを実行したらエラーになった。原因を調べて直して。

（打ったコマンドと、出た文字をそのまま貼る）
```

入力欄の先頭に `!` を付けると、そのコマンドがその場で実行されて、結果が会話の中に入ります。貼り直さずに、続けて「これ直して」と打てます。

```text
!./vendor/bin/sail up -d
```

アプリのコードのほうで起きるエラーは、渡す前に自分で見ておくものがあります。そちらは14-5-1で扱います。

## 🏃 最初の1回を頼んでみる

最初の1回では、アプリのコードには触りません。`README.md` に1行足してもらいます。見てほしいのは、できあがるものよりも、**ファイルが書き換わってコミットされるまでの流れ**です。

### Step 1: 依頼を1つ出す

起動したまま、次の1行を打って `Enter` を押します。

```text
README.md の末尾に「このリポジトリは Tutorial 14 でも使います」という1行を足してください。
```

この大きさなら、頼み方を組み立てずにそのまま送って通ります。組み立てが要るのは、もっと大きいものを任せるときで、そこからがChapter 2の話です。

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
あなた: （上の1行を送る）
Claude Code: （README.md を読み、末尾に1行を足して、書き換えた箇所を差分で示す）
```

### Step 2: 何をしたのかを読む

ファイルを書き換えると、Claude Codeは「このファイルを、こう書き換えました」という内容を画面に出します。ここに出てくるのが差分（変更した箇所だけを、前とあとで見比べられる形にしたもの）です。並ぶのは、足された行と消された行だけです。

12-2-3「プルリクエストの作成とレビュー」でプルリクエストの「Files changed」を見たときと、見ているものは同じです。どこで止まり、どこで止まらないのかは14-1-5で扱います。

**書き換えた箇所が差分で出ている画面**

<img alt="14-1-2_4.png" src="">

ここに出るのは、書き換わった瞬間の1回だけです。何ファイルにも及ぶ依頼だと、そのあとの作業に流されて、さかのぼるのが面倒になります。まとめて読み直すときは、VS Codeの**ソース管理**ビューを開きます。左端に縦に並ぶアイコンのうち、枝分かれの形をしたものです。

「変更」のところに、まだコミットしていないファイルが並びます。ファイル名をクリックすると、左に前の中身、右にいまの中身を並べた画面が開きます。ターミナルに出る差分と、見ているものは同じです。いまは `README.md` が1つだけ並んでいるはずです。

**VS Codeのソース管理ビュー**

<img alt="14-1-2_5.png" src="">

AIが何を書いたのかを読む場所は、この2つです。書き換わった瞬間に見るならセッションの画面、あとからまとめて読むならソース管理ビュー。どちらも、まだコミットしていない状態を見ています。

### Step 3: コミットまで任せる

記録もその場で頼みます。

```text
いまの変更をコミットしてください。
```

書き換えたファイルが何だったかを覚えていなくても構いません。AIは自分が変えた場所を知っています。

ここまでで、次を確かめてください。確かめ終えたら `/exit` で閉じます。

- [ ] `http://localhost` でタイムラインが表示され、自分のポストにだけ「編集」「削除」が出る
- [ ] `claude --version`・`node --version`・`gh auth status` がどれも表示される
- [ ] `README.md` の末尾に依頼した1行が増えていて、`git log` にそのコミットがある

## ✨ まとめ

- 投稿アプリは `./vendor/bin/sail up -d` で起動し、`http://localhost` から開く。ログインするとタイムラインに移る。
- Claude CodeはMacでもWindows（WSL）でも `curl -fsSL https://claude.ai/install.sh | bash` で入る。`sudo` は付けない。
- `gh` を入れると、GitHubの操作もAIに任せられる。Node.jsは、Chapter 4でブラウザの確認をAIに回すときに使う。
- 起動から `/exit` までのひとつづきのやり取りがセッション。終えると、そのやり取りは次の起動には引き継がれない。
- ファイルが書き換わると差分が出る。プルリクエストの「Files changed」と同じ見方で読む。
- AIが書いたものを読む場所は2つ。その場ならセッションに出る差分、あとからならVS Codeのソース管理ビュー。
- 導入や設定で詰まったら、Claude Codeに渡して直させる。先頭に `!` を付けると、コマンドの結果ごと会話に入る。
