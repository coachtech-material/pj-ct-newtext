# 14-1-5: モードと権限

## 🎯 このセクションで学ぶこと

- autoモードで何が確認なしに動き、何が止まるのかを言えるようになる。
- `.env` のような渡したくないファイルを、設定で読ませないようにできるようになる。

## 導入

## 権限モード

Claude Codeには、承認をどれくらい求めるかを決めるモードがあります。いまどれで動いているかは、入力欄の下の表示で分かります（2026年8月時点）。

| 画面の表示 | 呼び方 | 承認なしで動く範囲 |
|:--|:--|:--|
| `⏸ manual mode on` | manualモード | 読むだけ |
| `⏵⏵ accept edits on` | accept editsモード | 読むことと、ファイルの書き換え |
| `⏸ plan mode on` | planモード | 読むだけ（計画を立てさせるときに使います。14-3-2） |
| `⏵⏵ auto mode on` | autoモード | ほぼすべて（下の検査を通ったもの） |

`Shift+Tab` を押すたびに、モードが順番に切り替わります。autoモードからは、1回目で `⏸ manual mode on` になり、そのあと `⏵⏵ accept edits on` → `⏸ plan mode on` → `⏵⏵ auto mode on` と一周します。

**入力欄の下に出ているモードの表示**

<img alt="14-1-5_1.png" src="">

この教材では **autoモードを標準**にします。2026年8月時点では、Proプランの新しいセッションはautoモードで始まります。自分で既定を変えている場合はその設定が優先されるので、`Shift+Tab` でautoモードに合わせてください。

### autoモードは何をしているのか

autoモードでは、**別の検査役のモデルが、実行前に1つずつ中身を見ています**。公式ドキュメントによると、次のものは止まります。

- あなたが頼んだ範囲を超えて広がるもの
- 見覚えのない相手（知らないサーバーなど）を対象にするもの
- AIが読み込んだ文章に誘導されて実行しようとしたもの

ファイルシステムの根元やホームを消す命令（`rm -rf /`・`rm -rf ~`）も、この検査役が判断します。AIに実行させようとすると既定で止まるものには、ほかにこんな例があります。取ってきてそのまま実行する形（`curl | bash`）、本番へのデプロイとマイグレーション、force push、`git reset --hard` や `git restore .` のように記録していない変更を捨てる操作。

> ⚠️ **注意**: 検査役が見るのは「依頼の範囲を超えていないか」であって、「そのコードが正しいか」ではありません。公式ドキュメントにも、autoモードは承認の回数を減らすもので、安全を保証するものではない、と書かれています。できたものを検証する仕事は残ります。

planモードでも同じ検査役が働きます。計画を立てている間、読むだけのコマンドはそのまま動き、それ以外は検査を通ったものが動きます。

## 手元の外へ出ていくもの

任せてよいかどうかで迷ったときの物差しは1つです。**その作業の結果が、自分の手元の中で終わるか。** 終わるなら、任せて構いません。書き換えたファイルも、実行したコマンドも、自分のパソコンの中にとどまっているうちは、いくらでもやり直せます。

手元の外へ出ていくものは、先に何が起きるのかを確かめてから進めます。よく挙がるのは、本番で動いているデータ、秘密の値（パスワードやAPIキーは、コミットしてGitHubへ送った時点で外に出ます）、外部への公開です。ここに挙げたのは例で、これで全部ではありません。Tutorial 14で触るのは、ほとんどが手元の中で終わる側です。

画面も同じ線の内側にあります。作業中の画面を撮って人に見せるときや、ログをコピーして貼るときは、本物のメールアドレスやパスワードが写っていないかを見てください。この教材で使う `usera@example.com` / `password` も、このプロジェクトの `.env` に入っている値も、練習用のものなので気にしなくて構いません。

## 渡したくないファイルを、設定で止める

先に事実を1つ確認します。Claude Codeは、起動したフォルダとその下にあるファイルを読めます。読むだけであれば、承認を求められません。この「読めるファイル」には `.env` も含まれます。

つまり、**`.env` を自動で避ける仕組みはありません**。AIが気を利かせて避けてくれる、とは考えないでください。

11-3-2「APIセキュリティのベストプラクティス」では、APIキーの扱いとして、環境変数に保存する、コードに書かない、Gitにコミットしない、を学びました。ここにもう1つ足します。**AIに読ませない**、です。

これは設定ファイルで指定できます。プロジェクトの `.claude/settings.json` に書きます。

**`.claude/settings.json`**

```json
{
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(.env.*)"
    ]
  }
}
```

`deny` は「これは禁止する」という指定です。`Read(.env)` と書くと、`.env` を読もうとしたところで機械が止めます。`.env.*` のほうは `.env.local` のような派生ファイルをまとめて指しています。

> ⚠️ **注意**: JSONのファイルにコメントを書かないでください。`//` を1行入れただけで設定として読めなくなり、しかも何の警告も出ません。書いたつもりの設定が丸ごと無視されます。

### どこまで効いて、どこから効かないか

この `deny` が止める範囲は、決まっています。

| 経路 | 止まるか |
|:--|:--|
| Claude Codeがファイルを読む・書き換える | 止まる |
| `cat .env` のように、Claude Codeがコマンドで読む | 止まる（`cat`・`head`・`tail`・`sed` を見ています） |
| スクリプト（PHPやPythonのファイル）が中で開く | **止まりません** |

3つ目が大事です。設定は万能ではないので、**秘密の値そのものを依頼の文章に貼り付けない**という自分の側の線は、設定とは別に持っておいてください。

> 💡 **TIP**: 設定ファイルにはこれ以外にも書けることがあり、`deny` の反対の「これは毎回聞かなくてよい」という指定もできます。使い分けはTutorial 15で扱います。

## 🏃 設定を書いて、止まることを確かめる

### Step 1: モードを確かめる

ターミナルで投稿アプリのフォルダ（14-1-3でCLAUDE.mdを作ったフォルダ）へ移動して、Claude Codeを起動します。

```bash
# 投稿アプリのフォルダで実行する
claude
```

入力欄の下の表示を見ます。`⏵⏵ auto mode on` になっていればそのままで構いません。違う表示なら、`Shift+Tab` を何回か押してautoモードに合わせてください。

### Step 2: 設定ファイルをAIに作らせる

上の内容をそのまま自分で書いてもよいのですが、せっかくなので頼みます。

```text
このプロジェクトの .claude/settings.json を作って、
.env と .env.local を読めないようにする設定を書いてください。
```

作るファイルは名指ししていますが、書き方は指定していません。JSONの書式はAIのほうが確実に知っています。

できあがったら中身を読んで、`permissions` の中に `deny` があり、`.env` が指定されていることを確かめます。

### Step 3: 止まることを確かめる

同じセッションで、次を頼みます。

```text
.env の中身を見せてください。
```

拒否されれば成功です。設定が効いていない場合は中身が表示されてしまうので、そのときはStep 2に戻って `.claude/settings.json` の書式を確かめてください（`//` でコメントを書いていないかも見てください）。

**`.env` を読もうとして止まった画面**

<img alt="14-1-5_2.png" src="">

### Step 4: 設定をコミットする

この設定はチームで共有するものなので、リポジトリに入れます。これも頼みます。

```text
.claude/settings.json をコミットしてください。
```

投げ終えたら、次を確かめてください。

- [ ] 入力欄の下に `⏵⏵ auto mode on` と表示されている
- [ ] `.claude/settings.json` に `Read(.env)` の `deny` が書かれている
- [ ] `.env` の中身を見せるよう頼んで、拒否された
- [ ] `git log` に、設定を追加したコミットが増えている

## 💡 モデルとエフォートと使用枠

Claude Codeを使い続けていると、しばらく依頼を受け付けなくなることがあります。プランに含まれる使用枠を使い切った状態で、時間を置くとまた使えるようになります。長い作業の途中でこうなったときは、そこまでの変更をコミットしてから、時間を置いて再開してください。

枠の減り方は、どのモデルでどれくらい深く考えさせるかで変わります。`/model` と打つと切り替えの画面が出て、左右キーでエフォート（考える深さ）も変えられます。軽い設定ほど、枠の減り方はゆるやかです。この教材は既定のままで進められるので、枠が足りないと感じたときだけ触ってください。

## ✨ まとめ

- `Shift+Tab` でモードが切り替わり、いまのモードは入力欄の下に出る。この教材はautoモードを標準にする。
- autoモードでは、別の検査役が実行前に中身を見ている。見ているのは依頼の範囲を超えていないかで、コードの正しさは見ていない。
- 任せてよいかの物差しは、その作業の結果が自分の手元の中で終わるか。本番のデータ・秘密の値・外部への公開は、先に確かめてから進める。
- `.claude/settings.json` の `deny` に `Read(.env)` を書くと、読み取りが止まる。`cat` のようなコマンド経由も止まる。
- スクリプトが中で開く経路までは止まらない。秘密の値を依頼文に貼らない線は、設定とは別に持つ。
