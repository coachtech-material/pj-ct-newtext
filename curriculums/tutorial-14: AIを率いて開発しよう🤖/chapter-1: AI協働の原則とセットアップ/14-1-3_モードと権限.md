# 14-1-3: モードと権限

## 🎯 このセクションで学ぶこと

- 権限モードを切り替えて、いまどのモードで動いているかを読めるようになる。
- `.env` のような渡したくないファイルを、設定で読ませないようにできるようになる。
- その設定がどこまで効いて、どこから効かないのかを言えるようになる。

---

## 導入：承認が続くと、読まずに通すようになる

Chapter 3で1機能をまるごと作らせると、ファイルの作成と書き換え、コマンドの実行で、承認を求められる場面が何十回と続きます。同じ形の確認が並べば、内容を読まずに通すだけのボタンになります。読まずに通した10回目に想定外のものが混ざっていても、気づけません。

かといって、承認の回数を根性で減らすことはできません。先に設定で、**機械に任せる部分と触らせない部分**を決めておきます。

---

## 権限モード

Claude Codeには、承認をどれくらい求めるかを決めるモードがあります。この教材で使うのは3つです。

| モード | 画面の表示 | 承認なしで動く範囲 |
|:--|:--|:--|
| Manual | `⏸ manual mode on` | 読むだけ |
| Plan | `⏸ plan mode on` | 読むだけ（書き換えはしない。計画を立てさせるときに使う） |
| Auto | `⏵⏵ auto mode on` | ほぼすべて（下記の検査を通ったもの） |

`Shift+Tab` を押すたびに、モードが順番に切り替わります。いまどれで動いているかは、入力欄の下の表示で分かります。

この教材では **Auto を標準**にします。2026年8月時点では、Proプランの新しいセッションはAutoで始まります。自分で既定を変えている場合はその設定が優先されるので、`Shift+Tab` でAutoに合わせてください。

### Autoモードは何をしているのか

Autoは、確認を素通りさせているのではありません。**別の検査役のモデルが、実行前に1つずつ中身を見ています**。次のものは止まります。

- あなたが頼んだ範囲を超えるもの
- 見覚えのない相手（知らないサーバーなど）を対象にするもの
- AIが読み込んだ文章に誘導されて実行しようとしたもの

`rm -rf /` のような、ホームディレクトリやファイルシステムの根元を消す命令も、この検査役が判断します。

> ⚠️ **注意**: 検査役が見るのは「依頼の範囲を超えていないか」であって、「そのコードが正しいか」ではありません。Autoにしても、できたものを検証する仕事は残ります。

Plan モードでも同じ検査役が働きます。計画を立てている間、読むだけのコマンドはそのまま動き、それ以外は検査を通ったものが動きます。

## 渡したくないファイルを、設定で止める

先に事実を1つ確認します。Claude Codeは、起動したフォルダとその下にあるファイルを読めます。読むだけであれば、承認を求められません。この「読めるファイル」には `.env` も含まれます。

つまり、**`.env` を自動で避ける仕組みはありません**。AIが気を利かせて避けてくれる、とは考えないでください。

11-3-2「APIセキュリティのベストプラクティス」では、APIキーの扱いとして、環境変数に保存する、コードに書かない、Gitにコミットしない、を学びました。ここにもう1つ足します。**AIに読ませない**、です。

これは設定ファイルで指定できます。プロジェクトの `.claude/settings.json` に書きます。

**`.claude/settings.json`**

```json
{
  "permissions": {
    "deny": [
      "Read(.env)",
      "Read(.env.*)"
    ]
  }
}
```

`deny` は「これは禁止する」という指定です。`Read(.env)` と書くと、`.env` を読もうとしたところで機械が止めます。`.env.*` のほうは `.env.local` のような派生ファイルをまとめて指しています。

> ⚠️ **注意**: JSONのファイルにコメントを書かないでください。`//` を1行入れただけで設定として読めなくなり、しかも何の警告も出ません。書いたつもりの設定が丸ごと無視されます。

### どこまで効いて、どこから効かないか

この `deny` が止める範囲は、決まっています。

| 経路 | 止まるか |
|:--|:--|
| Claude Codeがファイルを読む・書き換える | 止まる |
| `cat .env` のように、Claude Codeがコマンドで読む | 止まる（`cat`・`head`・`tail`・`sed` を見ています） |
| スクリプト（PHPやPythonのファイル）が中で開く | **止まりません** |

3つ目が大事です。設定は万能ではないので、**秘密の値そのものを依頼の文章に貼り付けない**という自分の側の線は、設定とは別に持っておいてください。

この演習で使うプロジェクトの `.env` に入っているのは、練習用のダミーの値だけです。気をつけるのは、本物の値を扱うプロジェクトに移ったときです。

> 💡 **TIP**: 設定ファイルにはこれ以外にも書けることがあり、`deny` の反対の「これは毎回聞かなくてよい」という指定もできます。使い分けはTutorial 15で扱います。

## 🏃 設定を書いて、止まることを確かめる

### Step 1: モードを確かめる

アプリのフォルダでClaude Codeを起動して、入力欄の下の表示を見ます。

```bash
# アプリのフォルダへ移動して起動する
cd ~/laravel-practice/post-app-practice
claude
```

`⏵⏵ auto mode on` になっていればそのままで構いません。違う表示なら、`Shift+Tab` を何回か押してAutoに合わせてください。

### Step 2: 設定ファイルをAIに作らせる

上の内容をそのまま自分で書いてもよいのですが、せっかくなので頼んでみます。

```text
このプロジェクトの .claude/settings.json を作って、
.env と .env.local を読めないようにする設定を書いてください。
```

> 💡 この依頼のポイントは、①作るファイルを名指ししている ②何を実現したいか（読めないようにする）だけを書いて、書き方を指定していない、の2点です。JSONの書式はAIのほうが確実に知っています。

できあがったら中身を読んで、`permissions` の中に `deny` があり、`.env` が指定されていることを確かめます。

### Step 3: 止まることを確かめる

同じセッションで、次を頼みます。

```text
.env の中身を見せてください。
```

拒否されれば成功です。設定が効いていない場合は中身が表示されてしまうので、その場合はStep 2に戻って `.claude/settings.json` の書式を確かめてください（`//` でコメントを書いていないかも見てください）。

### Step 4: 設定をコミットする

この設定はチームで共有するものなので、リポジトリに入れます。

```bash
# アプリのフォルダで実行する
git add .claude/settings.json
git commit -m "AIに.envを読ませない設定を追加"
```

投げ終えたら、次の3つを確かめてください。

- [ ] 入力欄の下に `⏵⏵ auto mode on` と表示されている
- [ ] `.claude/settings.json` に `Read(.env)` の `deny` が書かれている
- [ ] `.env` の中身を見せるよう頼んで、拒否された

## ✨ まとめ

- `Shift+Tab` でモードが切り替わり、いまのモードは入力欄の下に表示されます。この教材ではAutoを標準にします。
- Autoは確認を素通りさせているのではなく、別の検査役が実行前に中身を見ています。ただし見ているのは「依頼の範囲を超えていないか」で、コードの正しさではありません。
- Claude Codeは起動したフォルダの中を読めます。`.env` を自動で避ける仕組みはありません。
- `.claude/settings.json` の `deny` に `Read(.env)` を書くと、読み取りが止まります。`cat` のようなコマンド経由も止まります。
- スクリプトが中で開く経路までは止まりません。秘密の値を依頼文に貼らない、という自分の側の線は別に持ちます。
