## AIとの付き合い方

Tutorial 13まで、設計書は自分の手で作ってきました。ここから先は、**基本的にはコードを自分で書きません**。書くのはAIです。設計書のほうも、Chapter 2からはAIと一緒に作るようになります。あなたに残るのは2つで、**ゴールを決めること**と、**できたものを検証すること**。その間の作業は渡して構いません。

任せる範囲を狭めても、品質は上がりません。上がるのは、渡す情報が良いときと、確かめ方が決まっているときです。Tutorial 14で扱うのはその2つで、AIをどこまで信じるかという話はしません。

検証も、AIを疑うためのものではありません。誰が書いたコードでも、受け取る前に確かめます。テストを回すのは、目で読むより速いからです。

この Tutorial で身につけてほしいのは、**速さと量**です。1回の指示で1ファイル直すのと、1機能まるごと作らせるのとでは、同じ時間で出てくるものの大きさが変わります。手で書いても間に合う量しか出さないなら、AIを使う意味はほとんどありません。

量を出すと、Tutorial 13で作った設計書が効いてきます。何を作るかが決まっていないまま量を出せば、違うものが大量にできるだけです。設計書は、それを先に防ぐためにあります。

慎重になるのは、**取り返しがつかないもの**に触るときです。本番で動いているデータ、パスワードやAPIキー、外部への公開などが当たります。ここに挙げたのは例で、これで全部ではありません。迷ったら、**失敗したときに自分の手で元へ戻せるか**で判断してください。戻せるなら、任せて構いません。

## Claude Codeとは何か

Tutorial 13までAIに質問するとき使ったのは、ブラウザで開く対話型のサービスでした。読んで答えてもらうだけなら、それで足ります。

Claude Codeは役割が違います。自分のリポジトリのファイルを**直接読み書きし、コマンドも実行できる**道具です。コードを画面に貼り付けて、返ってきたものを自分でファイルに写す、という往復が要りません。設計書を渡して実装させるには、この直接さが必要です。この教材が道具をClaude Code 1つに絞るのは、これが理由です。

Claude Codeを使うにはProプランの契約が要ります（2026年8月時点）。無料のプランには含まれていません。受講料とは別に、月々の支払いが発生します。

**先に済ませておくこと**

Claude Codeへのログインには、Anthropicのアカウントを使います。まだ持っていない方は、ブラウザで `https://claude.ai` を開いてアカウントを作り、Proプランに切り替えてから先へ進んでください。申し込みの画面はサービス側のものなので、表示される案内に従って進めます。

> ⚠️ **注意**: このセクションの手順と画面の説明は、2026年8月時点のものです。表示が違うときは、Claude Codeの公式ドキュメントのインストール手順を確認してください。

## ⚙️ アプリを動く状態にする

Tutorial 13で作った `post-app-practice` を、ここからは実際に動かします。設計のときは読むだけでしたが、これからは書き換えて、ブラウザで確かめます。

> **📌 Dockerが起動していることを確認**
>
> 以下のコマンドを実行する前に、Docker Desktop（またはDocker Engine）が起動していることを確認してください。Tutorial 13ではDockerを使わなかったので、止まったままになっていることがあります。

> 🪟 **Windowsの方へ**: 以下のコマンドは **WSL（Ubuntu）のターミナル**で実行してください（PowerShellでは動きません）。

```bash
# アプリのフォルダへ移動する
cd ~/laravel-practice/post-app-practice

# パッケージをインストールする
docker run --rm \
    -u "$(id -u):$(id -g)" \
    -v "$(pwd):/var/www/html" \
    -w /var/www/html \
    laravelsail/php82-composer:latest \
    composer install

# 環境ファイルを作る
cp .env.example .env

# Sailを起動する
./vendor/bin/sail up -d

# アプリケーションキーを作る
./vendor/bin/sail artisan key:generate

# テーブルを作り、練習用データを入れる
./vendor/bin/sail artisan migrate --seed
```

> 💡 **MySQLの起動待ち**: 初回起動時は `migrate` で「Connection refused」と出ることがあります。MySQLの起動が終わっていないだけなので、少し待ってから同じコマンドをもう一度実行してください。

**動くことを確かめる**

1. ブラウザで `http://localhost` を開く
2. 「ログイン」をクリックする
3. `usera@example.com` / `password` でログインする
4. 投稿一覧が表示され、ユーザーAの投稿にだけ「編集」「削除」ボタンが出る

ボタンの出し分けは、`app/Policies/PostPolicy.php` が決めています。このあと何度も出てくるので、場所だけ覚えておいてください。

## ⚙️ Claude Codeを入れる

インストールのコマンドは、MacでもWindows（WSL）でも同じです。

> ⚠️ **注意**: Windowsの方は、必ずWSL（Ubuntu）のターミナルで実行してください。PowerShellやコマンドプロンプトからは入れられません。

**手順1: `curl` があるか確かめる**

この手順はWindowsの方だけです。Macの方は手順2へ進んでください。

```bash
curl --version
```

バージョンが表示されれば入っています。`command not found` と出たときだけ、次を実行してください。

```bash
sudo apt update && sudo apt install curl
```

`sudo` を付けたコマンドを実行すると、パスワードを聞かれます。6-2-1でUbuntuを初めて起動したときに決めたパスワードを入力してください。入力しても画面には何も表示されませんが、ちゃんと打てています。

**手順2: インストールする**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

インターネットから取ってきた導入用のスクリプトを、そのまま実行しています。

> ⚠️ **注意**: 先頭に `sudo` を付けないでください。このインストーラーは、`sudo` を付けて実行されると自分で止まります。ファイルの置き場所が変わってしまい、`claude` コマンドが動かなくなるためです。

**手順3: 入ったか確かめる**

```bash
claude --version
```

バージョンが表示されれば成功です。`command not found` と出た場合は、下の折りたたみを開いてください。

<details>
<summary>⚙️ `claude: command not found` と出たときの手当て（クリックで展開）</summary>

コマンドは入っているのに、ターミナルがその置き場所を探しに行っていない状態です。まず、探しに行く場所の一覧に入っているかを確かめます。

```bash
echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin"
```

`$PATH` は、ターミナルがコマンドを探しに行くフォルダの一覧です。`:` で区切られて並んでいるものを1行ずつに分け、その中にClaude Codeが置かれた `.local/bin` があるかを探しています。

何も表示されなければ、一覧に入っていません。次の2行を実行して追加します。

```bash
# Macの方（zsh）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

```bash
# Windowsの方（WSLのbash）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

1行目は、ターミナルが起動時に読み込む設定ファイルの末尾に、「探しに行く場所へ `.local/bin` を足す」という1行を書き込んでいます。9-1-2で `sail` の短縮名を登録したときと同じやり方です。2行目の `source` は、その設定ファイルをいますぐ読み直させる命令です。ターミナルを一度閉じて開き直しても、同じことになります。

そのあと、もう一度 `claude --version` を実行してください。

一覧に `.local/bin` が表示されているのに `claude` が動かないときは、まずターミナルを一度閉じて開き直してください。それでも動かない場合は、手順2のコマンドをもう一度実行して、最後に `✅ Installation complete!` と表示されることを確かめてください。

</details>

## ⚙️ GitHubを操作する道具を入れる

Tutorial 12では、イシューもプルリクエストもGitHubの画面から作りました。Tutorial 14では、この操作もAIに渡します。そのために `gh`（GitHub CLI）を入れておきます。ターミナルからGitHubを操作するための公式のコマンドで、Claude Codeはこれを使ってイシューを立てたりプルリクエストを作ったりします。

**Macの方**

4-2-1で入れたHomebrewを使います。

```bash
brew install gh
```

**Windows（WSL）の方**

GitHubが配っているパッケージの置き場所をUbuntuに教えてから、インストールします。長いですが、まとめて1回貼り付けて実行して構いません。

```bash
(type -p wget >/dev/null || (sudo apt update && sudo apt install wget -y)) \
	&& sudo mkdir -p -m 755 /etc/apt/keyrings \
	&& out=$(mktemp) && wget -nv -O$out https://cli.github.com/packages/githubcli-archive-keyring.gpg \
	&& cat $out | sudo tee /etc/apt/keyrings/githubcli-archive-keyring.gpg > /dev/null \
	&& sudo chmod go+r /etc/apt/keyrings/githubcli-archive-keyring.gpg \
	&& sudo mkdir -p -m 755 /etc/apt/sources.list.d \
	&& echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/githubcli-archive-keyring.gpg] https://cli.github.com/packages stable main" | sudo tee /etc/apt/sources.list.d/github-cli.list > /dev/null \
	&& sudo apt update \
	&& sudo apt install gh -y
```

> ⚠️ **注意**: `sudo apt install gh` だけでも入りますが、そちらは使わないでください。Ubuntuに最初から登録されているものは古く、GitHub側が「一部の機能が動かない」と案内しています（2026年8月時点）。上のコマンドは、GitHub公式の置き場所を登録してから入れています。

**GitHubにログインする**

```bash
gh auth login
```

いくつか質問されるので、次のように答えます。

| 聞かれること | 選ぶもの |
|:--|:--|
| どのアカウントか | `GitHub.com` |
| 通信の方式 | `SSH`（4-4-2で鍵を作っているため） |
| どの鍵を使うか | 4-4-2で作った鍵 |
| ログインの方法 | `Login with a web browser` |

最後にターミナルへ8桁のコードが出るので、それをコピーして、開いたブラウザの画面に貼り付けます。

**入ったか確かめる**

```bash
gh auth status
```

`Logged in to github.com account` と自分のアカウント名が表示されれば成功です。

## ⚙️ ログインする

**手順1: アプリのフォルダで起動する**

Claude Codeは、作業したいプロジェクトのフォルダで起動します。

```bash
# アプリのフォルダへ移動して起動する
cd ~/laravel-practice/post-app-practice
claude
```

**手順2: 最初に出る2つの確認に答える**

初めて使うときは、ログインと、このフォルダで作業してよいかの確認を続けて聞かれます。出てくる順番は前後することがあるので、出たほうから答えてください。

ログインでは、ブラウザが開いてサインインを求められます。用意したProプランのアカウントでサインインしてください。終わるとターミナルに `Login successful` と表示され、`Enter` を押すと先へ進みます。一度ログインすれば、次からは聞かれません。

フォルダの確認では、そのフォルダで作業してよいかを聞かれます。いま開いたのは自分のプロジェクトなので、「このフォルダで作業する」にあたる選択肢を選んでください。

> ⚠️ **Windowsの方へ**: WSLで使っていると、ブラウザでサインインしたあとにターミナルへ戻ってこず、代わりにブラウザにコードが表示されることがあります。そのコードをコピーして、ターミナルに出ている `Paste code here if prompted` のところへ貼り付けてください。

## セッションという単位

ブラウザでClaudeやChatGPT、Geminiを使うとき、画面の左側に会話が1本ずつ並んでいます。同じ会話の中なら「さっきの件だけど」で通じますが、新しい会話を始めると、相手は前の話を何も知りません。

Claude Codeも同じです。`claude` を実行してから `/exit` で終えるまでのひとつづきのやり取りが、あの会話1本にあたります。これを**セッション**と呼びます。

セッションの中では、前に話したことが残っています。「さっきのファイル」と書けば通じますし、一度説明した決めごとを繰り返す必要もありません。終えると、その記憶は無くなります。次に起動したときは、また何も知らないところから始まります。

ブラウザとの違いは、残るものです。ブラウザの会話は履歴として残り、あとから読み返せます。Claude Codeで残るのは、そのあいだに書き換えられたファイルのほうです。やり取り自体を読み返す方法もありますが、この教材では毎回新しく起動して進めます。

> 💡 **TIP**: Tutorial 10で学んだログインのセッションとは別のものです。同じ言葉ですが、指しているものが違います。

どこでセッションを区切るかは、渡す情報の量に効いてきます。この判断は14-2-2で扱います。

## 基本の操作

| やりたいこと | 操作 |
|:--|:--|
| 起動する | プロジェクトのフォルダで `claude` |
| 終える | `/exit` と打つか、`Ctrl+D` を押す |
| 使えるコマンドを見る | `/help`。`/` を打つと一覧が出て、`Tab` で補完、`↑` で履歴が呼び出せる |
| 動いている途中で止める | `Esc` を押す（そこまでの作業は残ります） |
| 長い指示を改行しながら書く | 行の終わりで `\` を打ってから `Enter` |

最後の改行だけ補足します。Claude Codeの入力欄では、`Enter` がそのまま送信になります。複数行の指示を書きたいときは、行の終わりに `\` を打ってから `Enter` を押すと、送信されずに改行できます。

## 🏃 最初の1回を頼んでみる

最初の1回では、アプリのコードには触りません。`README.md` に1行足してもらいます。見てほしいのは、できあがるものではなく、**ファイルが書き換わるまでの流れ**です。

### Step 1: 依頼を1つ出す

起動したまま、次の1行を打って `Enter` を押します。

```text
README.md の末尾に「このリポジトリは Tutorial 14 でも使います」という1行を足してください。
```

> 💡 このお願いのポイントは、①どのファイルなのかを名前で指していること ②足す文字列をそのまま書いていること、の2点です。どこを触るのかと、どうなったら終わりなのかが決まっているので、あとで確かめるのも簡単になります。文言をそのまま覚える必要はありません。

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
あなた: （上の1行を送る）
Claude Code: （README.md を読み、末尾に1行を足して、書き換えた箇所を差分で示す）
```

### Step 2: 何をしたのかを読む

ファイルを書き換えると、Claude Codeは「このファイルを、こう書き換えました」という内容を画面に出します。ここに出てくるのが差分（変更した箇所だけを、前とあとで見比べられる形にしたもの）です。並ぶのは、足された行と消された行だけです。

12-2-3「プルリクエストの作成とレビュー」でプルリクエストの「Files changed」を見たときと、見ているものは同じです。どこで止まり、どこで止まらないのかは14-1-3で扱います。

ここまでで、Claude Codeに依頼を出してファイルが書き換わるまでが1周しました。Chapter 1のセットアップとして、次の3つを確かめてください。

- [ ] `http://localhost` で投稿一覧が表示され、ユーザーAの投稿にだけ編集・削除ボタンが出る
- [ ] `claude --version` と `gh auth status` がどちらも正常に表示される
- [ ] `README.md` の末尾に、依頼した1行が増えている

## 💡 つまずいたときに見るところ

**依頼を受け付けなくなったとき**

Claude Codeを使い続けていると、しばらく依頼を受け付けなくなることがあります。壊れたわけではなく、時間を置くとまた使えるようになります。長い作業の途中でこうなったときは、そこまでの変更をコミットしてから、時間を置いて再開してください。

**見慣れないファイルやフォルダが増えていたとき**

Claude Codeを使い始めると、プロジェクトの中に設定のためのファイルやフォルダが作られることがあります。いまは触る必要はありません。中身はTutorial 15で扱います。
