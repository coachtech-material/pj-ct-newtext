# 14-1-2: Claude Codeのセットアップと基本操作

## 🎯 このセクションで学ぶこと

- 10-3-5で作った投稿管理のアプリを、Tutorial 14用のフォルダで動く状態に戻せるようになる。
- Claude Codeを自分のパソコンに入れて、起動と終了ができるようになる。

## 導入：ブラウザのAIと、何が違うのか

1-1-6「AIの活用法」では、質問する相手はブラウザで使える対話型のAIサービスならどれでもよく、無料プランで足りると案内しました。13-8-2で設計書を読ませたときも同じです。読んで答えてもらうだけなら、それで十分でした。

ここから使うClaude Codeは、役割が違います。自分のリポジトリのファイルを**直接読み書きし、コマンドも実行できる**道具です。コードをブラウザに貼り付けて、返ってきたものを自分でファイルに写す、という往復が要りません。設計書を渡して実装させるには、この直接さが必要です。この教材が道具をClaude Code 1つに絞るのは、これが理由です。

そのかわり、Claude Codeを使うにはProプランの契約が要ります（2026年8月時点）。無料のプランには含まれていません。受講料とは別に、月々の支払いが発生します。

**先に済ませておくこと**

Claude Codeへのログインには、Anthropicのアカウントを使います。まだ持っていない方は、ブラウザで `https://claude.ai` を開いてアカウントを作り、そのアカウントをProプランに切り替えてから先へ進んでください。申し込みの画面はサービス側のものなので、表示される案内に従って進めます。ここで用意したアカウントを、このセクションの「⚙️ ログインする」で使います。

> ⚠️ **注意**: このセクションの手順と画面の説明は、2026年8月時点のものです。ツールの画面やコマンドの名前は変わることがあります。書いてあるとおりの表示にならないときは、Claude Codeの公式ドキュメントのインストール手順を確認してください。

このセクションは、アプリを手元に戻す、Claude Codeを入れる、ログインする、基本の操作を覚える、1回頼んでみる、の順で進めます。アプリを先に用意するのは、Claude Codeがプロジェクトのフォルダで起動する道具だからです。

## ⚙️ アプリを手元に戻す

これから機能を足していく相手は、10-3-5「認可機能 - ハンズオン演習」で作った投稿管理のアプリです。GitHubに置いた `authorization-app-practice` を、Tutorial 14用のフォルダへ取り直します。

Tutorial 3で使ったVS Codeの統合ターミナル（`Ctrl + @`）を開いてください。Windowsの方は、6-2-1で切り替えたWSL（Ubuntu）のターミナルです。VS Codeの左下に「WSL: Ubuntu」と出ているかを確認しておきましょう。

**手順1: 自分のリポジトリをcloneする**

GitHubで `authorization-app-practice` のページを開き、緑色の「Code」ボタンからURLをコピーします。13-1-3でdesign-practiceをcloneしたときと同じく、**SSHのタブに切り替えてから**コピーしてください。「Code」ボタンを押した直後はHTTPSのタブが選ばれています。この先のChapter 3で、このリポジトリへpushするので、SSHを使います。

```bash
# laravel-practiceディレクトリに移動
cd ~/laravel-practice

# Tutorial 14用のディレクトリを作る
mkdir -p 14_hands-on
cd 14_hands-on

# 自分のリポジトリを、別のフォルダ名でcloneする
# URLの部分は、自分がコピーしたものに置き換える
git clone git@github.com:あなたのユーザー名/authorization-app-practice.git authorization-app-ai
```

最後に付けた `authorization-app-ai` が、手元にできるフォルダの名前です。GitHub側のリポジトリ名は `authorization-app-practice` のままで、変えるのは手元のフォルダ名だけです。10-3-5の提出物をそのまま残したまま作業できるように、名前を分けています。

**手順2: 動く状態に戻す**

cloneしただけでは、まだ動きません。`.env` と `vendor` はGitで管理していないので、cloneしたフォルダには入っていないからです。10-3-5と同じ手順で用意します。

## ⚙️ Claude Codeを入れる

インストールのコマンドは、MacでもWindows（WSL）でも同じです。

> ⚠️ **注意**: Windowsの方は、必ずWSL（Ubuntu）のターミナルで実行してください。PowerShellやコマンドプロンプトからは入れられません。

**手順1: `curl` があるか確かめる**

この手順はWindowsの方だけです。Macの方は手順2へ進んでください。

```bash
curl --version
```

バージョンが表示されれば入っています。`command not found` と出たときだけ、次を実行してください。

```bash
sudo apt update && sudo apt install curl
```

`sudo` を付けたコマンドを実行すると、パスワードを聞かれます。6-2-1でUbuntuを初めて起動したときに決めたパスワードを入力してください。入力しても画面には何も表示されませんが、ちゃんと打てています。

**手順2: インストールする**

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

インターネットから取ってきた導入用のスクリプトを、そのまま実行しています。Macの方は、4-2-1「Gitのインストール」でHomebrewを入れたときに同じ形を一度見ています。

> ⚠️ **注意**: 先頭に `sudo` を付けないでください。このインストーラーは、`sudo` を付けて実行されると自分で止まります。ファイルの置き場所が自分のホームディレクトリではなくなり、`claude` コマンドが動かなくなるためです。

**手順3: 入ったか確かめる**

```bash
claude --version
```

バージョンが表示されれば成功です。`command not found` と出た場合は、下の折りたたみを開いてください。

もう少し詳しく確かめたいときは、次のコマンドも使えます。

```bash
claude doctor
```

インストールの状態が一覧で表示されます。途中に `No installation issues found.` という行が出れば問題ありません。見慣れない項目も並びますが、いまは気にしなくて大丈夫です。

<details>
<summary>⚙️ `claude: command not found` と出たときの手当て（クリックで展開）</summary>

コマンドは入っているのに、ターミナルがその置き場所を探しに行っていない状態です。まず、探しに行く場所の一覧に入っているかを確かめます。

```bash
echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin"
```

`$PATH` は、ターミナルがコマンドを探しに行くフォルダの一覧です。`:` で区切られて並んでいるものを1行ずつに分け、その中にClaude Codeが置かれた `.local/bin` があるかを探しています。

何も表示されなければ、一覧に入っていません。次の2行を実行して追加します。

```bash
# Macの方（zsh）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc
```

```bash
# Windowsの方（WSLのbash）
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

1行目は、ターミナルが起動時に読み込む設定ファイルの末尾に、「探しに行く場所へ `.local/bin` を足す」という1行を書き込んでいます。9-1-2で `sail` の短縮名を登録したときと同じやり方です。2行目の `source` は、その設定ファイルをいますぐ読み直させる命令です。ターミナルを一度閉じて開き直しても、同じことになります。

そのあと、もう一度 `claude --version` を実行してください。

一覧に `.local/bin` が表示されているのに `claude` が動かないときは、まずターミナルを一度閉じて開き直してください。それでも動かない場合は、インストールそのものが終わっていない可能性があります。手順2のコマンドをもう一度実行して、最後に `✅ Installation complete!` と表示されることを確かめてください。

</details>

## ⚙️ ログインする

**手順1: アプリのフォルダで起動する**

Claude Codeは、作業したいプロジェクトのフォルダで起動します。

```bash
# アプリのフォルダへ移動して起動する
cd ~/laravel-practice/14_hands-on/authorization-app-ai
claude
```

**手順2: 最初に出る2つの確認に答える**

初めて使うときは、2つのことを続けて聞かれます。ログインと、このフォルダで作業してよいかの確認です。出てくる順番は前後することがあるので、出たほうから答えてください。

ログインでは、ブラウザが開いてサインインを求められます。導入で用意したProプランのアカウントでサインインしてください。終わるとターミナルに `Login successful` と表示され、`Enter` を押すと先へ進みます。一度ログインすれば、次からは聞かれません。

フォルダの確認では、そのフォルダで作業してよいかを聞かれます。いま開いたのは自分のプロジェクトなので、「このフォルダで作業する」にあたる選択肢を選んでください。何を許可し、何を許可しないかという判断そのものは、14-1-4で扱います。

> ⚠️ **Windowsの方へ**: WSLで使っていると、ブラウザでサインインしたあとにターミナルへ戻ってこず、代わりにブラウザにコードが表示されることがあります。そのコードをコピーして、ターミナルに出ている `Paste code here if prompted` のところへ貼り付けてください。

> 💡 **TIP**: Claude Codeには、使った分だけ支払うAPIキーで使う方法もあります。この教材では、Proプランのアカウントでログインする方法を使います。

ここまで確認できたら、Claude Codeは起動したままにしておいて構いません。このあとの 🏃 でそのまま使います。

## セッションという単位

`claude` を実行してから終えるまでの、ひとつづきのやり取りを、セッション（Claude Codeを起動してから終えるまでの、ひとつづきのやり取り）と呼びます。Tutorial 10で学んだログインのセッションとは別のものです。同じ言葉ですが、指しているものが違います。

セッションの中では、前に話したことが残っています。「さっきのファイル」と書けば通じますし、一度説明した決めごとを繰り返す必要もありません。逆に、終えるとその記憶は無くなります。次に起動したときは、また何も知らないところから始まります。

ですから、どこでセッションを区切るかは、この先で扱う判断のひとつになります（14-2-2）。ここでは、起動から終了までがひと区切り、とだけ覚えておいてください。

## 基本の操作

このセクションで使う操作は、次の5つだけです。

| やりたいこと | 操作 |
|:--|:--|
| 起動する | プロジェクトのフォルダで `claude` |
| 終える | `/exit` と打つか、`Ctrl+D` を押す |
| 使えるコマンドを見る | `/help`。`/` を打つと一覧が出て、`Tab` で補完、`↑` で履歴が呼び出せる |
| 動いている途中で止める | `Esc` を押す（そこまでの作業は残ります） |
| 長い指示を改行しながら書く | 行の終わりで `\` を打ってから `Enter` |

最後の改行だけ、補足します。Claude Codeの入力欄では、`Enter` がそのまま送信になります。複数行の指示を書きたいときは、行の終わりに `\` を打ってから `Enter` を押すと、送信されずに改行できます。

## 🏃 最初の1回を頼んでみる

> 🔥 ここからは、AIに実装を任せて構いません。ただし「任せる」と「丸投げ」は違います。何を作るかは設計書で自分が決め、出てきたものはテスト・動作確認・コードレビューで自分が検証します。品質の責任は、AIではなくあなたが握ります。

最初の1回では、アプリのコードには触りません。`README.md` に1行足してもらいます。見てほしいのは、できあがるものではなく、**ファイルが書き換わるまでの流れ**です。

### Step 1: 起動しているか確かめる

さきほど起動したままなら、そのまま次へ進んでください。`/exit` で終えていた場合や、ターミナルを閉じてしまった場合は、もう一度起動します。

```bash
# アプリのフォルダへ移動して起動する
cd ~/laravel-practice/14_hands-on/authorization-app-ai
claude
```

### Step 2: 依頼を1つ出す

次の1行を打って、`Enter` を押します。

```text
README.md の末尾に「このリポジトリは Tutorial 14 でも使います」という1行を足してください。
```

> 💡 このお願いのポイントは、①どのファイルなのかを名前で指していること ②足す文字列をそのまま書いていること、の2点です。どこを触るのかと、どうなったら終わりなのかが決まっているので、あとで確かめるのも簡単になります。文言をそのまま覚える必要はありません。

このあとは、次のような流れになります。

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
あなた: （上の1行を送る）
Claude Code: （README.md を読み、末尾に1行を足す変更を示して、進めてよいかを尋ねてくる）
あなた: （示された内容を読んで、頼んだとおりなら承認する）
Claude Code: （README.md を書き換え、何をしたかを短く報告する）
```

### Step 3: 何をするつもりかを読む

ファイルを書き換える前に、Claude Codeは「このファイルを、こう書き換えます」という内容を画面に出して、進めてよいかを聞いてきます。ここに出てくるのが差分（変更した箇所だけを、前とあとで見比べられる形にしたもの）です。ファイル全体ではなく、足される行と消される行だけが並びます。

12-2-3「プルリクエストの作成とレビュー」でプルリクエストの「Files changed」を見たときと、見ているものは同じです。違うのは、まだファイルが書き換わっていない点です。あなたが承認するまで、`README.md` は元のまま置かれています。

### Step 4: 承認する

差分を読んで、頼んだとおりなら承認します。承認の選択肢は複数出ます。その中には「今後は聞かない」にあたるものもありますが、ここでは選ばないでください。**この1回だけ許可する**選択肢を選びます。選択肢の意味と選び分けは、14-1-4でまとめて扱います。

### Step 5: 自分の目で確かめて、終える

VS Codeで `README.md` を開き、末尾に1行増えているかを確認します。確認できたら、`/exit` と打ってセッションを終えます。

このセクションが終わった時点で、次の3つを確かめられれば大丈夫です。

- [ ] `http://localhost` で投稿一覧が表示され、ユーザーAの投稿にだけ編集・削除ボタンが出る
- [ ] `claude --version` でバージョンが表示され、アプリのフォルダで `claude` が起動する
- [ ] `README.md` の末尾に、依頼した1行が増えている

## 💡 つまずいたときに見るところ

**依頼を受け付けなくなったとき**

Claude Codeを使い続けていると、しばらく依頼を受け付けなくなることがあります。壊れたわけではなく、時間を置くとまた使えるようになります。長い作業の途中でこうなったときは、そこまでの変更をコミットしてから、時間を置いて再開してください。Tutorial 14の後半は1回のセッションが長くなるので、区切りごとにコミットしておくと安心です。

**見慣れないファイルやフォルダが増えていたとき**

Claude Codeを使い始めると、プロジェクトの中に設定のためのファイルやフォルダが作られることがあります。いまは触る必要はありません。これらの意味は、この先のTutorialで扱います。
