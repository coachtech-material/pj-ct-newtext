# 14-3-3: 設計から実装まで - AI演習

## 📌 この演習について

Chapter 2で決めたコメント機能を、ここで作り切ります。イシューと `docs/comment.md` は用意できているので、残っているのは、計画を承認して走らせ、出てきたものを受け取り、プルリクエストを開くところまでです。

1回の依頼で出てくるものが、ここまでで最も大きくなります。1ファイルの書き換えではなく、機能ひとまとまりです。

---

## 🎯 演習課題

### 📋 課題

**目的**

`docs/comment.md` に書いたとおりに、投稿へのコメント機能を作ります。

**変えないもの**

- 投稿の一覧・編集・削除の動き
- `routes/web.php` にいまある4本のルート
- `app/Policies/PostPolicy.php`

**受け入れ条件**

`docs/comment.md` の受け入れ条件が、ブラウザで上から順に確かめられる状態です。受け入れ条件には、次のような行が並んでいるはずです。文言が自分のものと違っていたら、そちらに読み替えてください。

- 投稿一覧から投稿を開くと、投稿詳細画面にその投稿とコメントの一覧が出る
- 本文を入れて送ると、コメントが一覧に増える
- 自分が書いたコメントには「削除」が出て、押すと一覧から消える
- 他人が書いたコメントには「削除」が出ない

最後の1行は、`userb@example.com` でログインし直さないと確かめられません。アカウントを行き来しての確認はChapter 4でやるので、この演習で自分の目で見るのは前の3行までにしてください。

**渡さないもの**

どのファイルを作るか、クラスをどう名づけるか、判定をどこに置くか。ここはAIが決めます。決まったものが設計書と合っているかどうかを、あなたが受け取りで見ます。

テストは実装と一緒に書かせます。回すのはChapter 4なので、ここでは書かれているところまでを見ます。プルリクエストも、開いたままにしておいてください。

### ✏️ 進め方タスク

1. 【自分】アプリを動かして、Claude Codeをプランモードで起動する
2. 【自分⇄AI】設計書を渡して計画を出させ、読んで、引っかかったら立て直させる
3. 【自分】計画を承認する
4. 【AI】実装・テスト・コミット・プルリクエストの作成まで走らせる
5. 【自分】出てきた差分を、3段の順で受け取る
6. 【自分⇄AI】引っかかったところを直させて、pushさせる

### ✅ 完成チェックリスト

- [ ] `feature/comment` ブランチで作業していて、`main` に直接コミットしていない
- [ ] `docs/comment.md` に書いていないテーブル・カラム・画面が増えていない
- [ ] `composer.json` が変わっていない
- [ ] 投稿の一覧・編集・削除が、以前と同じように動く
- [ ] 受け入れ条件の前の3行を、ブラウザで順に確かめた
- [ ] `tests/Feature/` に、受け入れ条件に対応するテストが書かれている
- [ ] プルリクエストが開いていて、本文に `Closes #1` が入っている

## 🏃 実践：一緒に進めてみましょう

### 📝 ステップバイステップ

#### Step 1: アプリとイシューを確かめる

```bash
# アプリのフォルダへ移動して、起動しておく
cd ~/laravel-practice/post-app-practice
./vendor/bin/sail up -d
```

イシューの中身は、ターミナルからも読めます。

```bash
gh issue view 1
```

`1` は自分のイシューの番号に置き換えます。表示された本文で、この機能で何ができるようになるかを読み直してください。完成の判定に使う受け入れ条件は、`docs/comment.md` のほうにあります。

#### Step 2: 計画を出させる

Claude Codeを起動し、`Shift+Tab` で `⏸ plan mode on` に合わせてから依頼を送ります。

```bash
claude
```

依頼文は自分で組み立ててください。材料は、📋 課題に書いてあるものと、コミットとプルリクエストの作成まで頼むことです。プルリクエストの本文に `Closes #1` を入れるところまで、依頼に書いておいてください。組み立てた形の例は14-3-1に載せてあります。

#### Step 3: 計画を読んで、承認する

3つの観点で読みます（14-3-1）。

- 触るファイルの一覧が、思っていたものと合っているか
- 設計書に無いものが入っていないか
- 順番が通っているか

引っかかったら、設計書のどこと食い違っているかを名指しして、立て直させます。納得できたら、そのまま最後まで進めさせる選択肢を選びます。

#### Step 4: 走り終わるまで待つ

> 💡 **出力例について**: AIの応答は毎回変わります。以下はあくまで一例です。文言が違っても、チェックリストの項目を満たしていれば問題ありません。

```text
あなた: （計画を承認する）
Claude Code: （ブランチを切り、マイグレーションとモデルを作り、コントローラーとルートと画面を書き、
              テストを書き、コミットして、gh pr create でプルリクエストを出す）
```

途中で質問が来たら答えます。エラーが出ても、AI自身が直しながら進むので、そのまま続けさせて構いません。何度やっても同じところで止まるときの手当ては、14-4-3で扱います。

#### Step 5: 受け取る

```bash
# 変わったファイルの名前だけを見る
gh pr diff --name-only

# 差分の中身をまとめて見る
gh pr diff
```

14-3-2の3段の順に読みます。設計書と突き合わせ、触っていないはずの4か所を見て、それから中身を読みます。

ブラウザでも確かめます。`http://localhost/posts` を開き、受け入れ条件の前の3行を上から順に試してください。ログインは `usera@example.com` / `password` です。

「テーブルが見つからない」というエラー画面が出たら、データベースへの反映が抜けています。

```bash
./vendor/bin/sail artisan migrate
```

#### Step 6: 直させて、pushさせる

引っかかったところがあれば、名指しで直させます（14-3-2）。直したあとのコミットとpushも、同じ依頼の中で頼んで構いません。

```text
（直してほしいところを名指しする）
直したらコミットして、プルリクエストのブランチに push してください。
```

引っかかるところが1つも無ければ、このStepは飛ばして構いません。

## 📖 進行例

> 💡 **進行例について**: AIとの開発は毎回違う流れになります。ここに示すのは一つの進行例です。あなたの画面と違っていても、チェックリストを満たしていれば正解です。

**1. 計画を頼む**

```text
@docs/comment.md を読んで、この設計書のとおりにコメント機能を実装する計画を立ててください。

- 作業は feature/comment ブランチで進めてください
- 設計書の受け入れ条件が、ブラウザで上から順に確かめられる状態を完成とします
- 受け入れ条件に対応するテストも、実装と一緒に書いてください
- 終わったらコミットして、gh pr create でプルリクエストを出してください
- プルリクエストの本文の最後に、Closes #1 の1行を入れてください
```

**2. 計画が返ってくる**

```text
Claude Code: （routes/web.php・PostController・Post モデル・投稿一覧の画面を読んだうえで、
              触るファイルの一覧と、作る順番を書いた計画を出す。
              そのあとに、どう進めるかを尋ねてくる）
```

**3. 1か所を指摘して、立て直させる**

一覧の中に、コメントを編集する画面が入っていました。設計書に入れていないものです。

```text
計画にコメントの編集画面が入っていますが、docs/comment.md にコメントの編集は入れていません。
そこは外して、計画を立て直してください。
```

立て直した計画からその画面が消えたので、承認しました。

**4. 走り終わる**

しばらく待つと、コミットが3つ積まれ、プルリクエストが1本できていました。途中で「コメントを送ったあと、どの画面へ戻しますか」と1度聞かれました。`docs/comment.md` に書いていなかったので、投稿詳細画面へ戻すと決めて、設計書に書き足してから答えました。

**5. 受け取る**

`gh pr diff --name-only` の一覧に、`composer.json` は出ていませんでした。`routes/web.php` には投稿詳細とコメントのルートが足されていて、いままでの4本には `-` の行が付いていません。

中身では1か所引っかかりました。投稿詳細画面にコメントを渡しているところに `with()` が付いていないのに、画面ではコメントごとに `{{ $comment->user->name }}` を出していました。

**6. 直させて、pushさせる**

```text
投稿詳細画面にコメントを渡しているところで、コメントごとに書いた人の名前を出しているのに
with() が付いていません。PostController::index() と同じ形にそろえてください。
直したらコミットして、プルリクエストのブランチに push してください。
```

出てきた差分は1行でした。プルリクエストは開いたままにして、Chapter 4へ進みます。

<details>
<summary>📖 参考実装（自分の差分を読み終えてから開いてください）</summary>

判定を書いた1メソッドだけ載せます。あなたのAIが書いたコードは、これとは違う形になっているはずです。同じでなければいけないものではありません。

```php
// app/Policies/CommentPolicy.php
public function delete(User $user, Comment $comment): bool
{
    return $user->id === $comment->user_id;
}
```

いま操作している人のIDと、コメントに記録されている投稿者のIDを見比べています。配られたときから入っている `app/Policies/PostPolicy.php` の `update` と、同じ形です。

見比べるときは、行が同じかどうかよりも、この判定がどこか1か所に書かれているかを見てください（14-3-2）。コントローラーの中に同じ条件が直接書かれていても、画面の上での動きは変わりません。

</details>
