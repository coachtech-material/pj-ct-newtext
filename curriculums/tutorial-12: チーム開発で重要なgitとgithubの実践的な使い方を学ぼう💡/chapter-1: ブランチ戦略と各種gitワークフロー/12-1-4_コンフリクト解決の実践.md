# 12-1-4: コンフリクト解決の実践

## 🎯 このセクションで学ぶこと

- コンフリクト（競合）が発生する原因を理解する
- コンフリクトを解決する方法を学ぶ
- 実践的な演習を通じて、コンフリクト解決の流れを体験する

---

## 導入：コンフリクトとは何か？

### コンフリクトを理解するための例え

コンフリクトは、**2人が同時に同じ文書の同じ箇所を編集しようとした状態**です。

例えば、GoogleドキュメントやWordで共同編集をしているとき、同じ行を2人が同時に編集すると、どちらの変更を採用すべきかわからなくなります。Gitでも同じことが起こります。

**コンフリクト（conflict）とは、同じファイルの同じ行を、異なるブランチで変更した場合に発生する競合**です。

---

### コンフリクトが発生する状況

例えば、以下のような状況でコンフリクトが発生します。

```
時間の流れ →

main     ●───●───●  「Hello PHP」に変更
              │
              │
feature       ●───●  「Hello Laravel」に変更
              
              ↓ マージしようとすると...
              
         コンフリクト発生！
         「どちらを採用すべき？」
```

この場合、Gitは**どちらの変更を採用すべきか判断できない**ため、コンフリクトが発生します。

---

### コンフリクトは怖くない

> 💡 **初心者へのアドバイス**: コンフリクトは「エラー」ではなく、「確認が必要な状態」です。Gitが「どちらの変更を採用すべきか教えてください」と聞いているだけです。落ち着いて対処すれば、必ず解決できます。

---

## 詳細解説

### 🔍 コンフリクトが発生する仕組み

**コンフリクトが発生する条件**

| 条件 | 説明 |
|:---|:---|
| 同じファイル | 異なるファイルを編集した場合は、コンフリクトは発生しない |
| 同じ行（または近い行） | 離れた行を編集した場合は、Gitが自動でマージできる |
| 異なるブランチ | 同じブランチ内では、コンフリクトは発生しない |

**コンフリクトが発生しない例**

```
main:     Aさんがファイルの1行目を編集
feature:  Bさんがファイルの10行目を編集
→ Gitが自動でマージできる（コンフリクトなし）
```

**コンフリクトが発生する例**

```
main:     Aさんがファイルの1行目を編集
feature:  Bさんがファイルの1行目を編集
→ Gitが判断できない（コンフリクト発生）
```

---

### 🔍 コンフリクトマーカーの読み方

コンフリクトが発生すると、Gitはファイルに**コンフリクトマーカー**を挿入します。

```
<<<<<<< HEAD
Hello PHP
=======
Hello Laravel
>>>>>>> feature/update-greeting
```

**コンフリクトマーカーの意味**

| マーカー | 説明 |
|:---|:---|
| `<<<<<<< HEAD` | 現在のブランチ（マージ先）の変更の開始 |
| `=======` | 2つの変更の区切り線 |
| `>>>>>>> feature/update-greeting` | マージ元のブランチの変更の終了 |

**図解**

```
<<<<<<< HEAD           ← 現在のブランチ（main）の変更開始
Hello PHP              ← mainブランチでの変更内容
=======                ← 区切り線
Hello Laravel          ← featureブランチでの変更内容
>>>>>>> feature/...    ← マージ元ブランチの変更終了
```

## 🚀 実践例1: コンフリクトの発生と解決

### ステップ1: `main`ブランチで`file.txt`を作成

```bash
git switch main
echo "Hello World" > file.txt
git add file.txt
git commit -m "Add file.txt"
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git switch main` | `main`ブランチに切り替えます |
| `echo "Hello World" > file.txt` | `file.txt`に「Hello World」を書き込みます（上書き） |
| `git add file.txt` | `file.txt`をステージングエリアに追加します |
| `git commit -m "Add file.txt"` | コミットを作成します |

**構文解説: `echo "文字列" > ファイル名`**

```bash
echo "文字列" > ファイル名
```

| 記号 | 説明 |
|:---|:---|
| `>` | ファイルを上書きします（既存の内容は消えます） |
| `>>` | ファイルに追記します（既存の内容の後に追加） |

---

### ステップ2: `feature`ブランチを作成

```bash
git switch -c feature/update-greeting
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git switch -c feature/update-greeting` | 新しいブランチを作成して切り替えます |

---

### ステップ3: `feature`ブランチで`file.txt`を変更

```bash
echo "Hello Laravel" > file.txt
git add file.txt
git commit -m "Update greeting to Laravel"
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `echo "Hello Laravel" > file.txt` | `file.txt`の内容を「Hello Laravel」に変更します |
| `git add file.txt` | 変更をステージングエリアに追加します |
| `git commit -m "Update greeting to Laravel"` | コミットを作成します |

---

### ステップ4: `main`ブランチに切り替えて、`file.txt`を変更

```bash
git switch main
echo "Hello PHP" > file.txt
git add file.txt
git commit -m "Update greeting to PHP"
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git switch main` | `main`ブランチに切り替えます |
| `echo "Hello PHP" > file.txt` | `file.txt`の内容を「Hello PHP」に変更します |
| `git add file.txt` | 変更をステージングエリアに追加します |
| `git commit -m "Update greeting to PHP"` | コミットを作成します |

**この時点でのブランチの状態**

```
main:     file.txt = "Hello PHP"
feature:  file.txt = "Hello Laravel"
```

両方のブランチで、同じファイルの同じ行を変更しています。

---

### ステップ5: `feature`ブランチをマージ

```bash
git merge feature/update-greeting
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git merge feature/update-greeting` | `feature/update-greeting`ブランチを現在のブランチ（`main`）にマージします |

**実行結果**

```
Auto-merging file.txt
CONFLICT (content): Merge conflict in file.txt
Automatic merge failed; fix conflicts and then commit the result.
```

**実行結果の読み方**

| メッセージ | 説明 |
|:---|:---|
| `Auto-merging file.txt` | Gitが`file.txt`を自動マージしようとしました |
| `CONFLICT (content)` | 内容のコンフリクトが発生しました |
| `Merge conflict in file.txt` | `file.txt`でコンフリクトが発生しています |
| `Automatic merge failed` | 自動マージに失敗しました |
| `fix conflicts and then commit` | コンフリクトを解決してからコミットしてください |

---

## 🔧 コンフリクトの確認方法

### `git status`でコンフリクトを確認

```bash
git status
```

**実行結果**

```
On branch main
You have unmerged paths.
  (fix conflicts and run "git commit")
  (use "git merge --abort" to abort the merge)

Unmerged paths:
  (use "git add <file>..." to mark resolution)
	both modified:   file.txt

no changes added to commit (use "git add" and/or "git commit -a")
```

**実行結果の読み方**

| メッセージ | 説明 |
|:---|:---|
| `You have unmerged paths` | マージされていないファイルがあります |
| `fix conflicts and run "git commit"` | コンフリクトを解決してコミットしてください |
| `git merge --abort` | マージを中止するコマンド |
| `both modified: file.txt` | 両方のブランチで`file.txt`が変更されています |

---

### ファイルの内容を確認

```bash
cat file.txt
```

**実行結果**

```
<<<<<<< HEAD
Hello PHP
=======
Hello Laravel
>>>>>>> feature/update-greeting
```

---

## 🔧 コンフリクトの解決手順

### ステップ1: ファイルを編集

エディタで`file.txt`を開き、コンフリクトマーカーを削除して、正しい内容に修正します。

**修正前**

```
<<<<<<< HEAD
Hello PHP
=======
Hello Laravel
>>>>>>> feature/update-greeting
```

**修正後（例：featureブランチの変更を採用）**

```
Hello Laravel
```

> 💡 **ポイント**: コンフリクトマーカー（`<<<<<<<`、`=======`、`>>>>>>>`）は**必ず削除**してください。残したままコミットすると、ファイルが壊れます。

---

### ステップ2: 変更をステージング

```bash
git add file.txt
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git add file.txt` | コンフリクトを解決したファイルをステージングエリアに追加します。これにより、Gitに「コンフリクトを解決しました」と伝えます |

---

### ステップ3: マージコミットを作成

```bash
git commit
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git commit` | マージコミットを作成します。`-m`オプションを省略すると、デフォルトのマージコミットメッセージが使われます |

デフォルトのマージコミットメッセージが表示されます。

```
Merge branch 'feature/update-greeting' into main

# Conflicts:
#	file.txt
```

保存して終了します。

---

## 💡 TIP: VSCodeでのコンフリクト解決

VSCodeでは、コンフリクトを視覚的に解決できます。

**VSCodeでの解決手順**

1. VSCodeで`file.txt`を開く
2. コンフリクトマーカーの上に、以下のボタンが表示される
3. ボタンをクリックして、コンフリクトを解決
4. `git add`と`git commit`を実行

**VSCodeのボタンの意味**

| ボタン | 説明 |
|:---|:---|
| **Accept Current Change** | 現在のブランチ（`main`）の変更を採用 |
| **Accept Incoming Change** | マージ元のブランチ（`feature`）の変更を採用 |
| **Accept Both Changes** | 両方の変更を採用（両方の内容が残る） |
| **Compare Changes** | 変更を比較して確認 |

## 🚀 実践例2: 複数ファイルのコンフリクト

複数のファイルでコンフリクトが発生した場合も、基本的な解決手順は同じです。

### ステップ1: `main`ブランチで2つのファイルを作成

```bash
git switch main
echo "File 1" > file1.txt
echo "File 2" > file2.txt
git add .
git commit -m "Add file1 and file2"
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `echo "File 1" > file1.txt` | `file1.txt`を作成します |
| `echo "File 2" > file2.txt` | `file2.txt`を作成します |
| `git add .` | すべての変更をステージングエリアに追加します |
| `git commit -m "Add file1 and file2"` | コミットを作成します |

---

### ステップ2〜5: featureブランチで変更し、mainでも変更

```bash
# featureブランチを作成して変更
git switch -c feature/update-files
echo "File 1 - Feature" > file1.txt
echo "File 2 - Feature" > file2.txt
git add .
git commit -m "Update files in feature branch"

# mainブランチに戻って変更
git switch main
echo "File 1 - Main" > file1.txt
echo "File 2 - Main" > file2.txt
git add .
git commit -m "Update files in main branch"

# マージ
git merge feature/update-files
```

**実行結果**

```
Auto-merging file2.txt
CONFLICT (content): Merge conflict in file2.txt
Auto-merging file1.txt
CONFLICT (content): Merge conflict in file1.txt
Automatic merge failed; fix conflicts and then commit the result.
```

2つのファイルでコンフリクトが発生しました。

---

### ステップ6: 複数ファイルのコンフリクトを解決

```bash
# file1.txtを編集（エディタで開いてコンフリクトマーカーを削除）
# 例: featureブランチの変更を採用
echo "File 1 - Feature" > file1.txt
git add file1.txt

# file2.txtを編集
echo "File 2 - Feature" > file2.txt
git add file2.txt

# マージコミットを作成
git commit
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `echo "File 1 - Feature" > file1.txt` | コンフリクトを解決した内容を書き込みます |
| `git add file1.txt` | 解決したファイルをステージングします |
| `git commit` | すべてのコンフリクトを解決したら、マージコミットを作成します |

> 💡 **ポイント**: 複数ファイルでコンフリクトが発生した場合は、**すべてのファイルを解決してから**`git commit`を実行します。

---

## 💡 TIP: マージを中止する方法

マージを中止したい場合は、`git merge --abort`を使います。

```bash
git merge --abort
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git merge --abort` | 進行中のマージを中止し、マージ前の状態に戻します |

**使用場面**

- コンフリクトが複雑で、最初からやり直したい場合
- 間違ったブランチをマージしようとした場合
- チームメンバーに相談してから解決したい場合

---

## 🔧 コンフリクトを避ける方法

### 方法1: こまめにマージする

`main`ブランチの変更を、こまめに`feature`ブランチにマージします。

```bash
git switch feature/add-login
git merge main
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git switch feature/add-login` | featureブランチに切り替えます |
| `git merge main` | mainブランチの最新の変更をfeatureブランチに取り込みます |

**なぜ効果的か？**

- mainブランチとの差分が小さくなる
- コンフリクトが発生しても、解決が簡単
- 最終的なマージがスムーズになる

---

### 方法2: リベースを使う

`git rebase`を使って、`feature`ブランチを`main`ブランチの最新の状態に更新します。

```bash
git switch feature/add-login
git rebase main
```

**コードリーディング**

| コマンド | 説明 |
|:---|:---|
| `git switch feature/add-login` | featureブランチに切り替えます |
| `git rebase main` | featureブランチのコミットを、mainブランチの最新の状態の上に移動します |

**マージとリベースの違い**

| 方法 | 特徴 |
|:---|:---|
| `git merge` | マージコミットが作成される。履歴が分岐したまま残る |
| `git rebase` | マージコミットが作成されない。履歴が一直線になる |

> ⚠️ **注意**: リベースは履歴を書き換えるため、すでにプッシュしたブランチでは使わないでください。

## 🚨 よくある間違い

### 間違い1: コンフリクトマーカーを残したままコミット

```bash
# NG: コンフリクトマーカーを削除していない
git add file.txt
git commit -m "Resolve conflict"
```

**なぜダメなのか？**

ファイルにコンフリクトマーカー（`<<<<<<<`、`=======`、`>>>>>>>`）が残ったままになり、プログラムが正しく動作しなくなります。

**対処法**: コンフリクトマーカーを**必ず削除**してからコミットします。

---

### 間違い2: 間違った変更を採用

```bash
# NG: 確認せずに現在のブランチの変更を採用
echo "Hello PHP" > file.txt
git add file.txt
git commit
```

**なぜダメなのか？**

- チームメンバーの作業が失われる可能性がある
- 本来採用すべき変更が消えてしまう

**対処法**: コンフリクトを解決する前に、**チームメンバーに確認**します。

---

### 間違い3: コンフリクトを放置する

```bash
# NG: コンフリクトを解決せずに放置
git merge feature/update-greeting
# コンフリクト発生...そのまま放置
```

**なぜダメなのか？**

- マージが完了していない状態が続く
- 他の作業ができなくなる
- 時間が経つと、何を解決すべきかわからなくなる

**対処法**: コンフリクトが発生したら、**すぐに解決**するか、`git merge --abort`で中止します。

---

## 💡 TIP: コンフリクト解決のベストプラクティス

| 番号 | ベストプラクティス | 理由 |
|:---|:---|:---|
| 1 | コンフリクトが発生したら、落ち着いて対処する | 焦るとミスが増える |
| 2 | ファイルの内容を確認し、どちらの変更を採用すべきか判断する | 両方の変更を理解することが重要 |
| 3 | わからない場合は、チームメンバーに相談する | 独断で決めると問題が起きる |
| 4 | コンフリクトマーカーを削除してからコミットする | マーカーが残るとファイルが壊れる |
| 5 | テストを実行して、正しく動作することを確認する | コンフリクト解決後のバグを防ぐ |

## ✨ まとめ

このセクションでは、コンフリクト解決の実践を学びました。

**コンフリクトの基本**

| 項目 | 説明 |
|:---|:---|
| コンフリクトとは | 同じファイルの同じ行を異なるブランチで変更した場合に発生する競合 |
| 確認方法 | `git status`で確認できる |
| コンフリクトマーカー | `<<<<<<<`、`=======`、`>>>>>>>`で変更箇所を示す |

**コンフリクト解決の手順**

1. ファイルを編集して、コンフリクトマーカーを削除する
2. `git add`で変更をステージングする
3. `git commit`でマージコミットを作成する

**コンフリクトを避ける方法**

- こまめにマージする
- リベースを使う

次のセクションでは、ここまでのChapter 1で学んだブランチ操作とマージを実践するハンズオン演習に進みます。
