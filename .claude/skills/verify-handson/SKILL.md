# ハンズオンSection検証スキル

## 目的

ハンズオンSectionが実際に動作するか、事前チェックを行う。検証は2段階:

| モード | 何をするか | いつ使うか |
|:-------|:-----------|:-----------|
| ①静的チェック | 読んで要件・手順の完全性を確認 | 常に（実機検証の前提） |
| ②実機検証 | `handson-verifier` エージェントが手順を実際に実行 | ユーザーが実行を求めたとき・量産の完走処理・静的チェックで疑義が出たとき |

## 必読ファイル

1. `guides/handson-structure.md` - ハンズオン構成ガイド
2. `guides/verification.md` - 検証ガイド
3. AI演習Section（T15/T16）の場合: `guides/ai-exercise-structure.md`（「AI出力は毎回変わる」前提の検証観点）

## ①静的チェックのワークフロー

```
1. 対象Sectionを読む
2. チェックリストに沿って検証
3. 問題点を洗い出し
4. ユーザーに報告
5. 問題があればGitHub Issueとして記録
```

### チェックリスト

**1. 要件・前提**

- [ ] 作業ディレクトリが明記されているか
- [ ] 新規/既存プロジェクトが明記されているか
- [ ] 必要なファイル（モデル、コントローラー等）が明記されているか
- [ ] 完成イメージが明記されているか

**2. 手順**

- [ ] ステップが順番に並んでいるか
- [ ] 各ステップの内容が明確か
- [ ] ファイル作成コマンドがあるか
- [ ] コード例が完全か（省略しすぎていないか）
- [ ] import文や依存関係が記載されているか

**3. 動作確認**

- [ ] 確認方法が記載されているか
- [ ] 期待する結果が明記されているか

**4. 構成の整合性**

- [ ] 「✏️ 実装タスク」「🧠 思考プロセス」「📝 ステップバイステップ」のステップが一致しているか
- [ ] 各ステップの文言が統一されているか
- [ ] コードの一貫性（ステップ・模範解答・Blade）が保たれているか

**5. AI演習Section（T15/T16）の追加観点**

- [ ] 完成チェックリストが検証手段（テスト・受け入れ条件・動作確認）で書かれているか
- [ ] 出力例・進行例に「毎回変わる」注記があるか

## ②実機検証のワークフロー

静的チェックを通過した（または疑義を特定した）うえで、`handson-verifier` エージェントを起動する。

1. **渡すもの**: 対象Sectionのパス・検証範囲（Section全体 / 特定Step）・一時作業ディレクトリの指定・（AI演習の場合）固定層のみ実行する旨
2. エージェントは実行計画（実行 / スキップ / BLOCKED の表）を立ててから一時ディレクトリで実行し、`RESULT:` 定型で報告する（詳細は `.claude/agents/handson-verifier.md`）
3. **報告の統合**: 静的チェックの結果と実機検証の `STEPS` / `FAILURES` を1つの報告にまとめる。❌ は「教材側の誤りか環境差か」の切り分けまで書く

> ⚠️ **注意**: Sail（Docker）を使うSectionの実機検証はビルドに時間がかかる。起動前に対象範囲と所要見込みを伝えること。

## 報告フォーマット

```markdown
## [Section番号] 検証結果

### 結果
- [ ] 問題なし
- [ ] 軽微な問題あり
- [ ] 重大な問題あり

### 検証方法
- [ ] 静的チェック
- [ ] 実機検証（handson-verifier / 環境: ...）

### 発見した問題

| No | 問題 | 重要度 | 修正案 |
|:---|:-----|:-------|:-------|
| 1 | ... | 高/中/低 | ... |

### 備考
...
```

## 注意

- **修正は検証後、ユーザー承認を得てから行うこと**
- 問題を発見した場合はGitHub Issueとして記録する
- 致命的な問題はユーザーに即座に報告する
