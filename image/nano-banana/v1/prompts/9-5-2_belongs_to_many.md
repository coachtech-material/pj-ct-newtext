## c1: 多対多リレーションシップの概念図

### プロンプト本文

```
Laravelにおける多対多リレーションシップ（belongsToMany）の概念を、ユーザーと役割（ロール）の具体例で図解してください。

## 内容
教材ではTutorial 8で学んだ多対多をLaravelで実装する方法を説明している:
- 1人のユーザーは複数の役割を持てる
- 1つの役割は複数のユーザーに割り当てられる
- 中間テーブル（role_user）で関係を管理する
- belongsToMany()で双方向のリレーションを定義

具体例:
- users: 山田太郎（id=1）、佐藤花子（id=2）
- roles: admin（id=1）、editor（id=2）、viewer（id=3）
- role_user: (1,1)=山田→admin, (1,2)=山田→editor, (2,3)=佐藤→viewer

## 描いてほしいもの
3つのテーブルと、Laravelのモデル定義を組み合わせた関係図:

【上段: テーブルとデータの関係】
usersテーブル（左）:
| id | name |
| 1 | 山田太郎 |
| 2 | 佐藤花子 |

rolesテーブル（右）:
| id | name |
| 1 | admin |
| 2 | editor |
| 3 | viewer |

role_userテーブル（中央・下）:
| user_id | role_id |
| 1 | 1 |
| 1 | 2 |
| 2 | 3 |

色付きの線でデータの関連を結ぶ:
- 山田太郎 → admin（赤線）
- 山田太郎 → editor（青線）
- 佐藤花子 → viewer（緑線）

【下段: Laravelのモデル定義】
Userモデル: belongsToMany(Role::class)
Roleモデル: belongsToMany(User::class)
双方向の矢印で「お互いにbelongsToMany」を示す。

キャラクター（山田太郎）が「僕はadminとeditorの2つの役割を持ってるよ！」
キャラクター（admin）が「僕は山田さんに割り当てられてる！」

タイトル: 「belongsToMany〜多対多リレーションシップ〜」

## 概念の強調
- 「belongsToMany()」の技術用語を最も大きく太い文字で描く
- 中間テーブル（role_user）が橋渡し役であることを視覚的に強調
- 中間テーブルの命名規則（アルファベット順で単数形: role_user）に小さく触れる
- データの関連を色付き線で結び、多対多の関係が直感的に分かるようにする
- 双方向のリレーション定義（User→roles, Role→users）を示す
```

## c2: sync()メソッドの実装図

### プロンプト本文

```
中間テーブル操作メソッド（attach / detach / sync）の違いを、具体的なデータの変化で図解してください。特にsync()の動作を詳しく描いてください。

## 内容
教材では中間テーブルを操作する3つのメソッドを説明している:

attach(): 中間テーブルにレコードを追加
- $user->roles()->attach(1) → role_id=1を追加
- $user->roles()->attach([1, 2, 3]) → 複数追加

detach(): 中間テーブルのレコードを削除
- $user->roles()->detach(1) → role_id=1を削除
- $user->roles()->detach() → 全削除

sync(): 中間テーブルの状態を同期（最重要）
- $user->roles()->sync([1, 2])
- 配列に含まれないものは削除、含まれるが存在しないものは追加、既存のものはそのまま

sync()の具体例:
- 変更前: user_id=1に role_id=1, 3 が紐付いている
- sync([1, 2]) を実行
- role_id=3 は配列にないので削除
- role_id=1 は既に存在するのでそのまま
- role_id=2 は存在しないので追加
- 変更後: user_id=1に role_id=1, 2 が紐付いている

## 描いてほしいもの
3つのメソッドを上段に概要として並べ、下段にsync()の詳細な動作を描く:

【上段: 3つのメソッドの概要】
attach(): 「＋追加する」（緑色）
detach(): 「－削除する」（赤色）
sync(): 「🔄同期する」（青色）＝「指定した状態に合わせる」

【下段: sync()の詳細フロー】
ビフォー: role_userテーブル
| user_id | role_id |
| 1 | 1 | ← そのまま（配列に含まれる）
| 1 | 3 | ← 削除（配列に含まれない）

sync([1, 2]) を実行 ↓

アフター: role_userテーブル
| user_id | role_id |
| 1 | 1 | ← そのまま
| 1 | 2 | ← 新規追加（配列に含まれるが存在しなかった）

3つの判定ロジックを番号付きで:
① role_id=3 → 配列にない → 🔴 削除
② role_id=1 → 配列にある＋既に存在 → ⚪ そのまま
③ role_id=2 → 配列にある＋存在しない → 🟢 追加

キャラクターが「sync()は指定した配列の状態にピッタリ合わせるよ！」

タイトル: 「attach / detach / sync〜中間テーブルの操作メソッド〜」

## 概念の強調
- 「sync()」を最も大きく太い文字で描く（このメソッドが最も重要）
- attach()とdetach()はsync()の構成要素として小さく配置
- sync()のビフォー・アフターを明確に対比
- 3つの判定（削除・そのまま・追加）を色分けして分かりやすく
- $user->roles()->sync([1, 2]) のコードを添える
```
