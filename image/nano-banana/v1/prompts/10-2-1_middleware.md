# 10-2-1: ミドルウェア（A1: 比喩フロー）

**Gem**: v4.1 | **テンプレート**: A1 | **ステータス**: テスト中

## プロンプト本文

```
Laravelのミドルウェアの仕組みを、「玉ねぎの層」の比喩で図解してください。

## 内容
教材ではミドルウェアスタックを玉ねぎの層に例えている:
- リクエストは外側の層から内側へ順番に通過する
- 中心のControllerで処理した後、レスポンスは内側から外側へ戻る
- 各層がそれぞれの役割（認証チェック、CORS処理、レート制限等）を担う

## 描いてほしいもの
玉ねぎの断面のような同心円の構造を描き、リクエスト/レスポンスの流れを示す:

構造（外側から内側へ）:
- 最外層: Middleware 1（CORS）
- 中間層: Middleware 2（Auth認証）
- 内側層: Middleware 3（Rate Limit）
- 中心: Controller

流れ:
① リクエストが外から入り → Middleware 1 → 2 → 3 → Controller
② Controllerが処理
③ レスポンスが内から出て → Middleware 3 → 2 → 1 → 返却

タイトル: 「ミドルウェア 〜玉ねぎの層〜」

## 概念の強調
- 「Middleware」「Controller」の技術用語を大きく太い文字で描く
- リクエストの流れ（外→内）とレスポンスの流れ（内→外）が逆順になることを矢印の色分けで明確に示す
- この図で伝えたいのは「リクエストもレスポンスも、必ず全てのミドルウェア層を通過する」こと
```
