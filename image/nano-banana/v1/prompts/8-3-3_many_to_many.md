# 8-3-3: 中間テーブルによる多対多の関係（B2: 関係図）

**Gem**: v4.1 | **テンプレート**: B2 | **ステータス**: ドラフト

## プロンプト本文

```
多対多（Many-to-Many）のリレーションシップを、中間テーブルを使って解決する仕組みをER図形式で図解してください。

## 内容
教材では「投稿（posts）」と「タグ（tags）」の関係で多対多を説明している:
- 1つの投稿は複数のタグを持てる（例: 投稿Aに #PHP, #Laravel）
- 1つのタグは複数の投稿で使われる（例: #PHPタグが投稿Aと投稿Bに付く）
- この「お互いが多」の関係は、直接表現できない
- 解決策: 中間テーブル（post_tag）を間に置いて、2つの「1対多」に分解する

## 描いてほしいもの
3つのテーブルをER図として描き、中間テーブルが「橋渡し役」であることを視覚的に表現する:

テーブル1: 「posts」（左側）
- id（PK）🔑、user_id（FK）、title、content
- サンプル: id=3 "Laravel入門"、id=4 "SQLの基本"

テーブル2: 「tags」（右側）
- id（PK）🔑、name
- サンプル: id=1 "PHP"、id=2 "Laravel"、id=3 "SQL"

テーブル3: 「post_tag」（中央の橋渡し）
- id（PK）🔑、post_id（FK）→postsのid、tag_id（FK）→tagsのid
- サンプル: (3,1) (3,2) (4,3)

リレーションシップの線:
- posts ──||──o{── post_tag: 「1つの投稿は中間テーブルに複数のレコードを持てる」
- tags ──||──o{── post_tag: 「1つのタグは中間テーブルに複数のレコードを持てる」

中間テーブルのキャラクターが「僕が2人をつなぐ橋渡し役だよ！」と説明する吹き出し。
posts側のキャラクターが「1つの投稿に複数のタグを付けられる！」と喜ぶ。

タイトル: 「多対多のリレーションシップ〜中間テーブルが橋渡し〜」

## 概念の強調
- 「Many-to-Many（多対多）」の技術用語を最も大きく太い文字でタイトル付近に描く
- 「中間テーブル（Pivot Table）」を図の中央に目立つように配置し、橋渡し役であることを強調
- posts→post_tag、tags→post_tagの2つの「1対多」関係を太い矢印で示す
- 中間テーブルがなぜ必要かを直感的に伝える: 「多対多 = 2つの1対多に分解」
- 複合ユニークキー制約（同じ組み合わせは登録できない）にも小さく触れる
```
