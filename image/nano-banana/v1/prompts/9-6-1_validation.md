# 9-6-1: バリデーション基礎（B1: フロー図）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
Laravelのバリデーション機能を、「入力データの検問所」として図解してください。

## 内容
教材では以下のポイントを説明している:
- ユーザー入力は「信用してはいけない」（必須項目が空、形式不正、文字数超過など）
- バリデーションは入力が正しい形式かをチェックし、不正な入力を拒否する仕組み
- $request->validate() でバリデーションルールを配列で指定
- バリデーション成功 → 処理続行（$validatedにデータ格納）
- バリデーション失敗 → 自動で前のページにリダイレクト、エラーメッセージ表示

## 描いてほしいもの
検問所（ゲート）のイメージで、入力データがチェックを受ける流れを描く:

構成要素:
- 左側: ユーザーからのリクエスト（フォーム入力データ）
- 中央: バリデーション（検問所のゲート）
- 右上: 成功ルート → Controller処理へ
- 右下: 失敗ルート → フォームに戻る（エラーメッセージ付き）

流れ（番号付き）:
① ユーザーがフォームを送信（リクエスト）
② バリデーションでルールをチェック（検問）
③-A チェック通過 → $validated に格納 → Controller処理続行
③-B チェック失敗 → $errors に格納 → 前のページにリダイレクト

検問所のゲートには、チェック項目を記載:
- required（必須）
- email（メール形式）
- max:255（文字数制限）
- unique（重複不可）

## ラベルの書き方
各要素の近くに、技術用語を最も大きく太い文字で1行目に書く:
- 1行目（大きく太く）: 「Validation」
- 2行目（小さく）: 入力チェックの検問所

核心ラベルの強調:
- 「Validation」「$validated」「$errors」の3つを図の中で最も目立つ要素にする
- 成功ルート（緑）と失敗ルート（赤）を色分けして明確に区別する
- 検問所のゲートを図の中央に大きく配置し、入力を審査する門番であることを示す

## 概念の強調（最も重要）
この図で伝えたいのは「バリデーション = 入力データのゲートキーパー」という役割構造です。
- 全てのユーザー入力はバリデーションを通過しなければならない
- 通過/拒否の2つの明確な分岐がある
- エラー時は入力値を保持して再入力を促す

タイトル: 「Laravelバリデーション〜入力データの検問所〜」
```
