## c1: タスク管理アプリのリレーション構造図

### プロンプト本文

```
タスク管理アプリにおけるモデル間のリレーション構造を図解してください。User, Category, Task の3つのモデルと、それらの1対多リレーション（hasMany / belongsTo）を分かりやすく表現してください。

## 内容
教材ではタスク管理アプリのモデル構造を説明している:
- User: ユーザー情報を管理
- Category: カテゴリー情報を管理
- Task: タスク情報を管理

リレーションの設計:
- User → Task: 1対多（1人のユーザーは複数のタスクを持つ）
- Category → Task: 1対多（1つのカテゴリーには複数のタスクが属する）
- Task → User: 多対1（1つのタスクは1人のユーザーに属する）
- Task → Category: 多対1（1つのタスクは1つのカテゴリーに属する）

具体例:
- users: 田中太郎（id=1）
- categories: 仕事（id=1）、プライベート（id=2）
- tasks: 会議の準備（id=1, user_id=1, category_id=1）、買い物リスト（id=2, user_id=1, category_id=2）

## 描いてほしいもの
3つのテーブルとLaravelのモデル定義を組み合わせたER図:

【上段: テーブルとデータの関係】
usersテーブル（左上）:
| id | name |
| 1 | 田中太郎 |

categoriesテーブル（左下）:
| id | name |
| 1 | 仕事 |
| 2 | プライベート |

tasksテーブル（右中央）:
| id | title | user_id | category_id |
| 1 | 会議の準備 | 1 | 1 |
| 2 | 買い物リスト | 1 | 2 |

色付きの線でデータの関連を結ぶ:
- 田中太郎 → 会議の準備（赤線）
- 田中太郎 → 買い物リスト（赤線）
- 仕事 → 会議の準備（青線）
- プライベート → 買い物リスト（緑線）

「1」側から「多」側へ向かう矢印で、1対多の関係を視覚化する。

【下段: Laravelのモデル定義】
Userモデル: hasMany(Task::class) → tasks() [複数形]
Categoryモデル: hasMany(Task::class) → tasks() [複数形]
Taskモデル: belongsTo(User::class) → user() [単数形]
Taskモデル: belongsTo(Category::class) → category() [単数形]

外部キー（user_id, category_id）がTasksテーブルに配置されていることを示す。

キャラクター（田中太郎）が「僕は2つのタスクを持ってるよ！」
キャラクター（仕事カテゴリー）が「会議の準備は僕に属してる！」

タイトル: 「User・Category・Task〜hasMany / belongsToリレーション〜」

## 概念の強調
- 「hasMany()」と「belongsTo()」の技術用語を大きく太い文字で描く
- 外部キー（user_id, category_id）が橋渡し役であることを視覚的に強調
- 「1」対「多」の関係が一目で分かるよう、矢印の太さや数で表現
- User と Category の両方から Task へ矢印が伸びる構図で、Taskが2つの親を持つことを示す
- メソッド名の命名規則（複数形:tasks、単数形:user, category）に小さく触れる
- $fillableプロパティの存在にも触れる（マスアサインメント保護）
```
