# 13-5-1: 認証機能フロー（B1: 認証フロー図）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
Laravel Fortifyの認証機能フロー（登録→ログイン→セッション管理→ログアウト）を図解してください。

## 内容
タスク管理アプリにFortifyを使って認証機能を実装する。認証フローは4つのフェーズで構成される:

1. ユーザー登録（Register）
   - ユーザーが名前・メール・パスワードを入力
   - CreateNewUserアクションでバリデーション&ユーザー作成
   - パスワードはハッシュ化してDBに保存

2. ログイン（Login）
   - メール&パスワードを入力
   - Fortifyがusersテーブルで認証
   - 認証成功 → セッション作成 → /tasks にリダイレクト

3. セッション管理（Session）
   - ログイン後はセッションIDがCookieに保存される
   - 以降のリクエストはCookieを自動送信 → サーバーでセッション照合
   - auth()->check() でログイン状態を確認可能

4. ログアウト（Logout）
   - ログアウトリクエストでセッション削除
   - Cookieも無効化 → ログイン画面へリダイレクト

Fortifyの役割:
- ヘッドレス（UIなし）で認証機能を提供
- コントローラーを自作せずにルート自動生成（/login, /register, /logout）
- ビューは自分で作成 → Fortify::loginView(), Fortify::registerView()

## 描いてほしいもの
認証フローの4つのフェーズを左から右に流れる図で表現:

登場キャラクター:
- ユーザー（Browser）: フォームを操作する人
- Fortify: 認証処理を担当するLaravelパッケージ
- Database: usersテーブル（ユーザー情報保存）
- Session: ログイン状態を保持する記憶領域

フロー（番号付き）:
① 【登録】名前・メール・パスワードを送信
② CreateNewUserがバリデーション → パスワードをHash化してDB保存
③ 【ログイン】メール&パスワードを送信
④ Fortifyがusersテーブルで照合 → 認証OK
⑤ セッション作成 → セッションIDをCookieで返す
⑥ 【セッション維持】以降のリクエストはCookie自動送信 → セッションで識別
⑦ 【ログアウト】セッション削除 → ログイン画面へ

タイトル: 「認証機能フロー 〜Fortifyで実現する4つのフェーズ〜」

## 概念の強調
- 「Fortify」「Session」「Cookie」を最も大きく太い文字で描く
- 4つのフェーズ（Register / Login / Session / Logout）を明確に区別する
- パスワードのHash化（セキュリティ）を強調
- セッションIDがCookieに保存され、以降は自動送信される仕組みを可視化
- 各フェーズの流れが一目で追えるよう、矢印と番号で明示
```
