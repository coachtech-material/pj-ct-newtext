# 13-6-3: Policy認可フロー（B1: 認可チェックフロー）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
LaravelのPolicyによる認可チェックフローを図解してください。

## 内容
教材ではPolicyを使った認可処理のリファクタリングを解説している:
- コントローラからの呼び出し: $this->authorize('view', $task);
- Policyメソッド: TaskPolicy::view($user, $task) が実行される
- 判定ロジック: $user->id === $task->user_id（所有者チェック）
- 結果: true → 処理続行 / false → 403 Forbidden

Policyを使うメリット:
- 認可ロジックを1箇所に集約できる
- コントローラのコードがシンプルになる
- Bladeテンプレートでも @can で使える

## 描いてほしいもの
3段構成の縦フロー図:

【上段: リクエスト受信】
- ユーザーアイコンが「タスク詳細を見る」リクエストを送信
- 矢印がコントローラに向かう
- 吹き出し: 「/tasks/5 にアクセス」

【中段: Policyによる認可チェック】
コントローラからPolicyへの流れ:

① TaskController が $this->authorize('view', $task) を呼び出す
   - コントローラを箱で表現
   - 「authorize を呼ぶよ」の吹き出し

② TaskPolicy の view メソッドが実行される
   - Policyを別の箱で表現（オレンジ系で強調）
   - 中に判定ロジック: $user->id === $task->user_id

③ 所有者チェックの分岐
   - 条件: 「ログインユーザーID = タスクの所有者ID？」
   - 左側: ✅ 一致（true）
   - 右側: ❌ 不一致（false）

【下段: 結果】
左側（成功パス）:
- ✅ true → 処理続行
- タスク詳細画面が表示される
- 緑系の枠

右側（失敗パス）:
- ❌ false → 403 Forbidden
- 「他人のタスクは見せないよ！」の吹き出し
- 赤系の枠

タイトル: 「Policyによる認可チェック」

## 概念の強調
- 「Policy」を最も大きく太い文字で中段に配置
- 「authorize」の呼び出しとPolicyメソッドの対応関係を明示する
- 所有者チェック（$user->id === $task->user_id）が認可の核心であることを強調
- true/falseの分岐が「許可/拒否」に直結することを視覚的に示す
- 403 Forbidden を赤く目立たせる
- フローが上から下に自然に流れるレイアウトにする
```
