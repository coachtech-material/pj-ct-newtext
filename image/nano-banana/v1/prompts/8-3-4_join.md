# 8-3-4: テーブル結合 INNER JOIN / LEFT JOIN 比較（B2: 比較図）

**Gem**: v4.1 | **テンプレート**: B2 | **ステータス**: ドラフト

## プロンプト本文

```
テーブル結合（JOIN）の仕組みを、INNER JOINとLEFT JOINの比較形式で図解してください。

## 内容
教材ではJOINを「分割したテーブルを仮想的につなぎ合わせる機能」として説明している:
- 正規化でテーブルを分割した結果、データがバラバラになった
- JOINで「主キーと外部キーの関連」を頼りに結合して一つの結果として取得する
- INNER JOIN = 両方のテーブルに一致するデータがある場合のみ結合
- LEFT JOIN = 左側のテーブルの全レコードを基準にし、右側に一致がなければNULL

## 描いてほしいもの
上下（または左右）で、INNER JOINとLEFT JOINを対比して描く:

### 元データ（共通）
usersテーブル:
| id | name |
| 1 | Jonathan Doe |
| 2 | Bob |

postsテーブル:
| id | user_id | title |
| 1 | 1 | 初めての投稿 |
| 3 | 1 | Laravel入門 |
| 4 | 1 | SQLの基本 |

### INNER JOIN（上段）
- キャラクターが「両方にマッチするものだけ！」と説明
- 結合結果: Jonathan Doeの3件の投稿だけが表示される
- Bobは投稿がないので結果に含まれない（Bobが「僕は仲間外れ…」と寂しそう）
- ON句 users.id = posts.user_id を矢印で示す

### LEFT JOIN（下段）
- キャラクターが「左のテーブルは全員参加！」と説明
- 結合結果: Jonathan Doeの3件 + Bobの1件（titleはNULL）
- Bobも含まれるが、titleカラムが「NULL」と表示される
- Bobが「僕も入れてもらえた！（でもNULL…）」と微妙な表情

タイトル: 「INNER JOIN vs LEFT JOIN」

## 概念の強調
- 「INNER JOIN」「LEFT JOIN」の技術用語を最も大きく太い文字で描く
- ON句（結合条件）の矢印を太く目立たせる: users.id = posts.user_id
- INNER JOINとLEFT JOINの違いが一目瞭然になるよう、結果テーブルの行数の差を強調
- NULLの表示を目立たせる（赤色や点線枠など）
- 「左のテーブル」という概念を矢印や色分けで明確にする
```
