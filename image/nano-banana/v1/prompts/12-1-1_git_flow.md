# 12-1-1: Git Flow vs GitHub Flow（B1: 技術フロー）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: テスト中

## プロンプト本文

```
Git FlowとGitHub Flowの2つのブランチ戦略を比較する図解を描いてください。

## 内容
教材ではブランチ戦略を交通ルールに例えている:
- ルールがないと、みんなが好き勝手に走って事故が起きる
- Git Flow = 5種類のブランチで厳密に管理（大規模向け）
- GitHub Flow = mainとfeatureだけのシンプル構成（小〜中規模向け）

## 描いてほしいもの
上下に分けた比較レイアウト:

【上段 — Git Flow】
水平タイムラインに5本のブランチを描く:
- main（青）: リリース済みの安定版
- develop（紫）: 開発の統合ブランチ
- feature（緑）: 新機能開発。developから分岐→developにマージ
- release（オレンジ）: リリース準備。developから分岐→mainにマージ
- hotfix（赤）: 緊急修正。mainから分岐→mainとdevelopにマージ

コミットを●で、マージを矢印で描く。

【下段 — GitHub Flow】
水平タイムラインに2本のブランチだけ:
- main（青）: 常にデプロイ可能
- feature（緑）: mainから分岐→PR→mainにマージ

各featureのマージに「PR & Review」と注記。

タイトル: 「Git Flow vs GitHub Flow」

## 概念の強調
- 上段の複雑さと下段のシンプルさの対比が一目で分かるようにする
- ブランチ名（main、develop、feature等）を大きく太い文字で描く
- 上段に「5ブランチで厳密管理」、下段に「シンプル！mainとfeatureだけ」と大きく注釈
- この図で伝えたいのは「チームの規模に応じてブランチ戦略を選ぶ」こと
```
