# 10-3-1: 認証(Authentication) vs 認可(Authorization)（B2: 比較/フロー図）

**Gem**: v4.1 | **テンプレート**: B2 | **ステータス**: ドラフト

## プロンプト本文

```
認証（Authentication）と認可（Authorization）の違いを比較し、Laravelのポリシーによる認可の仕組みを図解してください。

## 内容
教材では認証と認可を以下のように区別している:
- 認証（Authentication）: 「あなたは誰ですか？」→ ログインによる本人確認
- 認可（Authorization）: 「あなたはこれをしても良いですか？」→ 権限のチェック

ブログアプリケーションの要件例:
- 投稿の作成: ログインユーザーなら誰でもOK
- 投稿の編集: 投稿の作成者だけ
- 投稿の削除: 作成者、または管理者だけ

Laravelのポリシー（Policy）:
- 特定のモデルに対するアクセス権限を管理するクラス
- $this->authorize('update', $post) でコントローラーから呼び出す
- @can('update', $post) でBladeテンプレートから使う

## 描いてほしいもの
2段構成の図:

【上段: 認証 vs 認可の比較】
左右に分けた比較レイアウト:

左側（青系）— 認証（Authentication）:
- 建物の入口で「身分証を見せてください」とチェックしているキャラクター
- 「あなたは誰ですか？」の吹き出し
- Fortify / ログイン がラベル
- セリフ: 「山田太郎さんですね、どうぞ！」

右側（オレンジ系）— 認可（Authorization）:
- 建物内の各部屋の前で「この部屋に入る権限がありますか？」とチェックしているキャラクター
- 「これをしても良いですか？」の吹き出し
- Policy / Gate がラベル
- セリフ: 「この投稿の編集は作成者だけです！」

【下段: ポリシーの仕組み】
ポリシーの判定フロー:
① ユーザーが「投稿を編集」をリクエスト
② コントローラーが $this->authorize('update', $post) を呼ぶ
③ PostPolicy の update() メソッドが実行される
④ $post->user_id === $user->id を判定
⑤ true → 編集を許可 / false → 403 Forbidden

タイトル: 「認証と認可 〜Policyによる権限管理〜」

## 概念の強調
- 「Authentication」「Authorization」を最も大きく太い文字で上段の見出しにする
- 「Policy」を下段で最も大きく太い文字で描く
- 認証は「入口の1回だけ」、認可は「各アクションごとに毎回」チェックされることを対比で示す
- 403 Forbidden エラーが権限不足のときに返されることを明示する
- 上段の比較と下段のフローが自然につながるレイアウトにする
```
