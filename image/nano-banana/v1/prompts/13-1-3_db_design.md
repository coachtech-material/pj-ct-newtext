# 13-1-3: DB設計プロセス（B1: 技術フロー）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
データベース設計のプロセスを、4つのステップのフローチャートで図解してください。

## 内容
教材では以下のように説明している:
- DB設計はシステムで扱うデータの構造を設計する作業
- DB設計を行わずに開発すると、データの重複・不整合・パフォーマンス低下が起きる
- 4ステップ: エンティティ抽出 → リレーション定義 → ER図作成 → テーブル設計
- 具体例はタスク管理アプリ（User, Task, Category）

## 描いてほしいもの
上から下への縦フローで、4つのステップを段階的に描く。各ステップに具体例を添える:

【ステップ1 — エンティティ抽出（青系）】
- 「何を管理するかを決める」
- キャラクター（設計者）が「機能要件を見て、データのまとまりを見つけるよ！」と言っている
- 具体例: 3つのエンティティカードを並べる
  - User（ユーザー）: 名前、メール、パスワード
  - Task（タスク）: タイトル、説明、優先度
  - Category（カテゴリー）: カテゴリー名

【ステップ2 — リレーション定義（緑系）】
- 「エンティティ間の関係を決める」
- キャラクターが「1人のUserは複数のTaskを持つ？→はい！1対多！」と言っている
- 具体例: 矢印でリレーションを示す
  - User → Task（1対多）
  - Category → Task（1対多）

【ステップ3 — ER図作成（オレンジ系）】
- 「視覚的に確認する」
- キャラクターが「図にすると全体が見えるね！」と言っている
- 具体例: シンプルなER図
  - [users] ──1:多──▶ [tasks] ◀──1:多── [categories]
  - 外部キー（user_id, category_id）を矢印で示す

【ステップ4 — テーブル設計（紫系）】
- 「カラムとデータ型を決める」
- キャラクターが「カラム名、データ型、制約を決めるよ！」と言っている
- 具体例: tasksテーブルの一部を表形式で
  - id: BIGINT, PK
  - user_id: BIGINT, FK
  - title: VARCHAR(255), NOT NULL
  - priority: TINYINT, DEFAULT 2

各ステップの間を太い下向き矢印でつなぐ。

タイトル: 「DB設計プロセス 〜4つのステップ〜」

## 概念の強調
- 4つのステップが「段階的に具体化していく」ことを視覚的に示す（上が抽象的、下が具体的）
- 各ステップの番号を大きく描く
- 「エンティティ」「リレーション」「ER図」「テーブル設計」の技術用語を各ステップで最も大きく太い文字で描く
- この図で伝えたいのは「DB設計は4つのステップを順番に進めることで、抽象的な要件を具体的なテーブル構造に落とし込む作業」であること
```
