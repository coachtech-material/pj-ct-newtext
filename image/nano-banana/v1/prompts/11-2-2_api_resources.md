# 11-2-2: APIリソースによるレスポンス整形パイプライン（B1: 技術フロー）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
LaravelのAPI Resourcesによるレスポンス整形パイプラインを図解してください。

## 内容
教材では以下のように説明している:
- モデルをそのまま返すと、不要なデータ（user_id等）が含まれ、日付フォーマットもバラバラ
- API Resourcesは「レスポンスの変換層」として機能する
- 処理の流れ: データベース → Eloquentモデル → API Resource（変換） → JSONレスポンス
- API Resourceを使うことで、モデルとAPIレスポンスを分離できる

## 描いてほしいもの
左から右への横フローで、データが変換されていく様子をパイプライン形式で描く:

【ステップ1 — データベース（青系）】
- データベース（冷蔵庫や倉庫のキャラクター）
- テーブルのデータが格納されている
- 「生のデータがあるよ！」というセリフ

【ステップ2 — Eloquentモデル（緑系）】
- Eloquentモデル（配達員のキャラクター）
- データベースからデータを取り出す
- 「全部のカラム持ってきたよ！」というセリフ
- 表示例: id, user_id, title, description, status, created_at（タイムスタンプ形式）

【ステップ3 — API Resource（オレンジ系、最も大きく強調）】
- API Resource（整理・加工担当のキャラクター。料理の盛り付け担当のイメージ）
- 「不要なデータをカット！フォーマットを整える！」というセリフ
- 変換の様子を具体的に描く:
  - user_id → 削除（×印）
  - status: "pending" → status_label: "未着手" を追加（＋印）
  - created_at: "2024-01-01T00:00:00.000000Z" → "2024-01-01 00:00:00" に整形

【ステップ4 — JSONレスポンス（紫系）】
- きれいに整形されたJSONレスポンス
- 「きれいなデータの完成！」というセリフ
- 表示例: { id, title, description, status, status_label, due_date, created_at }

流れ:
① データベースからEloquentモデルがデータ取得
② Eloquentモデルが全カラムを持つ状態
③ API Resourceが変換・整形（不要カラム削除、ラベル追加、日付フォーマット統一）
④ きれいなJSONレスポンスが完成

タイトル: 「API Resource 〜レスポンスの変換パイプライン〜」

## 概念の強調
- 「API Resource」を図の中央に最も大きく太い文字で描く
- Before（生データ）とAfter（整形済みデータ）の対比を明確にする
- 変換の3つのアクション（削除・追加・整形）を具体的に示す
- この図で伝えたいのは「API Resourceはモデルのデータを整形してクライアントに最適な形で返す変換層である」ということ
```
