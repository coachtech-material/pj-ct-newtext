# 6-2-2: コンテナのライフサイクル（B1: 状態遷移フロー）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
Dockerコンテナのライフサイクル（run → ps → stop → rm）を状態遷移フローとして図解してください。

## 内容
教材ではコンテナの基本コマンドをこう説明している:
- docker run: 新しいコンテナを作成・実行する
- docker ps: 実行中のコンテナ一覧を表示する
- docker exec: 実行中のコンテナの中に入る
- docker stop: コンテナを停止する
- docker rm: 停止したコンテナを削除する
- docker images: イメージ一覧を表示する

## 描いてほしいもの
コンテナの「状態」をキャラクター化し、ライフサイクルをストーリーとして描く:

①【イメージ状態】（左端）
- 箱の設計図のようなイラスト（Dockerイメージ）
- 「まだ動いてないよ」とセリフ
- ラベル: 「Image（イメージ）」

②【実行中】（中央上）docker run で遷移
- 元気に動いているコンテナくん（走っている、汗や集中線）
- 「docker run」の矢印で①から②へ
- 「起動したよ！元気に稼働中！」とセリフ
- ラベル: 「Running（実行中）」
- 横に「docker ps で確認できる」と注釈
- 「docker exec で中に入れる」と小さく注釈

③【停止中】（中央下）docker stop で遷移
- 眠っているコンテナくん（zzz、目を閉じている）
- 「docker stop」の矢印で②から③へ
- 「おやすみ...でもまだ残ってるよ」とセリフ
- ラベル: 「Stopped（停止中）」
- 「docker ps -a で確認できる」と注釈

④【削除済み】（右端）docker rm で遷移
- コンテナくんが消えて、煙だけ残っているイラスト
- 「docker rm」の矢印で③から④へ
- 「完全に削除されたよ」とセリフ
- ラベル: 「Removed（削除済み）」

⚠️ 注意ポイント:
- ②（実行中）から直接④（削除）はできない、という注釈を赤字で追加
- 「先にstopしてからrmする」という順序を強調

タイトル: 「コンテナのライフサイクル」

## 概念の強調
- 「docker run」「docker stop」「docker rm」のコマンド名を矢印上に大きく太い文字で描く
- 各状態（Running, Stopped, Removed）のラベルを目立たせる
- 状態遷移の流れが①→②→③→④の順に一方向で明確にわかること
- 「stopしてからrmする」順序の重要性を⚠️で強調
```
