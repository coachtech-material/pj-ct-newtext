# 10-1-4: ログイン/ログアウトフロー（B1: シーケンス図）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
Laravel Fortifyのログイン・ログアウト機能のフローを、シーケンス図風に図解してください。

## 内容
教材では、Fortifyを使ったログイン・ログアウトの仕組みを解説している:

ログインの流れ:
1. ユーザーが /login にアクセス → login.blade.php が表示
2. メールアドレスとパスワードを入力してPOST
3. Fortifyがデータベースでユーザーを検索
4. Hash::check()でパスワードを検証
5. 成功 → セッションにユーザーIDを保存 → セッションIDをCookieに返す
6. 失敗 → エラーメッセージを表示

ログアウトの流れ:
1. ログアウトボタン（POSTリクエスト）をクリック
2. セッションを無効化
3. CSRFトークンを再生成
4. ログインページにリダイレクト

認証済みリクエスト:
- ブラウザがCookieのセッションIDを自動送信
- LaravelがセッションからAuth::user()でユーザー情報を復元

## 描いてほしいもの
3つのフェーズに分けたシーケンス図風のレイアウト:

登場キャラクター（横一列に配置）:
- Browser（ブラウザ）: ユーザーが操作する
- Fortify（認証エンジン）: 認証処理を自動で行う
- Database（データベース）: ユーザー情報を保持
- Session（セッション）: ログイン状態を管理

【フェーズ1: ログイン】（緑系）
① Browser → Fortify: POST /login（メール＆パスワード）
② Fortify → Database: ユーザーを検索
③ Fortify: Hash::check()でパスワード検証
④ Fortify → Session: セッション作成（ユーザーID保存）
⑤ Fortify → Browser: Cookie（セッションID）を返す
セリフ: 「認証OK！セッション作ったよ！」

【フェーズ2: 認証済みリクエスト】（青系）
⑥ Browser → Fortify: リクエスト + Cookie（セッションID自動送信）
⑦ Fortify → Session: セッションIDでユーザー情報を復元
セリフ: 「この人はログイン済みだね！」

【フェーズ3: ログアウト】（グレー系）
⑧ Browser → Fortify: POST /logout
⑨ Fortify → Session: セッション無効化 & CSRFトークン再生成
⑩ Fortify → Browser: /login にリダイレクト
セリフ: 「セッション削除！また来てね！」

タイトル: 「ログイン / ログアウト 〜セッション認証のシーケンス〜」

## 概念の強調
- 「Session」「Cookie」「Hash::check()」を大きく太い文字で描く
- 3つのフェーズが色分けで明確に区別されていること
- ログイン成功時の「セッション作成→Cookie返却」が核心の流れであることを強調
- 認証済みリクエストで「Cookieが自動送信される」ことを明確に示す
- ログアウト時の「セッション無効化」と「CSRFトークン再生成」を両方描く
```
