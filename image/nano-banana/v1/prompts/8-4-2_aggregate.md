# 8-4-2: GROUP BYによるデータのグループ化・集計（B1: フローチャート）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
GROUP BY句と集計関数によるデータのグループ化・集計の仕組みを、処理の流れ（フローチャート）として図解してください。

## 内容
教材では集計関数とGROUP BYを「データから洞察を得る」ツールとして説明している:
- 集計関数（COUNT, SUM, AVG, MAX, MIN）= データを要約した単一の値を返す
- GROUP BY = 指定したカラムの値が同じレコードを1つのグループにまとめる
- WHERE = グループ化する前の元データに対する条件
- HAVING = グループ化した後の集計結果に対する条件
- SQL実行順序: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

## 描いてほしいもの
「postsテーブルからユーザーごとの投稿数を集計する」例を、SQLの実行順序に沿ったフローチャートで描く:

ステップ① FROM posts
- postsテーブルの全レコードがずらっと並ぶ（5〜8件程度のデータ）
- キャラクターが「まずは全データを集めるよ！」

ステップ② GROUP BY user_id
- user_id=1のグループ、user_id=2のグループ…と色分けしたグループに分かれる
- キャラクターが「user_idが同じもの同士でグループ分け！」
- 同じ色の枠で囲んで、視覚的にグループが分かるように

ステップ③ SELECT user_id, COUNT(id) AS post_count
- 各グループが1行に集約される: user_id=1→5件, user_id=2→3件
- キャラクターが「各グループの件数をCOUNTで数えるよ！」

ステップ④ HAVING post_count >= 3（オプション）
- 条件に合わないグループが除外される
- キャラクターが「3件未満はさようなら〜」

番号付き矢印で①→②→③→④の流れを示す。

タイトル: 「GROUP BY〜データをグループ化して集計する〜」

## 概念の強調
- 「GROUP BY」「集計関数（COUNT）」の技術用語を最も大きく太い文字で描く
- SQLの実行順序（FROM→WHERE→GROUP BY→HAVING→SELECT→ORDER BY）を小さなフロー図として画面の隅に補足
- グループ化の前後で「バラバラのレコード→まとまったグループ→集約された結果」の変化が一目で分かるように
- WHERE（グループ化前）とHAVING（グループ化後）の違いを明確にラベリング
- 各グループを異なる色で区別し、視覚的にグルーピングを表現
```
