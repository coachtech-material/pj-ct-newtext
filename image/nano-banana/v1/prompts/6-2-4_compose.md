# 6-2-4: Docker Compose 複数コンテナ連携（B2: 構成図）

**Gem**: v4.1 | **テンプレート**: B2 | **ステータス**: ドラフト

## プロンプト本文

```
Docker Composeによる複数コンテナの連携構成を図解してください。Web+PHP+DBの3つのコンテナが協力して動く様子を描きます。

## 内容
教材ではDocker Composeをこう説明している:
- 複数のコンテナを1つの設定ファイル（docker-compose.yml）で定義し、1つのコマンドで管理するツール
- 典型的なLaravelアプリケーションには最低3つのサービスが必要:
  1. Webサーバー（Nginx）: リクエストを受け付け、PHPに処理を渡す
  2. PHP実行環境（PHP-FPM）: Laravelアプリ本体のコードを実行
  3. データベース（MySQL）: データを永続的に保存
- docker compose up -d で全て一斉起動、docker compose down で全て停止

## 描いてほしいもの

### 上部: docker-compose.yml ファイル
- ファイルのアイコン（📄）に「docker-compose.yml」のラベル
- 「この1つのファイルで全部定義！」とセリフ
- ファイルから下に「docker compose up -d」の矢印（太く、キラキラ付き）

### 中央: 3つのコンテナが連携している構成図
3つのコンテナをキャラクター化して横に並べる:

①【web（Nginx）コンテナ】（左）
- 受付係風のキャラクター（制服、笑顔）
- ラベル: 「web: Nginx（受付係）」
- 吹き出し: 「リクエストを受け付けるよ！」
- ポート表示: 「8080:80」

②【app（PHP）コンテナ】（中央）
- 職人風のキャラクター（エプロン、道具を持つ）
- ラベル: 「app: PHP-FPM（処理担当）」
- 吹き出し: 「Laravelのコードを実行！」

③【db（MySQL）コンテナ】（右）
- 金庫番風のキャラクター（鍵を持つ、真面目な顔）
- ラベル: 「db: MySQL（データ保管庫）」
- 吹き出し: 「データを安全に保管！」
- ボリューム表示: 「db-data」（永続化）

### コンテナ間の矢印
- web → app: 「②処理を依頼」の矢印
- app → db: 「③データを問い合わせ」の矢印
- 外部（ブラウザ）→ web: 「①リクエスト」の矢印

### 下部
- 「docker compose down」で全て停止できることを示す小さな注釈

タイトル: 「Docker Compose: 複数コンテナを一括管理」

## 概念の強調
- 「Docker Compose」をタイトルとして最も大きく太い文字で描く
- 「docker-compose.yml」のファイル名をコード風に目立たせる
- 3つのコンテナが「チーム」として協力している様子を強調（コンテナ同士を結ぶ矢印を太く）
- 「1つのファイルで定義、1つのコマンドで起動」がこの図の核心メッセージ
- docker compose up / docker compose down のコマンドを目立たせる
```
