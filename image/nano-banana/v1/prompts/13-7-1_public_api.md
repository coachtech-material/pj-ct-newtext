# 13-7-1: 公開API構造（B1: リクエスト/レスポンスフロー）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
公開APIのリクエスト/レスポンスフローを図解してください。

## 内容
教材では以下のように説明している:
- 公開APIは認証なしで誰でもアクセスできる
- GET /api/tasks でタスク一覧を取得
- GET /api/tasks/{id} でタスク詳細を取得
- TaskResourceを使ってレスポンス形式を統一
- レスポンスは「data」キーでラップされる

## 描いてほしいもの
左から右への横フローで、クライアントからのリクエストがJSONレスポンスになるまでの流れを描く:

【ステップ1 — クライアント（青系）】
- ブラウザやスマホアプリのキャラクター
- 「GET /api/tasks を送信！」というセリフ
- リクエストの矢印が出ている

【ステップ2 — routes/api.php（緑系）】
- ルーターのキャラクター（交通整理をする警察官のイメージ）
- 「/api/tasks → TaskController@index に案内！」というセリフ
- ルーティングの振り分けを表現

【ステップ3 — Api\TaskController（オレンジ系）】
- コントローラのキャラクター（指揮者のイメージ）
- 「データを取得して、リソースで整形！」というセリフ
- Task::with(['category', 'user'])->get() でデータ取得
- TaskResource::collection($tasks) で変換

【ステップ4 — TaskResource（黄色系、強調）】
- リソースのキャラクター（料理の盛り付け担当のイメージ）
- 「必要な情報だけ、きれいに整形！」というセリフ
- 整形される内容:
  - id, title, description
  - priority, priority_label
  - category: { id, name }
  - user: { id, name }
  - created_at, updated_at（ISO 8601形式）

【ステップ5 — JSONレスポンス（紫系）】
- きれいに整形されたJSONレスポンス
- 「data」キーでラップされている
- 「完璧なAPIレスポンスの完成！」というセリフ

流れ:
① クライアントが GET /api/tasks リクエストを送信
② routes/api.php が Api\TaskController@index にルーティング
③ TaskController がデータベースからデータを取得
④ TaskResource がレスポンス形式を整形
⑤ 「data」キーでラップされたJSONレスポンスを返却

タイトル: 「公開API 〜リクエストからJSONレスポンスまで〜」

## 概念の強調
- 「TaskResource」と「data」キーを図の中で目立つように描く
- リクエスト（GET /api/tasks）とレスポンス（JSONの構造）の対応が分かるようにする
- 認証なしで誰でもアクセスできる「公開API」であることを示す（鍵が開いているアイコン等）
- この図で伝えたいのは「公開APIはリクエストを受けて、リソースで整形し、統一されたJSON形式でレスポンスを返す」ということ
```
