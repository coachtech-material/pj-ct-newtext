ORM（Object-Relational Mapping）の概念を、テーブルとオブジェクトの対応関係を示すマッピング図として図解してください。

## 内容
教材ではORMを「データベースのテーブルをオブジェクトとして扱う仕組み」として説明している:
- SQLを書かずに、PHPのオブジェクト指向の構文でデータベースを操作できる
- LaravelのEloquent ORMが標準で組み込まれている
- テーブル ↔ モデル（クラス）、レコード ↔ インスタンス、カラム ↔ プロパティ の対応

演算子の使い分け:
- ::（ダブルコロン）= クラスに直接アクセス（まだインスタンスがない時）: User::find(1), User::all()
- ->（アロー演算子）= インスタンスのメンバーにアクセス: $user->name, $user->save()

SQLとEloquentの比較:
- SELECT * FROM users; → User::all();
- SELECT * FROM users WHERE id = 1; → User::find(1);
- INSERT INTO users ... → User::create([...]);

## 描いてほしいもの
左右にデータベースの世界とPHPの世界を配置し、対応関係をマッピング矢印で結ぶ:

【左側: データベースの世界（SQL）】
usersテーブルの構造を表形式で描く:
| id | name | email |
| 1 | 山田太郎 | taro@example.com |
| 2 | 佐藤花子 | hanako@example.com |

- テーブル名「users」を大きく
- 各カラム（id, name, email）にラベル
- 各行（レコード）にラベル

【右側: PHPの世界（Eloquent）】
Userモデルのクラスとインスタンスを描く:
- クラス: User（:: でアクセス）
- インスタンス: $user（-> でアクセス）
- プロパティ: $user->name, $user->email

【中央: マッピング矢印】
- テーブル ←→ モデル（クラス）: 太い矢印で「users テーブル = User モデル」
- レコード ←→ インスタンス: 「1行のデータ = 1つのオブジェクト」
- カラム ←→ プロパティ: 「name カラム = $user->name」

キャラクター（Eloquent担当）が「SQLを書かなくても僕が翻訳するよ！」と説明。

下部にSQLとEloquentの比較を小さく並べる:
- SELECT * FROM users; ↔ User::all();
- WHERE id = 1 ↔ User::find(1);

タイトル: 「Eloquent ORM〜テーブルとオブジェクトの橋渡し〜」

- 「ORM（Object-Relational Mapping）」の技術用語を最も大きく太い文字で描く

- :: と -> の使い分けを小さいコード例で示す
