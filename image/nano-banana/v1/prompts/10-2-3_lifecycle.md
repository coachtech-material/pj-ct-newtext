# 10-2-3: LaravelのHTTPライフサイクル全体（B2: 構成図）

**Gem**: v4.1 | **テンプレート**: B2 | **ステータス**: ドラフト

## プロンプト本文

```
LaravelのHTTPライフサイクル全体を、リクエストからレスポンスまでの一連の流れとして図解してください。

## 内容
教材では、HTTPライフサイクルを10ステップで解説している:
1. ユーザーがブラウザでURLにアクセス
2. public/index.php（エントリーポイント）がリクエストを受ける
3. HTTPカーネルがリクエストを処理開始
4. ミドルウェアがリクエストを前処理（認証、CSRF、セッション等）
5. ルーターがリクエストを適切なコントローラーに振り分け
6. コントローラーがビジネスロジックを実行
7. ビュー（Blade）がHTMLをレンダリング
8. ミドルウェアがレスポンスを後処理（Cookie追加、ヘッダー追加等）
9. HTTPレスポンスがブラウザに返される
10. アプリケーション終了処理（ログ書き込み、キュー処理等）

ミドルウェアの比喩: 空港のセキュリティチェック
ミドルウェアの層構造: 玉ねぎのように重なっている（リクエスト: 外→内、レスポンス: 内→外）

## 描いてほしいもの
左から右への横長のフローで、リクエスト〜レスポンスの全体像を描く:

登場キャラクター/要素:
- Browser（ブラウザ）: ユーザーが操作する端末
- index.php（入口の門番）: すべてのリクエストの入口
- HTTP Kernel（総司令官）: 処理全体を統括
- Middleware（セキュリティチェック係）: 玉ねぎの層のような構造
- Router（案内係）: リクエストを正しいコントローラーに誘導
- Controller（実行者）: ビジネスロジックを処理
- View/Blade（デザイナー）: HTMLを生成
- Response（返却物）: 最終的に返されるHTML/JSON

全体フロー:
① Browser → index.php: HTTPリクエスト送信
② index.php → HTTP Kernel: リクエストを渡す
③ HTTP Kernel → Middleware（前処理）: グローバルMW → グループMW → ルートMW
④ Middleware → Router: ルート解決
⑤ Router → Controller: 適切なメソッドを呼び出す
⑥ Controller → View(Blade): データを渡してHTMLレンダリング
⑦ View → Response生成: HTMLレスポンスオブジェクト
⑧ Response → Middleware（後処理）: 逆順で通過（Cookie追加等）
⑨ Middleware → HTTP Kernel → Browser: レスポンス送信
⑩ HTTP Kernel: 終了処理（ログ、キュー等）

ミドルウェアの層構造を小さなインセット図で表現:
```
[Global MW]
  [Group MW (web)]
    [Route MW (auth)]
      [Controller]
```

タイトル: 「LaravelのHTTPライフサイクル」

## 概念の強調
- 「HTTP Kernel」「Middleware」「Router」「Controller」「View」を大きく太い文字で描く
- ミドルウェアが前処理（リクエスト時）と後処理（レスポンス時）の両方で通過することを明確にする
- 「すべてのリクエストはindex.phpを通る」ことを入口で強調
- リクエストの流れ（青矢印）とレスポンスの流れ（赤矢印）を色分けする
- 10ステップの番号が全て見えるようにする
```
