# 11-3-1: APIセキュリティ（B1: 多層防御図）

**Gem**: v4.1 | **テンプレート**: B1 | **ステータス**: ドラフト

## プロンプト本文

```
APIセキュリティの多層防御の仕組みを図解してください。

## 内容
教材ではAPIセキュリティを以下のように解説している:

主な攻撃と対策:
1. DoS攻撃 → レート制限（Rate Limiting）で防御
2. SQLインジェクション → Eloquent ORM + バリデーションで防御
3. XSS → エスケープ処理で防御
4. 通信傍受 → HTTPSで暗号化
5. 情報漏洩 → 環境変数での機密情報管理、エラーメッセージの制限

レート制限の仕組み:
- デフォルトで1分間に60回までのリクエストを許可
- IPアドレスまたはユーザーIDで制限
- 超過時は429 Too Many Requestsを返す

多層防御の考え方:
- 1つの対策だけでなく、複数の防御層を重ねる
- 外側から内側に向かって: HTTPS → レート制限 → バリデーション → Eloquent ORM → ログ記録

## 描いてほしいもの
城壁のような多層防御のイメージで、外部からの攻撃がAPIサーバーに到達するまでに複数の防御層を通過する様子を描く。

【構成 — 多層防御の城壁】

登場キャラクター:
- 攻撃者（複数の攻撃を試みる悪意のあるユーザー）
- APIサーバー（城の中心。データベースと連携）
- 各防御層（門番のようなキャラクター）

防御層（外側から内側へ）:
① HTTPS（第1層）: 通信を暗号化する盾
   - 「通信内容は暗号化！盗聴は不可能！」

② レート制限（第2層）: 大量リクエストを弾く門番
   - 「1分間に60回まで！それ以上は429 Too Many Requests！」
   - DoS攻撃の矢が弾かれる

③ バリデーション（第3層）: 不正なデータを検査する番人
   - 「required|string|max:255... 入力値をチェック！」
   - SQLインジェクションの攻撃が弾かれる

④ Eloquent ORM（第4層）: データベースを守る最後の砦
   - 「プリペアドステートメントで自動エスケープ！」

⑤ ログ記録（監視塔）: 全てを記録し、異常を検知
   - 「Log::info() 全アクセスを記録中...」

攻撃者のセリフ:
- 「大量リクエストで落としてやる！」→ レート制限で阻止
- 「SQLインジェクションで侵入だ！」→ Eloquent ORMで阻止
- 「通信を盗聴してやる！」→ HTTPSで阻止

タイトル: 「APIセキュリティの多層防御」

## 概念の強調
- 「多層防御」「レート制限」「バリデーション」「HTTPS」を大きく太い文字で描く
- 「429 Too Many Requests」を攻撃阻止の象徴として表示
- 各層が連携して攻撃を防いでいる様子を明確に
- 外側から内側への防御の流れを矢印で示す
- 攻撃が各層で弾かれる様子を視覚的に表現（❌マーク）
```
