# 9-1-6: HTTPリクエスト/レスポンスの流れ（A1+B1: 比喩+フロー）

**Gem**: v4.1 | **テンプレート**: A1+B1 | **ステータス**: ドラフト

## プロンプト本文

```
HTTPリクエストとレスポンスの流れを、「ユーザーとサーバーの会話」の比喩で図解してください。

## 内容
教材ではWebアプリケーションを「ユーザー（ブラウザ）とサーバーの会話」に例えている:
- リクエスト（Request）= ユーザーがサーバーに送る「お願い」
- レスポンス（Response）= サーバーが返す「返事」
- Webアプリの基本サイクル: 入力（Request）→ 処理（Controller）→ 出力（Response）

教材の「挨拶アプリ」の例を使う:
1. ユーザーが /greeting にアクセス（GET）→ フォーム画面が表示される
2. ユーザーが名前を入力して送信（POST）→ 「こんにちは、〇〇さん！」と表示

## 描いてほしいもの
左右に「ユーザー（ブラウザ）」と「サーバー（Laravel）」を配置し、会話のやり取りを描く:

【左側: ユーザー】
- パソコンの前に座っているキャラクター
- フォームに「山田太郎」と入力している場面

【右側: サーバー（Laravel内部）】
- Routing → Controller → View の処理の流れをコンパクトに描く

会話の流れ（番号付き）:
① GET /greeting
  ユーザー →「フォームを見せて！」→ サーバー
② サーバーが showForm() を実行 → form.blade.php を返す
③ POST /greeting（name=山田太郎）
  ユーザー →「名前を送るよ！」→ サーバー
④ サーバーが greet() を実行 → $request->input('name') で名前取得
⑤ result.blade.php に名前を渡して表示
  サーバー →「こんにちは、山田太郎さん！」→ ユーザー

リクエストの矢印は青色、レスポンスの矢印は赤色で色分け。

タイトル: 「リクエストとレスポンス〜Webアプリの会話〜」

## 概念の強調
- 「Request（リクエスト）」「Response（レスポンス）」の技術用語を最も大きく太い文字で描く
- 「入力→処理→出力」のサイクルが一目で分かるように
- GET / POST の違いをラベルで明示（GETは「見せて」、POSTは「データを送るよ」）
- サーバー内部の処理（Routing→Controller→View）はコンパクトだが省略しない
- $request->input('name') のコードスニペットを小さく添える
```
